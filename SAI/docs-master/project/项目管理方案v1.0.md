## 一、总览

本方案面向项目全体成员，目标是用最轻量的方式让所有人养成三个习惯：代码提交到 Git、文档同步到 Git、日报写到 Git。关心项目的人打开 Git 就能看到昨天发生了什么、今天在做什么。

项目分为三层架构、五个团队代码库、一个公共文档库，共 6 个 Git 仓库。

## 四、Git 提交规范（核心规则，仅 3 条）

### 规则 1：提交信息写清楚做了什么

Commit message 格式：`[类型] 简要说明`

类型包括：`feat`（新功能）、`fix`（修复）、`docs`（文档）、`refactor`（重构）、`test`（测试）。

示例：
```
feat: 添加 Skill 热加载能力
fix: 修复 LLMRouter 超时重试逻辑
docs: 更新 Channel 接口对接文档
```

### 规则 2：代码提交必须同步文档

这是 v1.0 的核心约束。任何影响以下内容的代码变更，必须在 **同一天内** 在 `docs` 仓库对应团队目录下提交文档更新：

- 新增或变更的 API 接口
- 模块间交互方式的变化
- 新增功能的使用说明

文档可以先写再写代码，也可以代码写完再补文档，但 **当天必须完成同步**。

### 规则 3：每天至少一次提交

每位成员每个工作日至少有一次 Git 提交（代码仓库或文档仓库均可），让项目进度对所有人可见。

## 六、日报制度

### 每天写

每人每天在 `docs/daily/日期/姓名.md` 提交日报，内容不限格式，记录当天做了什么即可。可以用 AI 辅助生成——根据当天的 Git commit 记录整理即可。

### 什么时候写

每天下班前提交。

---

## 七、如何通过 Git 看项目进展

任何关心项目的人，可以用以下方式快速了解进展：

**看日报：** 打开 `docs` 仓库 `daily/` 目录，按日期浏览每人的工作内容。

**看代码活跃度：** 在各代码仓库查看近期 commit 历史，`git log --oneline --since="yesterday"` 即可看到昨天的所有提交。

**看各团队文档：** 进入 `docs` 仓库对应团队目录，查看设计文档和接口文档的变更记录。

## 八、快速上手清单

对于每位团队成员，第一天需要完成以下事项：

1. 找老徐获取 Git 账号权限，确保能访问自己负责的代码仓库和 `docs` 仓库。
2. Clone 自己负责的代码仓库和 `docs` 仓库到本地。
3. 在 `docs/daily/今天日期/` 下创建自己的第一篇日报并提交，验证 Git 流程跑通。
4. 阅读本方案，了解提交规范和文档同步要求。
