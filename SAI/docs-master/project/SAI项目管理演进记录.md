### 🔵 v1.0（4/20）— "Git即进度，最小约束"

| 引入的工具/流程 | 作用 |
|---|---|
| **Git 6仓库** | 文档和代码统一存放git，文档驱动开发 |
| **docs 文档库** | 日报/方案设计/项目管理 |
| **日报制度** | 每天 `daily/日期/姓名.md`，AI可从commit生成 |

**缺陷**：无需求跟踪、无任务管理、无里程碑，代码和需求完全断链——进度靠翻日报和 git log。

---

### 🟢 v2.0（5/8）— "Issue串联全链路"

| 引入的工具/流程 | 作用 |
|---|---|
| **GitLab Milestone** | 里程碑驱动，全局视角至顶向下和任务分支至下往上形成数据管道，串起所有研发链路 |
| **GitLab Issue** | Spec Issue（5个模块方案）+ Task Issue（N个开发任务），label 区分 |
| **MR 关联 TaskID** | MR 描述填"关联 #TaskID"，合入后自动追溯 |
| **plan标准化目录** | 新增里程碑文件 按模块聚合spec&pic |
| **GitLab CLI** | AI能自动读取和操作issue，免去人工到git页面操作 |

**闭环逻辑**：Task完成→关Issue → 所有Task完成→Spec标记完成 → 所有Spec完成→里程碑归档。

---

### 🔑 截止目前演进小结

**v1 靠人的习惯维持纪律，v2 靠系统机制自动约束。** v1 解决了"有没有"，v2 解决"串不串得起来"。
