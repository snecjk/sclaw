## 二、云端 & 本地Agent架构方案（今日确认）

**背景：** 明确云端与本地两条Agent技术路线的实施策略，确保资源效率与能力对齐。

**今日决策：**

**1. 云端Agent方案：**
- 当前方案：独立沙箱运行Claude Agent，每个Agent任务独占一个沙箱环境
- 备选方案（视资源压力切换）：单一容器 + 多进程Agent + 远程脚本执行沙箱
- 备选方案优势：Agent进程常驻，仅在需要执行脚本时申请沙箱，显著降低资源占用
- 切换判断依据：监控当前资源使用率，达到阈值时评估迁移

**2. 本地Agent方案：**
- 基于现有STO-Claw客户端基础进行改造
- UI界面调整，新增任务管理模块（任务创建、状态追踪、结果展示）
- 保留现有交互框架，降低用户学习成本

**3. 本地Claude Agent内核同步开发：**
- 本地Claw同步集成Claude Agent内核
- 与现有方案进行效果对比测试（响应质量、任务完成率、资源占用）
- 为后续统一内核选型提供数据支撑

**架构示意：**
```
云端：用户请求 → Gateway → 独立沙箱(Claude Agent) → 结果返回
本地：用户操作 → STO-Claw UI → 本地Agent内核(双内核对比) → 本地执行
```
