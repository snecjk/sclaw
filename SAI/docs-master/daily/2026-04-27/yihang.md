## 一、各模块进展

### 1. Agent_ai_claw

#### chat接口流式输出优化
- 消息处理逻辑从多类型判断改为 StreamEvent 事件驱动模式
- 新增 include_partial_messages 选项，支持部分消息处理

#### serverless环境
- OSS目录延迟挂载导致的技能软链接创建失败问题已修复
- `.claude/skills` 标准目录扫描支持已完成

### 2. agent-gateway

- 网关路由功能开发完成，支持将请求路由到 agent 沙箱
- 日志格式标准化完成，应用容器启动时日志标准输出并写入 start.log 文件，添加 request_id 等字段，替换 print 输出为标准日志输出

### 3. 通用Agent前端H5 SDK

#### H5 SDK demo开发
- 完成 H5 SDK demo 开发，实现流式响应处理框架，支持 AI SDK 的 HTTP 流式接口
- 新增会话 ID 状态管理，优化多轮对话连续性
- 完成与申懂懂 APP 的 sddToken 集成对接

#### 对话记录打标方案讨论
与凌雪讨论后续按域标定 Agent 性能指标方案，初步结论是需要人工抽样标注。后续分三步走：
- 第1步：提供打标页面，人工给问答打上标签
- 第2步：分权限管理，各域只能看自己的用户历史对话
- 第3步：AI 自动打标 + 人工调整，由各域通过提示词或判定 Agent 做个性化

#### CLI登录态对接方案确定
与文鹏确定登录态对接方案：前端传入单点登录的 stoToken，网关层将 token 作为环境变量传给 Agent 的 docker 容器，容器内的 SAI CLI 读取环境变量作为登录态。该方案避免了配置文件方式的链路延时。

### 4. 基于通用Agent的AI销售助理开发

#### 线索Skill优化
- 线索领取流程拆分：按店铺名称获取主体名称的流程改为先查看状态再手动领取，拆分为两个独立接口
- 线索查询新增竞对筛选条件（圆通、中通、顺丰等）
- 线索新增多个字段：线索来源、线索类型、社会信用代码、领取时间、领取人、线索状态
- 规则调整：每日领取上限10条，持有上限30条
