## 二、已完成模块

### 2.1 Agent 静默登录 ✅ 已交付

实现 `/api/v1/auth/silent-login` 接口，通过梧桐工号完成无交互登录。SSO 返回的用户身份信息与 StoToken 经 AES-256-GCM 加密后以密文返回，每次请求使用随机 nonce，GCM 认证标签防篡改。解决了桌面小精灵、CI/CD 等场景无法弹出浏览器的登录痛点。

### 2.2 sai update 自更新命令 ✅ 已交付

实现 `sai update` 内建命令，用户和 Agent 均可自助将 CLI 更新到最新版本。流程为远端查版本 → 下载二进制 → SHA256 校验 → 原地替换，任何环节失败自动回退备份。免认证执行，JSON 结构化输出方便 Agent 解析决策。不引入任何新第三方依赖，全部基于 Go 标准库。

### 2.3 Schema 缓存刷新策略 ✅ 已交付

落地"双阈值 + 事件触发自愈"方案，补齐了原有缓存策略的三个短板：

- **双阈值**：freshTTL（10 分钟）内直接命中缓存；maxStaleAge（2 小时）为硬上限，超过后即使远端失败也拒绝回退，杜绝长期陈旧风险；
- **自愈机制**：action 调用成功后自动异步刷新对应模块缓存；下游返回 404 后自动纠偏刷新；
- 所有新增行为均可通过环境变量开关控制，不引入后台守护进程。

### 2.4 登录体验优化 ✅ 已交付

主动在浏览器弹出登录链接，轮询过程不在屏幕上滚动输出，交互更干净。

### 2.5 CLI 命令分组 ✅ 已交付

帮助信息中区分「内置命令」与「动态命令」，命令结构一目了然。

### 2.6 下游大数据量处理 ⏳ 进行中

调研分页、流式、压缩等技术方案，解决下游接口返回数据量过大的问题，方案待定。

## 三、待启动模块

### 3.1 SAI Sprite 桌面小精灵 🔶 设计完成，开发待启动

已完成完整产品设计与技术选型。核心决策：选择 **Go + Wails 2.x** 作为桌面框架，理由有三：

1. 团队技术栈 Go + TS/JS，无 Rust 经验，零学习成本；
2. SAI CLI 同为 Go 项目，auth、config、registry、execute 等核心模块约 70% 可直接 import 复用；
3. 安装包仅 10-15MB、内存 30-60MB，远优于 Electron。

产品规划五大模块：CLI 生命周期管理（检测/安装/升级 SAI、Lark、Qoder、Cursor 等 CLI）、Skill 市场（浏览/安装/管理）、统一 SSO 认证中心、Agent IDE 对接、自动更新。实施分 P0-P6 六阶段推进，这是下一步的核心开发任务。

## 四、关键决策

| 决策 | 选择 | 理由 |
|------|------|------|
| 静默登录加密 | AES-256-GCM | 端到端加密，满足安全合规 |
| 缓存策略 | 2 小时硬上限 + 自动自愈 | 杜绝无限陈旧回退，补齐可用性短板 |
| 自更新 | 标准库实现，零新依赖 | 轻量可控，Agent 可编程触发 |
| 桌面框架 | Wails 2.x，放弃 Tauri | 复用 CLI 70% 代码，团队零学习成本 |
