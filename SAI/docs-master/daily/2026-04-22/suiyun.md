# 项目日报2026-04-22

## 一、 核心架构变更：确定单 CLI 方案

整体架构从 "多 CLI 分域部署" **演进为** "单 CLI 统一封装" 模式。

| 对比项 | 昨日方案 (v1.0) | 今日确定方案 |
|--------|----------------|-------------|
| CLI 交付形态 | 各业务域独立开发多个 CLI | **统一一个 `sai-cli` 二进制交付** |
| 业务系统职责 | 独立开发、维护各自 CLI | **专注核心 API 建设，提供标准描述** |
| Harness Manager 职责 | 元数据注册分发 | **统一封装构建、全生命周期管理** |

**职责演进总结**：架构向标准化迈进。业务系统将重心放在核心业务 API 的高质量建设与描述输出上；Harness Manager 负责承接 API 描述的聚合、元数据提取、标准化封装与二进制构建。通过分工协作，进一步降低各业务域的接入与维护成本。

## 二、 今日完成工作

### 1. 注册上报机制设计

确定 Harness Manager 对外提供两个核心接口：

#### 接口一：API 描述 → 标准注册 JSON 生成
业务系统提交 API 描述文档后，调用此接口生成标准注册 JSON。核心能力：
- **AI 自动提取 Tag**：从 API 描述中识别功能、参数、场景，自动填充 D1-D9 标签。
- **重复度检测**：与已有命令描述做相似度比对，高重复度的命令会有提醒，避免冗余注册。
- **返回补充指引**：返回标准 JSON 的同时，附带需要业务方人工补充的 Tag 说明清单。

#### 接口二：命令注册接口
格式基本保持不变，接收业务系统上报的标准 JSON（含 `systemCode`, `commands`, `tags` 等），写入全局命令目录。

### 2. CLI 二进制构建机制与鉴权兼容
确定由各业务系统注册上来的 CLI 命令元数据，由 Harness Manager **聚合构建为统一 `sai-cli` 二进制文件**，提供给 Agent 端使用。
- **统一构建**：业务系统不需要编译、部署任何 CLI 代码。Manager 根据注册的命令清单 + API 映射，动态生成 CLI 命令定义。
- **鉴权兼容设计**：
  - **云上版本**：CLI 从与 Agent 端约定的文件中获取 Token，Token **不进入模型上下文**，确保密钥安全。
  - **本地版本**：支持通过**扫码登录**的方式注入 `sto token`，方便本地调试与开发。
  - **进阶安全方案（设计中）**：针对"Token 跨环境复用”风险（如云上 Token 泄露被他人使用），正在设计基于**环境凭证绑定**的防伪方案，确保云地隔离、泄露无效，计划明日输出详细设计文档。

### 3. 与 Agent 交互细节敲定
- **交互媒介**：确认 Harness Manager 与 Agent 通过 **OSS 路径挂载**方式进行交互，Agent 不直接调用 Manager API。
- **挂载时机与产物**：在 **Agent 启动阶段**自动挂载指定 OSS 路径，Agent 从挂载目录中读取 `sai-cli` 二进制文件、Skill 元数据清单及版本配置。
- **挂载规范**：完成 OSS Bucket 申请与目录结构定义，确保产物存放路径与 Agent 侧读取逻辑完全对齐。
