## 二、Agent Workflow 架构设计（设计文档产出）

**定位：** 面向业务用户的生产级 Agent 工作流平台技术方案，已完成完整技术选型与架构设计。

### 核心决策

| 层次 | 选型 | 理由 |
|------|------|------|
| Agent 执行引擎 | Claude Agent SDK | 提供 agent loop、工具调用、会话管理 |
| Durable Runtime（默认） | Inngest | 低运维、TS 友好、部署最轻 |
| Durable Runtime（备选） | Temporal | 可复用 MySQL、能力上限最高 |
| 业务产品层 | 自研 Workflow Studio + DSL | 满足业务用户配置需求 |
| 业务主数据库 | MySQL | 与现有技术栈一致 |
| 工具接入 | MCP / Skill Registry | 统一工具协议与权限边界 |

### 关键设计点

- 三层职责分离：业务产品层 / Durable Runtime / Agent 智能执行层
- 同容器多 agent 实例为默认资源模型，SDK 权限 + Hook 做第一层隔离
- 脚本执行场景升级至独立沙箱，高风险任务走独立容器
- 双执行面：本地/内网执行面 + 云端执行面（K8s + gVisor/Kata 分层隔离）
- Completion Contract 机制确保 agent 任务可验证完成
- 多 agent 团队由平台自研 Team Orchestrator 管理，不依赖 SDK 实验性功能
- 不基于 n8n/Dify 等平台改造，保留产品自主权
