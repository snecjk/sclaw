## 4. 三项改动

### 4.1 任务列表与上方导航间距过大

**现状（根因）**：侧栏有**两段并列的 `flex-1` 滚动区**：
- 顶部导航 `<nav>`（L976–1098，`flex … flex-1 …`）放固定导航项（新对话/定时任务…）。
- 下方 `<div>`（L1100–1346，`… flex-1 …`）放任务列表 + 历史。

两个 `flex-1` 兄弟会**平分剩余空白**，顶部导航项很少却被撑高，于是导航和「任务列表」之间出现一大段空白 = 你看到的"距离太高"。

**目标**：导航项紧贴其内容高度，「任务列表」直接跟在下面，间距按设计稿。

**做法（阶段二，先在阶段一给方案）**：
- 顶部导航 `<nav>` 改为 **`shrink-0`**（按内容高度），**只保留下方任务/历史区为 `flex-1` 滚动**。
- 导航块与「任务」分区之间设计稿间距用 MasterGo 值（如 `mt-*`）。
- ℹ️ 工作台分区在上、下两处各渲染一次（L1072–1096 与 L1135–1159），但都受 `sidebarVis.workspace` 控制，**省区(provincial)下 `workspace=false` → 两处都不显示**，对本环境无影响；改结构时不要误把它们改成强制显示即可（`full` 模式才会出现，本任务不处理）。

### 4.2 任务列表默认收起

**现状**：`taskListSectionOpen` 初值 `useState(true)`（L624）= 默认展开。

**做法**：初值改 **`false`** = 默认收起；用户点标题仍可展开（交互不变）。
- 标题**保持「任务列表」不改名**（与线上一致）。✅ 已确认。

### 4.3 历史记录：今天/昨天/更早 合并为「最近」一层

**现状**：历史区把普通会话按 6 个日期桶分（today/yesterday/withinWeek/withinTwoWeeks/withinMonth/older，L771–778 + `getSessionBucket` L118–133），每桶一个**可折叠标题**逐个渲染（L1220–1341）。

**目标（对齐设计稿）**：取消日期分桶，所有普通会话**合并成单一「最近」列表**——一个**可折叠**的「最近」标题 + 一条扁平列表（按活跃时间倒序），不再有 今天/昨天/两周内 等子标题。

**做法（阶段二）**：
- 渲染层：把 L1220–1341 的"逐桶折叠"改成"**单个可折叠分区**"——标题「最近」+ chevron（沿用现有桶标题那套折叠交互），展开后直接遍历 `normalSessions`（已有，L800，按 `getEffectiveActivityMs` 倒序，见 L821–826 的排序）渲染会话行；保留现有**行内编辑/删除按钮、选中高亮、`显示更多` 截断**逻辑。
- **可折叠 + 默认展开** ✅：复用一个布尔态（如把 `bucketOpen` 简化成单个 `recentOpen`，初值 `true`）。
- 标题「最近」：⚠️ **省区(provincial)下 `sidebarVis.conversationChrome=false`，现有 L1161–1169 的「历史会话」标题本就不显示**。所以「最近」标题**不能再挂在 `conversationChrome` 门控下**，要让它在省区也渲染（新增 `common:sidebar.recent` 文案，三语同步；标题独立于 conversationChrome）。
- `sessionBuckets` / `getSessionBucket` / `bucketOpen`（多桶）逻辑**条件隐藏 + 注释**，不真删，避免牵连别处引用。
- "显示更多"截断：现按桶计数（`getBucketVisibleCount` / `bucketVisibleCounts`）→ 合并后改为**对「最近」单列表**做一个截断计数即可。

> 不动：`normalSessions` 的来源与过滤、`switchSession` 跳转、重命名/删除逻辑。
