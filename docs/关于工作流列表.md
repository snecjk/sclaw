# 关于工作流列表

## 各功能调用的 FastAPI 端点

| 功能 | 端点 | 路径前缀 | 备注 |
|---|---|---|---|
| 工作流页面 — 我的工作流 + 官方推荐 | `POST /api/workflow-templates/mine` | `/api/` | 两个 tab 共用同一端点，通过返回数据中的 `scope` 字段区分：`personal` → 我的工作流，`system` → 官方推荐 |
| 首页 Chat `/` Picker（工作流模版列表） | `POST /agent/v1/workflow-templates` | `/agent/v1/` | 分页搜索模板，Picker 预加载时也会调用 |
| 我的任务 → 查询工作流 | `GET /api/my-tasks/agent/v1/my-workflow` | `/api/my-tasks/` | 返回简单的 id/name/description 列表 |

**三个功能各自调用了不同的端点，没有复用。**

## 模板 vs 实例

- **模板 (template)** = 蓝图，一个模板可反复执行
- **实例 (instance)** = 每次执行创建一条独立记录，拥有自己的 `workflowId` 和 `runId`

Picker 每次执行都会创建一条新的工作流实例（不是模板），调用链路如下：

```
createAndStartWorkflowDirect()
  ① POST /agent/v1/workflows          → 创建实例，返回 workflowId
  ② POST /agent/v1/workflows/{id}/start → 启动执行，返回 runId
```

**同一模板执行 N 次，就会在 workflow 表里产生 N 条实例记录。**

## 潜在问题

`/api/workflow-templates/mine` 理论上应只返回模板，但如果后端将实例也混入该接口的返回结果，则"我的工作流"卡片会随执行次数不断增多。需确认后端此端点的查询逻辑是否仅查模板表。
