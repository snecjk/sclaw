## 四、重点问题终版方案（合并三模型 + 代码修正）

### 4.1 文件预览 OPS-11 / OPS-12 / STO-39

**三模型分歧**
- qianwen：P1，推荐 `shell.openPath`
- cursor：P0，paths.ts + 最长后缀
- kimi：外部链接 fallback，未拆 ENOENT

**原因分析（终版）**
1. `ChatMessage.tsx` 将 `[file-preview:]` 转为 `preview://` markdown 链接。
2. `normalizeLocalFilePath`（`preview-url.ts`）**未处理** `/.stoclaw` → 应展开为 `~/` 或 `homedir()`。
3. `electron/api/routes/files.ts` 的 `resolveWorkspaceFilePath` 同样不处理该前缀。
4. 扩展名：`split('.').pop()` 对 `file.tsv` 在部分 regex 竞争下可能先命中 `.ts`。
5. #11 根因：ReactMarkdown 的 `<a>` 未统一处理 `preview://` → 侧栏 `onPreviewFile` 未触发（**不是缺 shell.openPath**）。

**终版解决方案**
```
Step 1 [0.5d] preview-url.ts + files.ts：/.stoclaw → join(homedir(), '.stoclaw', ...)
Step 2 [0.5d] extFromPathOrUrl 改为最长后缀匹配（tsv > ts）
Step 3 [0.5d] exists 失败时尝试 +.v / +sv 等后缀回退
Step 4 [0.5d] ChatMessage markdown link：preview:// → useChatPreviewPanel.open
Step 5       单测：preview-path-normalize 增加 /.stoclaw 与 .tsv 用例
```
**不做：** 用 shell.openPath 替代侧栏预览（三模型中 qianwen 方案仅作外链 fallback）。

### 4.2 网关 OPS-10 / STO-30

**三模型分歧**
- qianwen：startup-orchestrator + **connection-monitor**（与仓库一致）
- cursor：UI 30s 失败态 + gateway:restart
- kimi：后端并行/缓存（偏题）

**原因分析（终版）**
- Main 已有 `waitForGatewayReady`（~60s）、`scheduleReconnect`、`GatewayConnectionMonitor` 心跳。
- **缺口：** `src/stores/gateway.ts` 渲染层长期 `connecting`，未消费 monitor 的 `onHeartbeatTimeout`；Windows 首启慢无用户可操作重试。

**终版解决方案**
```
Step 1 [1d] gateway store：connecting >30s → failed +「重试」「查看日志」
Step 2 [0.5d] IPC gateway:restart，按钮触发 Main start()
Step 3 [0.5d] 将 connection-monitor onHeartbeatTimeout 推到 renderer 状态
Step 4       STO-30 Windows 首问：与网关 failed 态联调，统一走 dispatchChatSend
```
**不做：** 自动换端口（qianwen 方案 C）— 风险大，二期再评估。
