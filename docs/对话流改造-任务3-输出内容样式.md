## 5. 逐项改动

### 5.1 标题分级（核心：MD 字体大小）

- **现状（关键问题）**：`globals.css` 第 347-353 行，`h1–h6` **全部同一字号 `0.875rem`(14px) / 600**——**没有层级**，标题和正文一样大。
- **目标**：按设计稿建立标题层级（图二："网点管理全景" > "1. 经营损益分析" > 子项）。
- **做法**：在 `.prose` 里给 `h1/h2/h3`（h4-h6 可并档）分别设字号 + 字重 + 上下间距，**字号在 02-styles 6 档内取**（建议 h1=16px/`text-base`、h2=15px、h3=14px，字重 600；最终以 MasterGo 为准）。保留 `:first-child margin-top:0`。
- **取值**：各级标题字号/字重/行高/段距 → MasterGo。

### 5.2 正文 / 段落

- **现状**：`.prose` 14px / line-height 1.625；`p` margin-bottom 0.75em。
- **做法**：正文字号默认 14px（`text-sm`）；行高/段距按设计微调；颜色 `text-foreground`。
- **取值**：行高/段距 → MasterGo。

### 5.3 加粗 / 内联强调

- **现状**：`strong` 用 prose 默认（无显式覆盖）。图二里加粗用于"客户经营损益""运单结算明细"等关键词。
- **做法**：`strong` 字重 600、颜色 `text-foreground`（或按设计略深）；不引入彩色加粗除非设计明确。
- **取值**：加粗色/字重 → MasterGo。

### 5.4 列表（有序 / 无序 / "—"描述项 / emoji 项）

- **现状**：`.prose ul/ol` padding-left 1.5em、`li` margin-bottom 0.25em；`li` 在 `ChatMessage` 有 `highlightAtMentionsInChildren` 包装（**逻辑保留**）。
- **目标**：图二的"1./2./3." 分组 + 每项"**关键词** — 说明"两段式、以及 emoji 项目符号（🔍📊💰📦⚠️）。
- **做法**：列表缩进/项间距/标记按设计；"关键词 — 说明" 是 markdown 文本本身，不需特殊组件，仅保证换行/间距/加粗排版正常；emoji 是内联字符，保证与文字基线对齐、间距合适即可。
- **取值**：缩进/项间距/标记样式 → MasterGo。

### 5.5 表格（核心：表格）

- **现状**：`globals.css` 第 390-405 行：`table` width 100% + `border-collapse`；`th/td` 1px `hsl(var(--border))` + padding 0.5em + 左对齐；`th` 背景 `hsl(var(--muted))`。
- **目标**：按设计稿细化（表头底色/描边/斑马纹/字号/圆角/对齐/外圆角裁切）。
- **做法**：在 `.prose table/th/td` 上按 MasterGo 调：表头底色（`bg-muted` 或设计色）、描边色（`border`）、单元格字号（13/14px）、是否斑马纹、外层圆角（如 `rounded-lg` + `overflow-hidden`）、横向滚动（窄屏 `overflow-x-auto`，可在 ChatMessage 给 table 包一层）。
- **取值**：表头底/描边/斑马/字号/圆角/对齐 → MasterGo。

### 5.6 内联 code / 代码块

- **现状**：`ChatMessage` 第 885-902 行：内联 code = `rounded-md bg-background/55 px-1.5 py-0.5 text-sm font-mono`；代码块 = `pre` `rounded-xl border border-border bg-background/55 p-4` + `font-mono`。
- **做法**：按设计微调底色/圆角/字号（对齐 02-styles：内联 code `rounded-sm`、代码块 `rounded-lg`、`13px` 等可按 §代码块规范）；不改解析、不加语法高亮（除非设计明确，属新功能 → 先问）。
- **取值**：→ MasterGo + 02-styles §代码块。

### 5.7 链接 / 文件路径链接 / 产物文件卡

- **现状**：
  - 链接 `a`（`ChatMessage` ~903 行）：可预览的远程/本地链接渲染成按钮触发 `onPreviewFile`；普通链接 `text-link`。**逻辑保留**。
  - 图三里 `/Users/.../outport-delivery-fee-report.html` 这类**文件路径**经 `preprocessTextForPreviewLinks` 转成可预览链接（逻辑保留）。
  - 产物/附件卡 = `FileCard`（图：`文件名 · 10.4 KB · 预览`）。
- **做法**：① 链接颜色/hover 下划线按设计（`text-link`/primary 派生，不裸 hex）；② 文件路径链接的展示样式按设计；③ `FileCard`：图标 + 文件名 + 大小 + "预览"按钮（橙色或按设计）的样式统一 token；**不改预览回调逻辑**。
- **取值**：链接色、FileCard 卡样式 + 预览按钮 → MasterGo。

## 6. 共享 / 风险

- **`.prose` 是全局**：`globals.css` 的 `.prose` 同时作用于"助手回复正文"和"思考过程里的 markdown"（任务一）。改 `.prose` 会同时影响两处——
  - 若设计要求两处排版一致 → 改 `.prose` 即可；
  - 若要求不一致（如思考区字号更小）→ 用更具体的作用域类（如给回复正文容器加专属类，仅在该类下覆盖），**不要把思考区改坏**；拿不准 → 停下来问。
- **`prose` 还可能用于非对话页**（如其它 markdown 渲染处）：grep `className=".*prose` 确认影响面；若波及无关页面，改用更局部的作用域。
- **不改逻辑**：`highlightAtMentionsInChildren`、`onPreviewFile`、`preprocessTextForPreviewLinks`、`urlTransform` 等一律保留。
- **🟥 语法高亮**：若设计稿代码块带语法高亮 = 新功能（需引库），**先停下来问**，默认不做。
