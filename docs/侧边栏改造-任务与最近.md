## 0. 目标

把侧边栏的「任务」「最近」两块对齐设计稿：① 纯样式/交互（顶部文案、分区标题、默认展开、任务组平铺）；② 最近会话项新增**运行中 / 失败 / 未读**三种状态指示。

## 1. 绝对铁律

1. **范围 = §3 文件**；「工作台」分区、「我的文件」、其它页面不动。
2. **样式按设计稿改**；**精确值以 MasterGo MCP 为准**（见 §4），找不到对应 token 不要造，列出来问。
3. **逻辑改动严格限定**：本任务**只允许**两处逻辑改动——(a) 新建 `session-unread` 轻量 store；(b) 在 chat store"运行成功完成"处调用 `markSessionUnread`、在"打开/切换会话"处调用 `markSessionRead`。**除此之外不改** chat store 收发/流式/运行逻辑、不改既有 props 签名。运行中/失败指示**只读** `runtimeBySessionKey`，零逻辑。
4. **写法遵守 02-styles**：Tailwind + `cn()`；禁止 inline style、模板字符串拼 className、无注释裸 hex、其它样式方案；现有 `dark:` 原样保留。
5. **横切统一 token + 品牌色**：颜色用语义 token，品牌色 `#FF6700`/`text-primary`，状态色用 success/destructive token；不引入 `#FF6F00`。
6. **要删的元素改为条件隐藏 + 注释**，不真删。
7. **顶部导航文案不改**：第一项保持 **"新对话"**（不改成"新任务"）；顶部其它项也不动文案/数量；**不加"我的文件"**。本任务顶部导航只在分区/留白样式层面受 §5 影响，文案零改动。

## 5. 逐项改动

### 5.0 品牌头加 logo（样式）

- **现状**：`sidebar-brand-header.tsx` 的 `SidebarBrandTitle`（~30 行）= 纯文字 `productName`("SClaw", `text-base font-semibold`) + 版本号(`text-xs text-muted-foreground`) + 可选 `ChromeEnvBadge`([DEV])，**无 logo**。
- **目标**：在 "SClaw" 文字**左侧加 logo 图标**（设计稿的 SClaw 吉祥物）。
- **做法**：
  1. `import logoSvg from '@/assets/logo.svg'`（现成资源；若与设计不符，按 MasterGo 导出的 logo 替换），在 `SidebarBrandTitle` 的 `productName` `<span>` 前渲染 `<img src={logoSvg} alt="" width={..} height={..} />`，尺寸/间距按 MasterGo（建议 `h-5 w-5`/`gap-2`，最终以 MCP 为准）。装饰图 `alt=""`，显式 width/height 防抖。
  2. 产品名/版本号样式按 MasterGo 微调（基本沿用现有 `text-base font-semibold` + 版本 `text-xs muted`）。
  3. **`[DEV]` 徽章逻辑不动**（`ChromeEnvBadge` 仅非生产显示，生产本就不显示）；折叠钮位置不动。
- **约束**：只在 `SidebarBrandTitle` 加图标 + 调样式，不改品牌头的 layout 变体逻辑（Mac/Win/省区分支保持）。

### 5.3 任务组平铺显示子项（交互）

- 设计稿里任务组（周会材料生成…）**直接平铺显示子项**，没有 per-group 折叠 chevron；任务名前有**图标**，子项左侧有**竖线**。
- **做法（逐条）**：
  1. **默认展开**：`SidebarTaskGroup`（~325 行）/ `SidebarScheduledTaskGroup`（~417 行）的 `open` 初始值 `false`→**`true`**。**保留**折叠能力代码（不删 toggle/chevron 逻辑，只改默认值 + 按设计调 chevron 显示）；若设计要求**完全去掉**组级折叠，则把 chevron 条件隐藏 + 注释（不真删）——拿不准先问。

  3. **三级子项加左竖线（新增）**：现状子项容器（~389）是 `mt-1.5 flex flex-col gap-1 **pl-5**`，**只有左缩进、无竖线**。改为加**左竖线**：容器加 `border-l`（色 `border-border`/按 MCP）+ 调左内距，使竖线对齐任务图标下方、子项相对竖线缩进（具体缩进/竖线色/粗细按 MasterGo）。`SidebarScheduledTaskGroup` 的子项容器同样处理。

- **token/约束**：图标 Lucide + §Icon 规范；竖线用 `border-border` 或 MCP 色，粗细 1px；缩进用间距阶梯。两个 Group 组件保持一致。

### 5.4 最近会话项：运行 / 失败 / 未读 三态指示（核心）

在最近会话行（~1480 行）右侧加一个状态指示位，**同一行最多显示一个**，优先级 **运行中 > 失败 > 未读**：

| 状态 | 数据来源（已确认） | 视觉 |
| --- | --- | --- |
| **运行中** | `runtimeBySessionKey[key]?.sending`（或 `activeRunId != null`）为真——含思考中/选项卡待填等执行态 | 转圈 `Loader2 animate-spin`，色按 MasterGo（建议 `text-muted-foreground`/primary） |
| **失败** | `runtimeBySessionKey[key]?.error != null` | 红色错误图标（`AlertCircle`/`XCircle`，`text-destructive`），参照 `WorkflowCard` 失败态 |
| **未读** | `useSessionUnread().isSessionUnread(key)`（见 5.5） | 红点（`#FA3C3C`/`bg-destructive`，尺寸位置按 MasterGo，约 6-8px） |
| 无 | 以上都不满足 | 不显示 |

- **只读 store**：运行中/失败直接从 `runtimeBySessionKey` selector 读，**不改任何运行逻辑**。
- 指示位用 `aria-label` 标注（运行中/执行失败/未读），装饰图标 `aria-hidden` 按 02-styles。
- 折叠态（整条侧栏 collapsed）下的最近图标列是否也显示指示，按 MasterGo；默认可不加，避免拥挤。

### 5.5 会话级未读 store（新建，🟥 我的设计）

- **新建** `src/stores/session-unread.ts`（zustand，仿 `sto-task-subitems` / `scheduled-task-unread` 的轻量模型）：
  ```
  interface SessionUnreadState {
    unreadKeys: Record<string, true>;           // 或 Set 序列化
    markSessionUnread: (key: string) => void;
    markSessionRead: (key: string) => void;
    isSessionUnread: (key: string) => boolean;
  }
  ```
  - 建议 `persist`（localStorage/electron-store）保留未读，重启不丢；key 名独立，不与现有 store 冲突。
- **打标点（chat store 两处，唯一允许的逻辑改动）**：
  1. **运行成功完成时** → `markSessionUnread(sessionKey)`。位置：chat store 把某会话 `sending` 由 true→false 且 `error == null` 的"运行收尾"处（参考 `stores/chat.ts` 中 `sending: false` 的 run-finalize 分支）。**仅成功完成才标未读；失败不标未读**（失败走 5.4 的 error 指示）。可加条件：仅当**该会话不是当前正在查看的会话**才标（避免给正看着的会话标未读）——按体验取舍，默认标了也行（打开即清）。
  2. **打开/切换到该会话时** → `markSessionRead(sessionKey)`。位置：`switchSession` / 进入该会话的入口。
- **未读优先级低于运行/失败**：运行中或失败时不显示未读红点。
- 🟥 这两处打标点要 Cursor 在 chat store 里精确定位"运行收尾"和"切换会话"，**改动前贴出准备改的代码片段给用户确认**，避免误伤收发逻辑。

### 5.6 分区标题 sticky 固定 + 列表滚动（方案 A，布局/样式）

- **现状**：`Sidebar.tsx` 第 ~1174 行是**单一滚动容器**（`flex min-h-0 flex-1 overflow-y-auto overflow-x-hidden`），任务/工作台/最近 的标题 + 列表全装在里面**一起滚动**，标题会随内容滚走。
- **目标（设计稿）**：分区标题（任务/工作台/最近）**钉在滚动区顶部不动**，列表在标题下方滚动（内容从标题下方穿过、被压住截断），整个中间区**仍只有一个滚动条**。
- **改动类型**：🟩 布局/样式（纯 CSS，不碰滚动逻辑/数据）。
- **做法**：
  1. **保持单滚动容器**（1174 行那个），**不**拆成多滚动区。
  2. 把分区标题组件 `SidebarCollapsibleSectionLabel`（~534 行）改成 **`sticky top-0 z-10`** + **底色 `bg-[var(--sto-sidebar-bg)]`**（盖住从下方穿过的列表，避免透出叠字）。它现在外层有 `mt-4`，sticky 时要处理好 `top` 偏移与层级，确保标题贴容器顶端钉住、且盖在列表之上。
  3. **三个分区标题（任务/工作台/最近）统一 sticky**（一致体验）。下滚时：任务标题先钉住 → 滚到最近时最近标题顶上来接力钉住（标准 sticky 行为）。
  4. **不改滚动结构/数据**：只加 `sticky` / `z-index` / 底色，不动 `overflow` 容器、不动列表渲染与"显示更多/展开全部"逻辑。
- **token/取值**：sticky 标题底色用 `--sto-sidebar-bg`（深色保留现有 `dark:` 对应色）；标题区 padding/高度/层级按 MasterGo；`z` 值确保盖住列表但不与顶部固定导航、底部用户卡冲突。
- **验证点**：下滚时子项被标题压住截断、不露字；只有一个滚动条；任务↔最近标题接力钉住正常；折叠某分区时 sticky 不错位。

## 6. 风险 / 注意

- `runtimeBySessionKey` 是现有 store，**只读不写**；运行中/失败零逻辑风险。
- 未读 store 的两个打标点是**唯一**碰 chat store 的地方，务必精准、先贴片段确认。
- 分区标题 / 任务组的默认值改动会影响"折叠状态不持久化"现状——本任务**不强求持久化**（除非 MasterGo/用户要求）；若要持久化是额外项，先问。
- 「工作台」`workspaceNav` 整段、顶部其它导航项、"显示更多/展开全部"机制——不动。
- 折叠态（侧栏整体收起）下的最近图标列改动谨慎，先确认是否要状态指示。
