# 连接器配置指南

在 memory-center「连接器管理」页新建/编辑连接器。目录为服务端驱动，**配置保存后客户端零代码生效**（技能广场 → 连接器 tab 刷新即可见）。

## 页面字段

| 字段 | 说明 |
|---|---|
| 名称 * | 卡片显示名 |
| 连接器类型 * | `托管命令行（managed_cli）` 或 `api_token` |
| 描述 | 卡片副标题 |
| 提示词 * | 用户点「去试试」后预填主聊天输入框的试用文案，支持多行 |
| 图标 URL / 排序 | 卡片图标与展示顺序 |
| runtime JSON * | 核心配置，见下 |
| installManifest JSON | **仅 `manifest_assets` 策略必填**，其余留空 |
| agent JSON | Agent 侧能力说明与 detail skill，见下 |

> 灰色占位符只是示例：开始输入后消失，**不相关字段直接删除，勿留占位文本**。可点「钉钉 dws 模板 / QPath 模板」一键填入再改。

## runtime JSON 怎么填

`managed_cli` 的 runtime 永远是 `binary + install + auth + gateway` 四段，差异只在按两个选择填哪些字段：

**安装方式 `install.strategy`（三选一）**

| strategy | 要填的字段 |
|---|---|
| `shell_script` | `unix`、`windows` 安装脚本 URL，`binDir` |
| `release_asset` | `releaseApiUrl`（release 列表 API）、`assetNameHint`（平台包名子串） |
| `manifest_assets` | `manifestUrl`（推荐 `server://{编码}/install-manifest`），且 installManifest 框必填 |

**授权方式 `auth.type`（二选一）**

| type | 要填的字段 | 客户端体验 |
|---|---|---|
| `cli_login` + `ui: "open_url"` | `login`/`status`/`logout` argv、`loginUrlPattern`（**必填**）、`loggedInPattern`/`loggedOutPattern`/`authExpiredPattern` | 弹内嵌窗口走网页授权 |
| `api_token` | 可选 `login` argv，占位符 `{{token}}`/`{{hostname}}`/`{{serverUrl}}` | 弹 serverUrl + Token 表单 |

### 示例 1：安装脚本 + 网页授权（QPath 式，最常见）

```json
{
  "binary": "your-cli",
  "install": {
    "strategy": "shell_script",
    "unix": "https://你的cdn/your-cli/install",
    "windows": "https://你的cdn/your-cli/install.cmd",
    "binDir": "~/.sto/your-cli/bin"
  },
  "auth": {
    "type": "cli_login",
    "ui": "open_url",
    "openIn": "embedded",
    "login": ["your-cli", "login"],
    "status": ["your-cli", "status"],
    "logout": ["your-cli", "logout"],
    "loginUrlPattern": "https://login\\.你的域/\\S+",
    "loggedInPattern": "已登录",
    "loggedOutPattern": "未登录",
    "authExpiredPattern": "请重新登录|expired"
  },
  "gateway": { "allowBinary": "your-cli", "denyArgs": ["upgrade", "install", "uninstall"] }
}
```

### 示例 2：release 下载 + PAT（glab 式）

```json
{
  "binary": "your-cli",
  "install": {
    "strategy": "release_asset",
    "releaseApiUrl": "https://gitlab…/api/v4/projects/{id}/releases?per_page=1",
    "assetNameHint": "windows_amd64",
    "binDir": "~/.stoclaw/bin"
  },
  "auth": {
    "type": "api_token",
    "login": ["your-cli", "auth", "login", "--hostname", "{{hostname}}", "--token", "{{token}}"],
    "status": ["your-cli", "auth", "status"]
  },
  "gateway": { "allowBinary": "your-cli", "allowBinaries": ["git"], "denyArgs": ["upgrade", "install"] }
}
```

### 示例 3：无 CLI 的纯 API 服务（类型选 api_token）

runtime 无 binary/install/auth，只需：

```json
{
  "serverUrlHint": "https://your-service.example.com",
  "tokenHint": "Personal Access Token",
  "validatePath": "/api/v1/me",
  "requiredScopes": ["read", "write"],
  "helpUrl": "https://docs…/如何创建token"
}
```

`gateway` 说明：`allowBinary` = 连接后放行给 Agent 的 Bash 命令；`allowBinaries` = 顺带解锁的二进制（如 glab 带 git）；`denyArgs` 不填默认禁 `upgrade`/`install`。未连接时这些二进制会被门禁拦截并提示用户去广场连接。

## installManifest JSON（仅 manifest_assets）

```json
{
  "version": "1.2.3",
  "platforms": {
    "darwin-arm64": { "url": "平台包下载地址", "sha256": "可选校验" },
    "windows-amd64": { "url": "平台包下载地址" }
  },
  "skillsZip": { "url1": "技能包地址" },
  "sources": { "github": { "repo": "可选源仓库" } }
}
```

## agent JSON

```json
{
  "readyWhen": "connected",
  "summary": "一句话能力说明，进入 Agent 系统上下文",
  "examples": ["查一下我的 XX 任务", "创建一个迭代"],
  "skill": {
    "slug": "your-cli-commands",
    "scope": "connector",
    "source": "package",
    "packageUrl": "https://gitlab…/archive.tar.gz"
  }
}
```

skill 包为 zip/tgz，解压后必须含 `SKILL.md`；仅连接成功后对 Agent 可见，断开自动隐藏。

## 验证

1. 保存后客户端打开 技能广场 → 连接器，点刷新
2. 一键连接应依次经历 `installing → authorizing → connected`
3. 新会话中让 Agent 调用该 CLI 验证门禁放行；断开后再试应被拦截

## 常见坑

- `open_url` 忘填 `loginUrlPattern` → 客户端报「暂不支持鉴权，请升级客户端」
- 占位示例文本原样保存 → 客户端解析出垃圾 URL
- `shell_script`/`release_asset` 误填 installManifest（应留空）
- Windows 登录 argv 与 mac 不同时需补 `auth.loginWindows`
- skill 包内没有 `SKILL.md` → 投影失败，Agent 看不到技能
