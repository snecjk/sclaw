## 1. 绝对铁律

1. **改动范围 = 对话流相关组件**（见 §2），其它页面/面不动。
2. **不改功能 / 接口 / 逻辑**：接口调用、props 既有签名、hooks、Zustand store、事件 handler 函数体、消息收发/流式逻辑、表单提交逻辑——一律不动。新增**可选 prop** 不算违规，但不得改既有签名语义。
3. **思考过程只改样式，不新增状态**（用户确认 c）：连接中 / 理解中 / 思考中 / 工具运行 / 完成折叠 这些**现有状态**保持逻辑不变，只调视觉。
4. **样式按设计稿改**（颜色/字号/间距/圆角/阴影/描边/图标/布局）。
5. **结构改动**：本文档 §4 已逐项标注「样式」/「结构（已确认）」/「🟥 需实现前再确认」。**已确认**的结构项（选项卡固定浮层、工作流卡查看态等）可直接做；本文档没写明的结构/逻辑改动必须停下来问。
6. **视觉值以 MasterGo MCP 为准**：色值/圆角/间距/图标名/固定高度，先从 MCP 取，再映射 `02-styles.mdc` token；找不到对应 token 不要造，列出来问（见 §3）。
7. **写法遵守 `02-styles.mdc`**：Tailwind + `cn()`；禁止 inline style、模板字符串拼 className、无注释裸 hex、其它样式方案；现有 `dark:` 原样保留、不新增。
8. **横切：统一 token + 校正品牌色**。这些组件现在大量写死 hex 且品牌色用 `#FF6F00`；本轮新写/改到的样式统一用语义 token，品牌色一律 `#FF6700` / `text-primary` 派生，不再引入 `#FF6F00`。
9. **共享组件 gate**：对话流组件被多处复用（见 §5），凡新增能力用可选 prop 默认关闭，确保未用到的调用方零变化。

## 4. 逐项改动规格

### 改动一：思考过程—— 仅样式

- **现状**：`ThinkingProcessPanel.tsx`。折叠态摘要"思考 N 次,使用 N 个工具"在 `ChatMessage.tsx`（`streaming.completedLabel` = "以上信息由 AI 提供"）。流式时展开、回合结束自动折叠（`useEffect` 已实现）。
- **改动类型**：🟩 样式（**不加状态、不改时机**）。
- **做法**：
  1. **展开/折叠时机保持不变**（用户确认 T1）：流式中展开、结束折叠，逻辑不动。
  2. **条目内容最多 4 行 + 内部滚动**（用户确认 T2）：思考文本 / 工具调用文本（`深度思考` / `调用工具–竞品分析` 等展开内容）超 4 行时容器固定高度、`overflow-y-auto` 内部滚动。具体行高/最大高度按 MasterGo。
  3. **整体样式按设计稿**（用户确认 T3）：面板底色、条目 icon、折叠摘要行（"思考 N 次…"）、`以上信息由 AI 提供 / ✓已完成` 的颜色/间距/字号，全部对齐 MasterGo + 02-styles token。
  4. 头像（`AssistantTurnMessage` 橙色 Sparkles 渐变块）按设计微调，逻辑不动。
- **token/约束**：文字 `text-sm`/`text-[13px]` + `text-muted-foreground`；图标 Lucide 按 §Icon；动画走 transform/opacity。

### 改动二：选项卡改为"吸附输入框上方的固定浮层"（结构）

- **现状（关键）**：`ParameterFormCard` 目前**内联渲染在 `ChatMessage.tsx` 第 ~447 行**，跟随消息流滚动。
- **目标（用户确认）**：参数选项卡变成**固定在对话底部输入框正上方的浮层**——固定高度、选项多时**卡内部滚动**，不随消息流滚走。
- **改动类型**：🟧 **结构（已确认）**——本轮最大结构改动，务必小心。
- **做法**：
  1. **挂载位上移**：在"承载对话消息列表 + 输入框"的容器里，于 `ChatInput` **正上方**新增一个固定浮层挂载区，渲染当前待处理的 `ParameterFormCard`；移除 / 停用 `ChatMessage.tsx` 内联渲染处（按铁律：若涉及删除，改为条件隐藏 + 注释，保留旧挂载代码）。
  2. **least-invasive 原则**：优先**不改表单状态来源逻辑**。推荐用以下之一（Cursor 评估后选，若任一方案需要改动表单 state/store 逻辑，**先停下来问**）：
     - (A) 用 React Portal 把 `ParameterFormCard` 渲染到输入框上方的固定容器，数据/回调仍来自原处；
     - (B) 在 chat store 暴露"当前待处理表单"的 selector（只读，不改写入逻辑），输入框上方据此渲染。
  3. **只显示一张 + 仅在有待选择时出现**（按建议定 T5）：同一时刻最多一张固定浮层；没有待处理表单时不渲染。
  4. **动画**（用户确认 T4）：浮层滑入/滑出（slide + fade）。duration/easing 用 02-styles 动画档（建议入场 `200ms ease-out`、出场 `150ms ease-in`），走 transform/opacity。
  5. **固定高度**（T6）：浮层最大高度 / 占对话区比例按 MasterGo；超出卡内部 `overflow-y-auto`。
  6. **等待态**（用户确认 T2/2）：浮层出现期间，思考区显示 `等待你的回复…`（脉冲点），**一直显示到用户提交**。若该文案/指示器现不存在，则作为"表单待提交"现有状态的**视觉新增**（不新增逻辑状态）；文案走 i18n 三语，样式参考 §流式脉冲（02-styles）。
  7. **提交后**（用户确认 T3/3）：浮层收起，流里留一条摘要行（如 `参数已确认 >`，可展开看所填），**样式参考 MasterGo 设计稿**。
- **🟥 实现前确认**：若方案 A/B 都无法避免改动表单的 state/store 写入逻辑，停下来问用户再做。

### 改动三：选项卡三模式

- **现状**：`OptionCardList.tsx`（数字徽章恒实心橙、选中=橙边+`#FFF5E6`）；`FormFieldRenderer.tsx`（number/select/...）；容器 `ParameterFormCard`（头部 1/N 翻页、底部"继续/提交"）。
- **改动类型**：🟧 样式 +（步进器）在现有字段上改造。
- **做法**：
  1. **徽章（数字角标）**：即每个选项左侧的圆形数字（1/2/3）。改为**未选 = 灰描边、选中 = 实心橙**（用户确认 T7 的口径），精确色值/描边按 MasterGo。
  2. **选中态/未选态/卡底色描边**：按设计稿（选中=橙边+浅橙底；未选=灰边+白底；hover 态按设计）。
  3. **数据修改 `− 数值 +` 步进器**（用户确认 T8）：**在现有 `renderNumberField` 基础上改样式**实现步进器（左 `−`、中数值、右 `+` + 单位），**不新增字段类型**、不改 onChange/校验逻辑。
  4. **区间字段 `20 ~ 50 %`**（按建议 T9）：两个数值输入 + 中间 `~` + 单位；聚焦态橙边（`focus` 边框 `#FF6700`）。按 MasterGo。
  5. **卡内填写**（按建议 T10）：选中的卡内联输入（文本等），复用 `FormFieldRenderer` 字段，仅样式贴合卡片。
  6. **容器**：头部"标题 · 选择类型 · N/N · 收起"、底部深色「继续/提交」(`继续 ↵`)；整卡作为改动二的固定浮层呈现。
- **token/约束**：标题 `text-sm`/`text-base` `font-semibold`；描述 `text-[12.5px]`/`text-sm` `text-muted-foreground`；徽章/边框/底色按 §颜色 token + MCP。

### 改动四：工作流卡

- **现状**：`WorkflowCard.tsx`，已有 running/completed/failed/timeout/pending 主题（绿/红/橙/黄）、计时、进度条、产物预览、"查看预览/查看工作流"。线上有"已运行 X 秒 · 执行中(绿)/执行失败(红)"。
- **改动类型**：🟩 样式（统一 token），不加新功能。
- **做法**：
  1. **状态色/徽章/计时/图标**：按 MasterGo（T13），统一到 02-styles 状态色 token（success/destructive/warning/primary），品牌色 `#FF6700`。
  2. **「查看产物」= 橙色按钮**（用户确认 T12）：实心或描边橙按钮按设计稿，替换现在的橙色文字/描边样式。
  3. **查看（完成）态**：只读展示，**不新增"重新运行"**（按建议 T11）。
  4. 运行中/失败/完成三态图标 + 文案颜色按 MCP。
- **约束**：不改 `hydrateWorkflowRun` / store / 计时逻辑，只换样式与按钮外观。

### 改动五：对话流整体

- **现状**：`ChatMessage.tsx`，助手消息容器 `mx-auto max-w-4xl`，markdown 用 `ReactMarkdown + remarkGfm`，用户气泡 `max-w-[80%]` + 橙渐变头像，AI 全宽无气泡。
- **改动类型**：🟩 样式。
- **做法**：
  1. **内容区宽度保持现状**（用户确认 T14）：维持 `max-w-4xl`，不改。
  2. **markdown 表格按 MasterGo 样式**（用户确认 T15）：定制表头底色/描边/斑马纹/字号/圆角，按 MCP 取值，映射 token。仅改 `ReactMarkdown` 的 table 相关渲染样式，不改解析。
  3. **用户气泡 / AI 全宽无气泡维持现状**（按建议 T16），只按设计稿统一颜色 token。
- **约束**：不改消息结构/角色判断/markdown 插件。

### 改动六：横切——统一 token + 校正品牌色

- 上述所有改到的样式：颜色优先语义 token；新写样式品牌色 `#FF6700`/`text-primary`；移除/替换新触及处的 `#FF6F00`（未触及处不强改，避免扩大 diff）；间距/圆角/阴影用 02-styles 档位。

## 5. 共享 / 结构风险

- **对话流组件被多处复用**：`ChatMessage` / `ThinkingProcessPanel` / `ParameterFormCard` 出现在 `Chat/index.tsx`、`HomeMainConversation`（首页对话）、`TaskDetail/TaskSubitemChatSurface`。改动二（选项卡固定浮层）要在**每个承载对话+输入框的布局**里都正确呈现——
  - 实现前先 grep 出所有渲染 `ChatMessage` + `ChatInput` 的容器，确认固定浮层挂载位；
  - 若不同容器结构差异大、无法统一，**停下来问**是否分容器处理。
- **gate**：`ThinkingProcessPanel` / `OptionCardList` / `FormFieldRenderer` 的样式改动若可能影响非对话流用途（如 `UserFormModal` 也用 `FormFieldRenderer`），新增样式用可选 prop / variant 控制，默认不变；改完验证 `UserFormModal` 等其它用例视觉无回归。
- **不真删**：涉及"移除内联挂载"等，按需保留旧代码并条件隐藏 + 注释（标注本文档章节、恢复方法）。
