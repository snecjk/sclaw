## 建议（第 2 / 5 / 7）

### 2. 微信 Worker 超时/崩溃 — 两段逻辑，勿当成「抄 Pi 即可」

现状：ready 超时不杀子进程；退出后 `failed` 永不自拉。  
微信 `WeixinChannelService` **没有** `disposeChild()`，只有 `shutdown()`——P1 必须**新建**（可对照 [`pi-runtime-service.ts`](../electron/services/pi-runtime-service.ts) 273–277，不是已有方法）。

本期做两段**不同**的逻辑（不做成无限守护）：

| 段 | 行为 | 与 Pi 的关系 |
| --- | --- | --- |
| A. 首次拉起 | 失败必杀 → 立即再试，**最多 2 次**，无退避 | **借鉴** Pi `startWithRetry`（118–139：首次 2 次、之后 1 次、失败立即重试）。**不是**复制粘贴整段；微信侧要自建 `disposeChild` + 自己的 retry 循环 |
| B. 就绪后崩溃 | 若 `getWeixinBinding()` 仍 bound → 指数退避自拉 **1s / 4s / 16s… 每簇最多 5 次**；超过则停，列表 disconnected | **全新代码**，Pi **没有**对等实现；禁止写成「抄 startWithRetry」 |

段 B 计数语义（写死）：**每簇崩溃 5 次**，不是进程生命周期总上限。`ensureReady` 成功握手后清零 `postReadyRestartCount`——崩→恢复→再崩会重新拿满 5 次预算；连续 5 次起不来才放弃。恢复路径本身要过 ready 握手，天然有节流。

其余写死：

1. **失败必杀**：timeout / `runtime.failed` / fork 异常都走新建的 `disposeChild()`（`kill` + 置空 + `state=stopped`），禁止残留僵尸。
2. **已解绑 / 无凭证**：不自拉。
3. **对端文案**：微信回 `处理失败` 用固定短句，**禁止**把 `String(error)` 发到会话；`errorMessage` 等细节只打日志（`logger.warn`），不发到会话。

不建议：启动路径改成阻塞等 Worker ready；不建议无上限重启。

### 5. 钉钉被抢绑 — 按「设备级 Hub」处理，并显式清 token

钉钉与 Mobile **共用一条 Hub WS / 一条 refreshToken**。对端设备抢走的是整机 Hub，不是「只抢钉钉」。旧 token 在本机已经废了，Mobile 无法单独连上。

建议：

1. `handleDingTalkBindReplaced` 同时 **revoke 钉钉 + disable Mobile**，再 `disconnectPermanently`。
2. **清共享 token（写死）**：`disableMobileAppBind`（及/或抢绑路径）必须把 mobile 行的 `refresh_token` **显式置 `null`**；钉钉 `revokeDingTalkHubBind` 已清 token，保持。  
   说明：仅 `revoked+enabled=0` 时，`resolveSharedHubRefreshToken` 因要求 `bound+enabled+token` 也取不到——功能已安全。仍显式 null，贴合「清共享 token」、避免语义缝隙。
3. 频道页用同一套 `replaceHint`：钉钉行 + 移动端都提示「已在其它设备绑定 / 已解绑，请重新绑定」。
4. **不要**在抢绑后用 Mobile 残留 token 重连（与按需拉起方案 §4.3 已选 B 一致）。

### 7. 打包 — 安装包已经只含产物；本期锁死并给源树减肥

[`electron-builder.yml`](../electron-builder.yml) `files` 只有 `dist` / `dist-electron` / `package.json`。Vite 把 Worker 打成 `dist-electron/weixin-runtime/worker-entry.js`（`inlineDynamicImports`）+ 迷你 `package.json`。**vendor / spike 源码不会进安装包。**

本期仍要做：

1. **断言**：after-pack 或单测检查 `weixin-runtime/` 只有 `worker-entry.js` + `package.json`，没有 `vendor/`、`spike/`、`*.test.ts`。
2. **源树**：从 git 去掉 vendor 里不参与 thin import 的噪音（至少 `package-lock.json`、`.github/`、vendor 测试、spike `phase0-report.json`）。thin 仍 import 的 `api.ts` / `types.ts` / `cdn` / `mime` 保留。
3. **spike** 不进运行时；可留 `runtime/spike/` 作开发脚本，或移到 `docs/` / `scripts/`，README 标明「不打包」。

## 核心机制：一次 epoch 重置

常量（只加不改语义；下一轮破坏性升级再换新值）：

```ts
export const CHANNEL_BIND_EPOCH = '2026.09-host-weixin';
```

持久化：`AppSettings.channelBindEpoch`（electron-store）。  
触发点：**仅** [`ensureChannelRuntimesReady`](../electron/message-channel/hub/startup.ts)，且在 `ensureFixedChannelBindings` / probe / start Worker **之前**。幂等：已是本 epoch 则跳过。  
实现顺序：先 `wireSclawInboundListener` / `wireSclawBindReplacedListener`，再 `maybeResetChannelRuntimeEpoch`——监听器先就位，epoch 内 `disconnectPermanently` 才不漏事件（比字面「函数第一行」更安全）。

### 重置做什么

```
maybeResetChannelRuntimeEpoch()
  ├─ 杀微信 Worker（若已 fork）
  ├─ Hub disconnectPermanently
  ├─ 删目录
  │    ~/.stoclaw/weixin/
  │    ~/.stoclaw/openclaw/openclaw-weixin/
  │    遗留 sync：~/.stoclaw/openclaw/agents/default/sessions/.openclaw-weixin-sync/
  ├─ SQLite channel_connections（dingtalk / wechat / sto-mobile / mobile）
  │    bind_status=revoked, enabled=0
  │    refresh_token / credential_token = null
  ├─ catalog_sessions：session_type='channel' 且未删 → softDelete
  ├─ 写 channelBindEpoch
  └─ info 日志（不把 token 打出来）
```

**不做：** 删主聊 / 工作流 catalog；不删引擎 transcript 文件；不改 `openclaw.json` 里已有的第三方剥离（sanitize 继续负责）。

### 重置之后的运行时

| 通道 | 行为 |
| --- | --- |
| 微信 | 无凭证 → skip Worker；列表走 Available「扫码绑定」 |
| 钉钉 | 无 token → skip Hub；「扫码绑定」 |
| Mobile | 行 revoked → 开关关闭，需重新打开绑定 |
| 入站 | latest 找不到（已 soft-delete）→ 新 sessionKey；引擎固定 `pi`+`main` |

### 停迁移：5 处必须一致 no-op（含子进程 boot）

[`migrateLegacyCredentials`](../electron/message-channel/weixin/runtime/transport/migrate-credentials.ts) **永久改为 no-op**（或删实现、调用方改空函数），**禁止**再把 legacy 拷进 `~/.stoclaw/weixin/`。遗留目录只在 epoch 重置时删除。

运行时调用点（**必须 5 处全覆盖**；漏一处仍可能从 OC 目录复活）：

| # | 位置 | 今日调用 |
| --- | --- | --- |
| 1 | `hasWeixinBotBound` | → `ensureWeixinCredentialsMigrated` |
| 2 | `getBoundWeixinAccountId` | → 同上 |
| 3 | `upsertWeixinBinding` | → 同上 |
| 4 | `WeixinChannelService.start` | → 同上 |
| 5 | **`worker-entry.ts` `boot()`** | **直接** `migrateLegacyCredentials({ overwrite: false })` |

第 5 点特别重要：fork 出的子进程 boot 若仍迁移，Host 已清盘后 Worker 仍可能从 legacy 拷回凭证。post-epoch 重扫只写新目录，no-op 迁移是安全的，但覆盖要全。spike 脚本可保留迁移或改为显式开发工具，**不进生产启动路径**。

解绑/探测一律以 **DB bound + 新目录凭证** 为准，禁止仅用 `hasWeixinBotBound()`（只看文件）当「该拉 Worker」。

### probe 与 binding 读路径

`probeChannelRuntimeNeeds.weixin.shouldStartWorker` 改为：`await getWeixinBinding() != null`（与列表同源）。

- `probeChannelRuntimeNeeds` **已是 async**，`await` 即可；勿再同步调 `hasWeixinBotBound` 作 start-gate。
- 核查：`hasWeixinBotBound` 作拉起决策的只有 probe（已改为 `getWeixinBinding`）；`WeixinChannelService.hasBoundBot()` 已删除，避免文件检查 footgun。

### `getWeixinBinding` 无 DB 行兜底（保留，写清意图）

[`binding.ts`](../electron/message-channel/weixin/binding.ts) 在 `!conn` 时用 `resolvePrimaryAccount()` 从凭证文件兜底——**保留**，仅服务「扫码成功已写文件、DB 行尚未落盘 / 迁移窗口」的短窗口。

- epoch 重置**同时**删凭证文件 + revoke DB → reset 后该分支**天然不会触发**（机制安全，不是漏洞）。
- **不要**为「防复活」删掉该分支；**也不要**在此分支里重新引入 legacy 迁移。
- 实现/评审注释补一句：保留首次绑定窗口；reset 后因文件已删不会复活。

## 实施切片

### P0 — epoch 重置 + 停迁移（对应决定 1、3）

1. `AppSettings.channelBindEpoch` + `CHANNEL_BIND_EPOCH`
2. 新模块（建议 `electron/message-channel/common/channel-runtime-epoch.ts`）：删目录、revoke 三通道行（token 一律 null）、bulk soft-delete channel catalog、停 Worker / Hub
3. `ensureChannelRuntimesReady` 开头调用；失败只 warn，仍写入 epoch，避免每次启动循环清盘（清盘失败细节打日志）
4. `migrateLegacyCredentials` **永久 no-op**；上表 **5 处**全部走 no-op（含 `worker-entry` boot）；`ensureWeixinCredentialsMigrated` 可保留为空壳或删除调用
5. probe：`await getWeixinBinding()`；解绑保持清新目录（legacy 已在 epoch 删光）
6. 注释/`weixin/README`：写明 `getWeixinBinding` 无 DB 兜底仅首次绑定窗口；reset 后不触发

单测：

- 未写 epoch → 删 fixture 目录、revoke 行、catalog channel 变 `deleted_at`
- 已写 epoch → 不再删、不再 revoke
- 有 legacy 文件、无 DB 行 → 不拉 Worker；`migrateLegacyCredentials` 不拷贝
- worker boot 路径：no-op 后不从 legacy 恢复
- `getWeixinBinding`：revoked 不复活；`!conn`+无文件 → null

### P1 — Worker 生命周期 + 对端错误（建议 2）

1. **新建** `WeixinChannelService.disposeChild()`（对照 Pi 273–277：`kill`、置空、`state=stopped`）；现有 `shutdown()` 可复用或委托它
2. timeout / failed 先 dispose 再 reject
3. **段 A**：首次拉起最多 2 次立即重试（借鉴 Pi，自写循环；**勿**整段复制 `startWithRetry` 当已含退避）
4. **段 B**：`exit` 且仍 bound → **新建**指数退避自拉（1s/4s/16s… **每簇**最多 5 次；ready 成功后计数清零）；unbound 不拉
5. `bridge-inbound` 对端固定文案（如「处理失败，请稍后重试」）

单测：timeout 后 `kill` 被调用；exit 后 bound 会再 start、revoked 不会；退避次数上限。

### P2 — 抢绑同步 Mobile（建议 5）

1. `handleDingTalkBindReplaced`：`revokeDingTalkHubBind` + `disableMobileAppBind`
2. **`disableMobileAppBind`（或抢绑专用路径）显式 `refresh_token: null`**——与计划「清共享 token」对齐，不只靠 enabled=0
3. 通知渲染器：现有 `channel:dingtalk-bind-replaced` 可复用；Mobile 行靠 refresh 后的 status
4. 频道页：钉钉 `replaceHint` 时，Mobile 副文案同步「需重新绑定」（不单独发明 WS 重连）

单测：replaced 之后 `resolveSharedHubRefreshToken()` 为 null；mobile 行非 bound 且 `refresh_token` 为 null。

### P3 — 打包与源树（建议 7）

1. after-pack 或 vitest：`dist-electron/weixin-runtime` 文件白名单
2. vendor 去掉 lock / `.github` / 未引用测试；README.VENDOR 写清「thin 引用了哪些文件」
3. spike 标注开发专用；`weixin/README.md` 去掉「会迁移 legacy」的表述，改为「本 epoch 不迁移，需重扫」

### 不在本期

- 策略 C registry 缺失盲区（决定 4）
- 恢复 WhatsApp 等（决定 6）
- 拆 Hub 为钉钉/Mobile 两条 WS
- 批量改写历史 registry / 把旧会话迁到 `pi`+`main`
- 频道页「升级说明」大弹窗（列表已是未绑定扫码态；可选一次 toast，非必须）

## 启动时序（改后）

```
ensureChannelRuntimesReady
  ├─ wire inbound / bindReplaced listeners  ← 先挂监听，再 disconnect 不漏事件
  ├─ maybeResetChannelRuntimeEpoch()       ← 幂等；在 fixed/probe/start 之前
  ├─ ensureFixedChannelBindings()          ← 重置后行已是 revoked，基本 no-op
  ├─ probe（await getWeixinBinding；Hub 看 bound+token）
  ├─ 有微信 binding → start Worker
  │     ├─ 段 A：失败必杀 + 最多 2 次立即重试
  │     └─ 段 B：就绪后崩溃 → bound 才指数退避自拉（每簇最多 5 次）
  └─ 有 Hub token → sync → 再取 token → connect
       sync replaced/unbound → 钉钉+Mobile 一起清（token null）→ 不 connect
```

扫码成功路径仍 **禁止** 再跑全量 ensure（只 `hub.connect` / `applyLoginSuccess`）。epoch 已写过，扫码不会被重置冲掉。

## 验收

1. 升级前已绑微信（含 `~/.stoclaw/openclaw/openclaw-weixin`）→ 升级后未绑定、Worker 未起、旧目录不存在；重扫后可收发。
2. 升级前钉钉/Mobile 已绑 → 需重新扫码/打开开关；旧 Hub token 不能连。
3. 升级前钉钉里聊过的会话 → 再发消息是新 sessionKey；App 历史列表不出现可续的旧 channel 会话。
4. 主聊/工作流会话不受影响。
5. 微信 Worker ready 超时 → 无残留进程；杀 Worker 后仍 bound 会自拉（有退避上限），解绑后不自拉。
6. 另一台设备抢 Hub → 本机钉钉与 Mobile 都变未绑定，`refresh_token` 均为 null，WS 停。
7. 安装包 `weixin-runtime` 仅入口 + package.json。
8. Telegram/WhatsApp 配置启动后仍被剥掉（既有 sanitize）。
9. 子进程 boot 后仍不存在从 legacy 拷回的凭证文件。
