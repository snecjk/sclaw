# 应用描述创建与工作台编辑方案

## 1. 目标

为开发应用补充“应用描述”能力，覆盖两个入口：

1. 在“创建应用”弹窗中填写应用描述。
2. 进入应用工作台后，点击顶部应用名称，通过浮框查看和编辑应用描述。

描述需要在本地应用元数据中持久化，并在应用首次提交时写入远程 Site App；对于已经绑定远程 Site App 的应用，编辑后直接更新远程描述。

## 2. 现状与约束

当前创建流程为：

```text
创建应用弹窗
  -> POST /api/app-dev/apps
  -> 创建本地模板和 .sclaw/app-dev.json
  -> 首次提交源代码
  -> POST /api/v1/site-apps 创建远程应用
```

当前首次提交创建远程应用时，描述固定为：

```ts
`${applicationName} 应用`
```

现有远程接口已经支持描述字段：

```http
POST /api/v1/site-apps
POST /api/v1/site-apps/{appCode}/update
```

因此远程协议无需新增接口，只需在本地创建、元数据读写和工作台编辑链路中补齐 `description`。

本需求只编辑应用描述，不提供应用名称编辑。应用卡片和应用内部页面是否展示描述不在本次范围内。

## 3. 产品交互

### 3.1 创建应用

在“应用名称”下方、“应用类型”上方新增多行输入框：

```text
应用名称 *
┌────────────────────────────────────┐
│ 快递查询助手                       │
└────────────────────────────────────┘

应用描述（选填）
┌────────────────────────────────────┐
│ 例如：帮助网点查询快递物流、跟踪异常件 │
│                                    │
└────────────────────────────────────┘
简要介绍应用的用途和主要功能。    18/200
```

交互规则：

- 描述选填，最多 200 个字符。
- 输入框默认显示 3 行，不允许横向缩放。
- 字数按 JavaScript 字符串长度计算，与前后端校验保持一致。
- 提交时去除首尾空白；只包含空白字符时保存为空字符串。
- 描述超长时禁止提交，并在字段下方显示错误。
- 弹窗内容超出视口时，中间内容区域滚动，底部操作区固定。

### 3.2 工作台浮框

将工作台顶部应用名称从静态标题改为可点击按钮。鼠标悬停时显示浅色背景和下拉图标，点击后在名称下方打开浮框：

```text
测试Assets1号 ▾
┌────────────────────────────────────┐
│ 应用描述                           │
│ ┌────────────────────────────────┐ │
│ │ 帮助网点查询快递物流、跟踪异常件 │ │
│ │                                │ │
│ └────────────────────────────────┘ │
│                             18/200 │
│                       取消    保存 │
└────────────────────────────────────┘
```

交互规则：

- 浮框宽度 360px，受窗口宽度限制；在标题按钮左侧对齐、下方展开。
- 浮框使用 `no-drag`，避免与 Electron 顶栏拖拽区域冲突。
- 打开时加载应用描述；加载期间输入框和保存按钮不可用。
- 没有描述时显示占位文案“添加应用描述”。
- 内容未变化、正在加载、正在保存或超过 200 字时，“保存”按钮禁用。
- 保存成功后关闭浮框，并提示“应用描述已保存”。
- 保存失败时保留草稿，浮框不关闭，在字段下方显示错误并允许重试。
- 按 `Esc` 或点击“取消”放弃本次草稿并关闭。
- 点击浮框外部：内容未修改时直接关闭；内容已修改时保持打开，避免误丢输入。
- 切换到其他应用时清空当前草稿、错误和加载状态。

应用模板工作区不展示该编辑入口，因为模板描述属于模板元数据，不是 Site App 描述。

## 4. 数据模型

扩展本地应用标记文件 `.sclaw/app-dev.json`：

```ts
interface AppDevMarker {
  // 现有字段省略
  description?: string;
}
```

新建应用始终写入该字段，即使用户没有填写：

```json
{
  "kind": "app-dev",
  "name": "快递查询助手",
  "description": "",
  "pageType": "site"
}
```

`undefined` 和空字符串具有不同含义：

| 本地值 | 含义 | 首次创建远程应用时的值 |
| --- | --- | --- |
| 字段不存在 | 旧版本创建的应用 | `${applicationName} 应用` |
| `""` | 新应用明确未填写，或用户清空 | `null` |
| 非空字符串 | 用户填写的描述 | 去除首尾空白后的内容 |

`writeAppDevBootstrap` 重新写入标记文件时必须保留已有 `description`。只有调用方明确传入 `description` 时才覆盖原值，避免运行环境初始化、导入或其他已有流程意外清空描述。

## 5. API 设计

### 5.1 创建本地应用

扩展现有接口：

```http
POST /api/app-dev/apps
Content-Type: application/json
```

请求体新增：

```ts
{
  name: string;
  description?: string;
  parentDir?: string;
  projectType?: string;
  pageType?: 'site' | 'assets';
  templateId: string;
  templateVersion: string;
  templateSource?: 'local-resource' | 'memory-center';
}
```

后端执行统一标准化：

```ts
const description = input.description?.trim() ?? '';
if (description.length > 200) {
  throw new Error('应用描述不能超过 200 个字符');
}
```

标准化后的描述写入 `.sclaw/app-dev.json`。

### 5.2 获取可编辑描述

新增 Host API：

```http
GET /api/app-dev/apps/description?workspaceId={workspaceId}
```

返回：

```ts
{
  description: string;
  bound: boolean;
  source: 'remote' | 'local';
  stale?: boolean;
}
```

读取规则：

1. 根据 `workspaceId` 解析并校验本地工作区路径。
2. 读取 `.sclaw/app-dev.json`。
3. 没有 `appCode` 时直接返回本地描述。
4. 有 `appCode` 时调用现有 `getSiteApp(appCode)`，以远程描述为准，并将远程结果回写本地缓存。
5. 远程读取失败但本地存在描述时，返回本地描述，并设置 `stale: true`；浮框显示“当前展示本地缓存，连接恢复后可保存同步”。
6. 远程读取失败且本地也没有描述时，接口返回错误。

该接口必须通过 renderer 的 `hostApiFetch` 调用，不在 React 组件中直接请求 Memory Center。

### 5.3 保存描述

新增 Host API：

```http
POST /api/app-dev/apps/description
Content-Type: application/json
```

请求体：

```ts
{
  workspaceId: string;
  description: string;
}
```

返回：

```ts
{
  description: string;
  bound: boolean;
}
```

保存规则：

1. 校验 `workspaceId`，并解析到真实应用目录。
2. 对描述执行 `trim()`，校验长度不超过 200。
3. 未绑定远程应用时，只更新 `.sclaw/app-dev.json`。
4. 已绑定远程应用时，先调用：

   ```http
   POST /api/v1/site-apps/{appCode}/update
   Content-Type: application/json

   { "description": "标准化后的描述" }
   ```

   清空描述时传 `{ "description": null }`。

5. 远程更新成功后，将远程响应中的标准化描述写回本地标记文件。
6. 远程更新失败时不修改本地文件，向前端返回错误，保证用户再次打开时不会误以为已经同步成功。

远程成功、本地缓存写入失败属于少见的部分成功状态。接口应返回明确错误并记录日志；下次打开浮框会重新读取远程内容并修复本地缓存，因此不会覆盖远程结果。

## 6. 首次提交同步

扩展 `readMarkerForFirstPush` 返回值：

```ts
{
  applicationName: string;
  description?: string;
  pageType: SiteAppPageType;
  source?: 'created' | 'imported';
  appCode?: string;
}
```

首次提交创建远程应用时：

```ts
const remoteDescription = marker.description === undefined
  ? `${applicationName} 应用`
  : marker.description.trim() || null;

await createSiteApp({
  name: applicationName,
  description: remoteDescription,
  pageType,
});
```

这样既保持旧应用行为，也能正确同步新应用填写或主动清空的描述。

### Renderer

1. `src/components/more-apps/CreateAppDialog.tsx`
   - 增加 `description` 状态、输入框、字数和校验。
   - 调用 `createUserApp` 时提交描述。
   - 调整弹窗最大高度、内容滚动和底部操作区布局。

   - 将应用名称替换为可点击按钮。
   - 对非模板应用挂载描述浮框。
   - 管理打开、加载、草稿、保存、错误和脏数据状态。
   - 切换 `workspaceId` 时重置编辑状态。

3. `src/components/app-dev/AppDescriptionPopover.tsx`（新增）
   - 封装浮框展示与编辑 UI，避免继续扩大工作台主组件。
   - 接收 `workspaceId`、`appName`，内部调用描述查询和保存接口。
   - 补充 `aria-expanded`、`aria-controls`、字段标签和错误提示。

4. `src/lib/app-dev-api.ts`
   - `createUserApp` 参数增加 `description?: string`。
   - 新增 `getAppDescription(workspaceId)`。
   - 新增 `updateAppDescription({ workspaceId, description })`。

### Electron Main

1. `electron/services/app-dev-service.ts`
   - `AppDevMarker` 和 `CreateUserAppInput` 增加 `description`。
   - 创建应用时校验并保存描述。
   - `writeAppDevBootstrap` 支持写入并保留描述。
   - 新增读取与更新应用描述的 service 方法。

2. `electron/api/routes/app-dev.ts`
   - 注册描述查询和保存路由。
   - 继续使用现有 Host API 鉴权、错误序列化和工作区路径解析机制。

3. `electron/services/code-collab-service.ts`
   - `readMarkerForFirstPush` 读取描述。
   - 首次创建远程应用时使用本地描述，替换固定拼接值。

4. `electron/services/site-app-api.ts`
   - 不新增远程接口。
   - 复用 `getSiteApp` 和 `updateSiteApp`；如有必要，为更新描述增加窄类型包装函数，避免调用方传任意字段。

## 8. 实施顺序

建议按以下顺序开发，每一步都可以独立验证：

1. 扩展 `AppDevMarker`、创建参数及 `writeAppDevBootstrap`，完成本地持久化。
2. 修改首次提交逻辑，验证创建远程应用时描述传参正确。
3. 增加描述查询与保存的 Host API，验证未绑定和已绑定两条分支。
4. 修改创建应用弹窗。
5. 新增工作台描述浮框并接入标题。
6. 补齐单元测试和回归测试。
7. 根据仓库 OpenSpec 约定，在正式编码前创建 proposal、design、specs 和 tasks；实现完成后再执行 apply 和归档流程。

## 9. 测试方案

### 单元测试

创建弹窗：

- 输入描述后，`createUserApp` 收到去除首尾空白后的描述。
- 未填写描述时提交空字符串。
- 200 字允许提交，201 字禁止提交。
- 创建请求失败时保留用户输入。

本地服务：

- 创建应用后 `.sclaw/app-dev.json` 包含 `description`。
- `writeAppDevBootstrap` 未显式传入描述时保留旧值。
- 描述超长时后端拒绝写入。
- 旧应用缺少描述字段时能够正常读取。

首次提交：

- 非空描述原样传给 `createSiteApp`。
- 新应用空字符串转换为 `null`。
- 旧应用缺少字段时仍使用“应用名称 + 应用”。

工作台浮框：

- 点击应用名称打开浮框并加载描述。
- 模板工作区不出现描述浮框。
- 未修改时保存按钮禁用。
- 保存成功后关闭并提示成功。
- 保存失败时保留草稿和浮框。
- 切换应用后不会显示前一个应用的描述或错误。

远程同步：

- 未绑定应用仅更新本地文件。
- 已绑定应用调用 `/api/v1/site-apps/{appCode}/update`。
- 清空描述时远程请求传 `null`。
- 远程失败时本地文件不改变。
- 远程读取失败时能够显示带 `stale` 标记的本地缓存。

### 手工回归

1. 分别创建 Site、Assets 应用，填写描述并检查本地标记文件。
2. 首次提交后从远程详情确认描述一致。
3. 点击工作台标题修改描述，关闭并重新打开，确认远程和本地一致。
4. 清空描述并保存，确认远程描述为空。
5. 断网后打开已绑定应用，确认展示本地缓存；保存失败后草稿仍在。
6. 在小窗口和 macOS 顶栏拖拽区域验证浮框定位、滚动和点击行为。

## 10. 验收标准

- 创建应用时可以选填 0～200 字的应用描述。
- 描述写入 `.sclaw/app-dev.json`，重启应用后不会丢失。
- 首次提交时描述正确同步到远程 Site App。
- 点击工作台顶部应用名称可以查看和编辑描述。
- 已绑定应用保存后，远程详情与本地缓存一致。
- 保存失败不会关闭浮框或丢失草稿，也不会把未同步内容写成本地成功状态。
- 旧应用、未绑定应用、Site、Assets 和模板工作区均保持兼容。
- Renderer 不直接请求远程服务，所有调用继续通过 Host API 进入 Electron Main。

## 11. 不在本次范围内

- 编辑应用名称。
- 在应用广场卡片上展示描述。
- 在生成的应用页面内部展示或修改描述。
- 描述驱动 AI 自动生成或修改应用。
- 描述历史版本、审计记录和多人同时编辑冲突处理。
