## 0. 目标

修对话流三栏（导航 / 对话区 / 预览区）的**布局与交互**，并按设计稿做面板样式。只动布局/样式，**不改消息收发、产物解析、预览渲染逻辑**。新增**可选 prop / 持久化字段**不算违规。

设计稿四个状态（MasterGo「stoclaw框架」）就是验收目标：
1. **对话内容区**：对话区顶部标题栏固定、输入框固定底部，导航 + 对话区两栏。
2. **导航栏折叠**：导航收起，对话区居中，两侧留白 `Auto` 自适应扩大。
3. **产物预览时**：变三栏，对话区自适应缩小让出预览区，预览区可手动拖宽。
4. **手动拖拽预览区**：对话区与预览区**最大可调比例 3:7**，记住用户拖动的比例，下次打开产物按上次比例展示（图示底部 30% / 70%）。

## 4. 框架交互问题（三个 Bug）

### 4.1 输入区/参数浮层不跟随对话区宽度

**现状（根因）**：对话列里**三套宽度各管各的**，宽度变化时不同步：
- 对话列容器 `stoChatShellPageColumnClass`（= `stoChatShellPageClass`，`max-w-862 + mx-auto`）→ 包消息区。
- `ChatInput` 外层（`ChatInput.tsx` L703–709）**又自己套了一层** `stoChatShellPageClass` + `px-6`：等于在已经限宽的列里再限一次宽、再缩进 24px，导致输入框比消息区窄、且边距随宽度变化对不齐。
- 参数浮层挂载（`index.tsx` L616–620）用的是 `px-6` + 内层 `mx-auto max-w-5xl`（**1024px**）——和上面 862px **不是一个宽度**，三者无法对齐。

**目标**：消息区、参数浮层、输入框**共用同一宽度容器**，对话区宽度变化（开预览 / 拖拽 / 折叠导航）时三者一起缩放、左右边缘始终对齐。

**做法（阶段二，先在阶段一给方案）**：
- 让对话列容器（`stoChatShellPageColumnClass`）作为**唯一限宽源**（`mx-auto max-w-862`）。
- `ChatInput`（default variant）外层**去掉重复的 `stoChatShellPageClass`**，改成 `w-full` + 与消息区一致的水平内距；保留 `embedded` 分支不动。
- 参数浮层挂载点（`index.tsx` L616–620）**去掉 `max-w-5xl`**，与消息/输入同宽同内距。
- 三者水平内距**统一为左右各 18px**（消息区也加上，与输入/浮层齐边）。✅ 已确认。

### 4.2 三栏默认不是对半分 + 拖拽范围 + 记忆比例

**现状**：
- 默认 `previewPanelPercent = 70`（`index.tsx` L75）→ 一开预览，预览区就占 70%、对话区只剩 30%（顶到最小），不是对半。
- 拖拽夹取在 `index.tsx` L370–377 与 `clampPreviewPanelPercent`（`surfaces.ts` L160–164）：预览区限制在容器 **30%–70%**。
- `previewPanelPercent` 是组件内 `useState`，**每次卸载/重进重置**，没有记忆。

**目标（对齐设计稿状态 3/4）**：
1. **默认对半分**：首次打开产物，对话区:预览区 = **50:50**。
2. **拖拽范围**：预览区在 **30%–70%** 之间（对话区 30%–70%），沿用现有夹取，不改。✅
3. **记忆比例**：**仅当前会话内存**——拖完保留比例，同一会话内关闭/再开产物按上次比例；切走或重进可重置。✅（不落 persist）
4. **比例标尺**：拖拽时显示当前比例（如 `30% / 70%`），对齐设计稿状态 4 底部标尺。✅ 要做。

**做法（阶段二）**：
- 默认值 `70 → 50`（`index.tsx` L75 与 `clampPreviewPanelPercent` 兜底默认 L161 改为 50）。
- 拖拽/夹取范围**不改**（仍 30–70）。
- 记忆：**保持 `previewPanelPercent` 为组件 state 即可**（已是会话内存），不新增 persist 字段。
- 标尺：拖拽态（`isResizing`）时在分隔条/预览区角落显示 `${100-previewPanelPercent}% / ${previewPanelPercent}%`，样式从 MasterGo 取。

### 4.3 产物预览区被遮挡

**现状（两条疑似根因，阶段一需逐条核实）**：
1. **窗口控件浮层压在预览右上角**：`AppShellChromeOverlay` 的 `WindowsControlsOverlay`（`app-shell-chrome-overlay.tsx` L74）为 `absolute right-0 top-0 z-40`，正好压在预览区头部右上角的操作按钮组（全屏/刷新/下载/在浏览器打开/关闭，`ChatPreviewPanel.tsx` L189–209）上 → Windows 下按钮被盖/点不到。
2. **预览区顶到窗口顶、没给窗口 chrome 留位**：省区壳层（`MainLayout.tsx` provincial 分支）无整行顶栏，`Chat` 外层 `-m-6`（`index.tsx` L446）把内容上移，预览头部贴到窗口顶部 chrome 区（`--sto-chrome-h`）下方。

**目标**：预览区头部（tab + 操作按钮）**完整可见可点**，不被窗口控件/拖拽区盖住，各平台一致。

**做法（阶段一先给方案、🟥 确认后再动）**：
- 优先**给预览区头部预留顶部内距**（让出 `--sto-chrome-h`），不动全局 chrome 浮层 z-index，避免影响导航折叠按钮/窗口控件。
- 若确为 `WindowsControlsOverlay` 与按钮重叠：方案是预览头部右侧操作组在 win32 下额外右移/留出控件宽度，**而非**降低浮层层级。
- 🟥 `app-shell-chrome-overlay.tsx` 是全局壳层，改它会牵动所有页面——**任何对该文件的改动先停下来确认**，本任务默认只改 `ChatPreviewPanel` 头部内距。

### 4.4 预览区头部改为双行（产物 tab 行 + 操作行）

**现状**：`ChatPreviewPanel` 头部是**单行**（`ChatPreviewPanel.tsx` L162–210）——左侧固定两个 tab「产物 / 工作流」，右侧一组操作按钮（全屏/刷新/下载/在浏览器打开/关闭）；多个产物之间靠**下拉切换**（L213–270 的 file switcher）。

**目标（按用户标注的红/绿两行）**：
- **上行 = 产物 Tab 行（红）**：把**当前页所有产物**(`previewableFiles`，来自 `use-chat-preview-panel.ts`)平铺成一排 **tab**，每个 tab 显示产物名 + **可关闭 `×`**；点 tab = 切换 `activePreviewFilePath`。
  - 左端 `☰` 图标：产物过多时的**列表/溢出菜单**入口（列出全部产物供选择）。🟥 行为待确认。
  - 右端图标：**收起/展开预览区**的开关（替代原来的全局关闭 `×`，对应现有 `closePreviewPanel` / 隐藏态浮层）。
  - 取代原下拉切换：L213–270 的 file switcher **条件隐藏 + 注释**，逻辑被 tab 行接管。
- **下行 = 操作行（绿）**：左侧显示**当前产物标题** + **元信息**（如 `数据日期：2026-05-19 08:00`）；右侧放**原右上角那组操作按钮**（全屏/刷新/下载/分享，对应现有 `handleFullscreen / handleRefresh / handleDownload / handleOpenExternal`，`ChatPreviewPanel.tsx` L189–209）。
  - 当前产物是**工作流**时，右侧额外出现 **`编辑工作流`** 按钮（对应现有 workflow tab 能力）。🟥 见下。

**做法（阶段二，先在阶段一给方案）**：
- 头部拆成两个 `shrink-0` 行：第一行 tab 列表（map `previewableFiles`，`activeFilePath` 高亮，`×` 调关闭单个 tab）；第二行 标题/元信息 + 操作按钮组。
- 「关闭单个 tab」：在 `use-chat-preview-panel.ts` 增一个**本地隐藏集合**（如 `dismissedFilePaths`），从 `previewFiles` 过滤；**不改产物扫描来源**。关到空时回到隐藏态/收起预览。
- 「产物/工作流」原二选一 tab 的语义如何并入新结构 → 🟥（见待确认）：是把工作流也作为 tab 行里的一个 tab，还是工作流独占一种产物类型、靠下行 `编辑工作流` 区分？
- 元信息（数据日期等）来自哪个字段：`AttachedFileMeta` 现无"数据日期"，工作流详情里可能有 → 阶段一确认数据来源，缺字段就列出来问，**不要造**。

> 边界：本节只动 `ChatPreviewPanel` 头部 + `use-chat-preview-panel` 的隐藏态；产物如何被扫描收集、预览内容怎么渲染——不动。

3. **导航折叠态（状态 2）**：对话区居中 + 两侧 `Auto` 留白——核对现有折叠逻辑（`settings.sidebarCollapsed`）下对话区是否已居中、最大宽度是否符合设计。
4. **预览头部**：tab（产物/工作流）选中态、操作按钮组样式按设计稿；保持品牌色 `#FF6700`。
5. 🟥 状态 4 底部 30%/70% 标尺：是否做成可见 UI，还是仅设计示意？

> 边界提醒：预览**内容区**渲染（`FilePreviewViewer` / `WorkflowPreviewPanel`）本轮不动，只动其外层面板的卡片/边距/头部。
