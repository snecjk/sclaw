## 4. 逐项改动

### 4.1 选项卡改为"吸附输入框上方的固定浮层"（结构，已确认）

- **现状（关键）**：`ParameterFormCard` 目前**内联渲染在 `ChatMessage.tsx` 第 ~447 行**，跟随消息流滚动。
- **目标**：选项卡变成**固定在对话底部输入框正上方的浮层**，固定高度、选项多时**卡内部滚动**，不随消息流滚走。
- **改动类型**：🟧 结构（已确认）——本任务核心、风险最高。
- **做法**：
  1. **挂载位上移**：在"承载对话消息列表 + 输入框"的容器里，于 `ChatInput` **正上方**新增固定浮层挂载区渲染当前待处理的 `ParameterFormCard`；`ChatMessage.tsx` 内联渲染处**条件隐藏 + 注释**（保留旧代码，标注本节、恢复方法）。**不改 `ChatInput` 本体**。
  2. **least-invasive（不动逻辑）**：优先**不改表单 state/store 写入逻辑**，二选一（Cursor 评估后选；任一方案**若需要改表单 state/store 写入逻辑，先停下来问用户**）：
     - (A) **React Portal**：把 `ParameterFormCard` 渲染到输入框上方固定容器，数据/回调仍来自原 props；
     - (B) **store 只读 selector**：在 chat store 暴露"当前待处理表单"的**只读** selector，输入框上方据此渲染（不新增写入 action）。
  3. **仅在有待处理表单时出现 + 同时只一张**（按建议定）：没有待处理表单时不渲染；同一时刻最多一张。
  4. **动画**（用户确认 T4）：滑入/滑出（slide + fade）。入场 `200ms ease-out`、出场 `150ms ease-in`，走 transform/opacity（02-styles 动画档）。
  5. **固定高度**（T6）：最大高度 / 占对话区比例按 MasterGo；超出卡内部 `overflow-y-auto`。
  6. **等待态**（用户确认）：浮层出现期间，思考区显示 `等待你的回复…`（脉冲点），**持续到用户提交**。若该指示器现不存在，作为"表单待提交"现有状态的**视觉新增**（不新增逻辑状态）；文案走 i18n 三语，脉冲样式参考 02-styles §流式脉冲。
  7. **提交后**（用户确认）：浮层收起，消息流里留一条摘要行（如 `参数已确认 >`，可展开看所填），**样式参考 MasterGo 设计稿**。
- **🟥 实现前确认**：若 A/B 都绕不开改表单 state/store **写入**逻辑，停下来问用户再做（碰"不改逻辑"红线）。

### 4.2 选项卡三模式—— 样式

**三模式 → 真实代码（已核对，先对齐口径再改）**

| 设计模式 | 对应代码 | 现状要点 |
| --- | --- | --- |
| **默认选择** | `renderSelectField`（`options` 非空）→ `OptionCardList`（`single`/`multi`/`display`） | 数字徽章恒实心橙（`OptionCardList` ~90 行 `bg-[var(--sto-brand-6)]`）；选中=橙边+`#FFF5E6`（~78-88 行）；`isDisplay` 由 `disabled` 或 description 含"仅展示/不可修改/系统预置"**自动判定**（`renderSelectField` ~201 行） |
| **卡内填写** | 选项卡 + 选中项内联 `FormFieldRenderer` 字段 | 现无专门组合形态；按 schema 实际结构呈现 |
| **数据修改** | `renderNumberField`（~146 行）+ `field.suffix`(单位) | 现为裸 `<input type=number>` + 左右 `prefix/suffix` 绝对定位文字，**无步进器**；区间是两个相邻 number 字段 |

- **改动类型**：🟧 样式 +（步进器）在现有字段上改造，**不新增字段类型 / 不改 onChange/min/max/step/校验**。
- **做法**：
  1. **徽章（选项左侧圆形数字）**：`OptionCardList` ~90 行那个 `bg-[var(--sto-brand-6)]` 角标，改为**未选=灰描边空心、选中=实心橙**；精确色值/描边按 MasterGo。
  2. **卡选中/未选/底色描边**：`OptionCardList` ~78-88 行 className，选中=橙边+浅橙底、未选=灰边+白底、hover 按设计；`display` 态=灰底只读不变。
  3. **数据修改步进器**：在 `renderNumberField` 外层包 `−` / `+` 两个按钮、中间保留现有 `<input type=number>`、右侧 `field.suffix` 作单位（如 天/%/分钟）；点 `−/+` 调 `onChange`（沿用现有 value 逻辑，受 `min/max/step` 约束），**不改字段类型/校验**。
  4. **区间字段 `20 ~ 50 %`**：两个相邻 number 字段并排 + 中间 `~` + 单位；聚焦态橙边（`focus:border-[#FF6700]`）。若实际 schema 不是两 number 而是单字段 → 停下来确认。
  5. **卡内填写**：选中卡内联渲染对应 `FormFieldRenderer` 字段，样式贴合卡片；不改字段逻辑。
  6. **容器 `ParameterFormCard`**：头部"标题 · 选择类型 · N/N(翻页) · 收起"（~367-390 行：容器 `rounded-2xl border-[#E5E6EB] bg-[#FAFBFC]`、头部 `border-b bg-white px-5 py-3.5`）、底部深色「继续/提交」(`继续 ↵`)；整卡作为 4.1 固定浮层呈现。所有写死 hex 改 02-styles token + MasterGo。
- **token**：标题 `text-sm`/`text-base` `font-semibold`；描述 `text-[12.5px]`/`text-sm` `text-muted-foreground`；徽章/边框/底色/步进器按 §颜色 token + MCP。
