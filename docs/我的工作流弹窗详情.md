# 我的工作流弹窗详情开发计划

## 背景
目前工作流列表点击卡片后弹出的详情弹窗（`WorkflowDetailModal`）中展示的数据是 Mock 数据。本次开发计划从后端获取真实数据，展示在弹窗"它会怎么做"时间轴中。

## 1. 定义 API 数据结构
在 `src/types/workflow.ts` 中:
* **新增接口** `MyWorkflowVersionResponse`:
  * 用于"我的工作流"请求结果。
  * 包含 `nodes` 数组。
* **复用/补充** 官方模板节点结构:
  * 官方推荐来源为 `workflow_template` 表的 `definitionJson` (或列表返回中的 nodes)，不需要新增类型，直接从现有 API 返回提取。

## 2. 新增 API 客户端函数
在 `src/lib/workflow-api.ts` 中:

* **新增函数** `fetchMyWorkflowVersionDetail(workflowId: string)`:
  * **请求路径**: `/api/my-tasks/agent/v1/workflow/{workflowId}/version` (暂定)
  * **用途**: 获取"我的工作流"详情，从版本记录中提取 `nodes` 列表。

* **注意**：官方推荐模板不需要新 API。通过复用现有的列表接口，解析返回数据体中的 `nodes` 或 `definitionJson` 即可获取步骤数据。

## 3. 创建 Hook 连接 UI
在 `src/pages/Workflow/` 下:

* **新增 Hook** `useWorkflowDetail(id: string, type: 'mine' | 'template')`:
  * 若 `type === 'mine'`，调用 `fetchMyWorkflowVersionDetail`。
  * 若 `type === 'template'`，解析现有数据获取 nodes。
  * **数据映射**: `steps[i].title = node.name`, `steps[i].description = node.description` (暂无则填空)。

## 4. 集成详情弹窗
修改 `src/pages/Workflow/components/workflow-detail-modal.tsx`:
* 接收真实 `steps` 数据，渲染时间轴。

## 5. FastAPI 后端更新（memory-center）

### 5.1 新增 API 端点
在 `memory-center/src/api/claw_api/v1/workflow_client.py` 中:

* **新增路由** `GET /api/my-tasks/agent/v1/workflow/{workflow_id}/version`:
  * **用途**: 获取"我的工作流"版本详情，返回包含 `nodes` 的完整版本数据。
  * **路径参数**: `workflow_id` (工作流实例 ID)
  * **返回数据结构**: `MyWorkflowVersionResponse`
    ```python
    {
      "success": True,
      "data": {
        "workflowId": "wf_xxx",
        "workflowName": "工作流名称",
        "description": "描述信息",
        "version": 1,
        "nodes": [
          {"id": "node_1", "type": "trigger", "name": "节点名称", "description": "节点描述", "config": {...}},
          ...
        ],
        "edges": [...]
      },
      "traceId": "xxx"
    }
    ```

### 5.2 Service 层方法
在 `memory-center/src/services/workflow_service.py` 中:

* **新增方法** `get_client_workflow_version_detail(workflow_id: str, user_code: str) -> dict | None`:
  * 通过 `workflow_repository.get_workflow_by_biz_id(workflow_id)` 获取工作流实例
  * 校验 `user_code` 是否为工作流创建者（权限控制）
  * 调用 `workflow_repository.find_preferred_version(workflow_id)` 获取首选版本（优先草稿，其次已发布）
  * 从 `version.definition_json` 中解析出 `nodes` 和 `edges`
  * 返回标准化后的版本详情数据

### 5.3 实现要点
* **权限校验**: 仅允许工作流创建者查看，非创建者返回 404
* **版本选择逻辑**: 
  1. 优先返回草稿版本 (`find_draft_version`)
  2. 若无草稿，返回已发布版本 (`find_preferred_version`)
* **数据提取**: 从 `definition_json` 字段（JSON 字符串）中解析 `nodes` 数组
* **复用现有逻辑**: 可参考已有的 `get_client_workflow_detail` 方法实现思路
