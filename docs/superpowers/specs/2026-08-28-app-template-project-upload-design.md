# 应用模板编辑页上传项目设计

**状态：已确认设计，实施计划已完成**

## 1. 背景

SClaw 已支持在“应用模板管理”中创建或打开 Site、Assets 模板工作区。模板工作区复用应用开发工作台，具备 AI 对话、代码编辑、内嵌预览、Git 提交和模板发布能力。

模板作者在维护初版模板时，通常已经有一个可运行的 React/Vite 项目。当前只能从 minimal 模板开始逐文件修改，无法直接把已有项目载入模板工作区，导致初始迁移成本较高。

本设计在模板编辑页增加“上传项目”能力。模板作者选择本地项目后，SClaw 将项目业务代码受控覆盖到当前模板工作区；上传完成后继续在同一页面通过 AI、代码和预览调整，最终使用现有“发布模板”能力发布 OSS 新版本。

## 2. 目标

- 在模板编辑页直接选择并上传本地前端项目。
- 支持反复“重新上传”，方便模板作者在外部工程与 SClaw 之间迭代。
- 上传后立即刷新现有内嵌预览，不离开模板编辑页。
- 保留模板身份、页面类型、Git 历史及 SClaw 平台基建。
- 上传前展示新增、修改、删除文件和兼容性问题。
- 每次应用覆盖前自动创建可恢复的 Git checkpoint。
- 上传只修改本地模板草稿；只有点击“发布模板”才上传 OSS 并生成新版本。

## 3. 非目标

第一期不包含：

- 浏览器远程上传 ZIP 或云盘文件。
- 在普通应用工作台中覆盖导入项目。
- 自动把 Site 项目转换为 Assets，或把 Assets 转换为 Site。
- 自动修复所有非 Vite 技术栈。
- 自动发布模板。
- 将本地项目目录、密钥或环境变量写入模板产物。

## 4. 用户体验

### 4.1 入口

入口只在当前标签为模板工作区时展示，位于模板编辑页顶部工具栏：

```text
模板名称    [运行状态]  [提交] [上传项目] [发布模板]
```

首次成功上传后，按钮文案改为“重新上传”。来源目录只记录在模板工作区的本地 `.sclaw` 信息中，不进入 Git 提交和 OSS 模板产物。

### 4.2 首次上传

1. 模板作者点击“上传项目”。
2. SClaw 打开本地文件夹选择器。
3. 用户选择项目目录。
4. SClaw 扫描项目并生成导入预览。
5. 确认弹窗展示：
   - 项目识别结果；
   - 将新增、修改、删除的文件数量和文件清单；
   - `package.json` 合并摘要；
   - 被忽略的敏感文件；
   - 阻断项和警告项。
6. 存在阻断项时禁止确认。
7. 用户确认后，SClaw 创建 checkpoint 并执行受控覆盖。
8. 完成依赖准备并刷新当前内嵌预览。

### 4.3 重新上传

模板工作区记录上一次来源目录及导入文件清单。点击“重新上传”时默认重新扫描该目录，也允许重新选择目录。

重新上传采用镜像语义：来源项目中已删除的业务文件，应从模板工作区删除；受保护的平台文件不参与镜像删除。确认弹窗必须明确列出待删除文件。

### 4.4 上传与发布的关系

“上传项目”只更新本地模板工作区，不调用 memory-center，不上传 OSS，也不递增模板版本。

模板作者通过 AI、代码编辑器和预览完成调整后，继续使用现有“发布模板”按钮。发布前仍需二次确认，发布成功后由 memory-center 自动产生新版本和 OSS 产物。

## 5. 文件处理规则

### 5.1 永久保护

以下内容不得被来源项目覆盖或删除：

- `.git/`
- `.sclaw/`
- 模板工作区身份标记
- `manifest.json` 中的 `schemaVersion`、`templateId`、`pageType`
- SClaw 必需的 Runtime、Skill、外部服务脚本及发布契约
- 模板工作区 Git 历史和 checkpoint

来源项目中的 `manifest.json` 只用于兼容性分析，不直接覆盖目标文件。允许合并的名称、描述等普通字段必须经过显式白名单。

### 5.2 默认导入

以下内容作为业务工程主体导入：

- `src/`
- `public/`
- HTML 入口
- 业务资源和样式
- TypeScript、Vite、ESLint 等普通工程配置
- `package.json` 中的业务依赖和业务脚本

### 5.3 默认排除

以下内容不复制、不打包、不记录具体值：

- `.env`、`.env.*`
- Token、证书、私钥和常见凭据文件
- `node_modules/`
- 构建产物和缓存目录
- 日志、覆盖率和临时文件
- 来源项目的 `.git/`、`.sclaw/`
- 操作系统和编辑器临时文件

扫描报告只展示敏感文件路径及忽略原因，不读取或回显其内容。

### 5.4 package.json 合并

`package.json` 不进行整文件覆盖：

- 以来源项目的业务依赖和业务脚本为主体；
- 保留 SClaw 必需的依赖、scripts 和包管理约束；
- 同名依赖版本冲突必须在确认弹窗展示；
- SClaw 基建依赖不能被来源项目移除；
- 合并结果必须在应用覆盖前通过结构校验。

### 5.5 Site 与 Assets

模板工作区的 `pageType` 是最终权威值，上传不能修改。

- Site 模板继续保留 Site SSO 和固定站点运行时能力。
- Assets 模板继续保留本地 SClaw 身份桥接和 iframe 发布约束。
- 来源项目明确声明了相反类型时，作为阻断项处理。
- 来源项目没有声明类型时，按当前模板类型注入基建并展示提示。

## 6. 架构

### 6.1 前端组件

在 `AppPlazaDevAppPane` 的模板工作区工具栏中增加上传入口，并新增独立确认弹窗。前端负责：

- 调用本地文件夹选择器；
- 发起扫描；
- 展示差异、警告和阻断项；
- 用户确认后发起应用覆盖；
- 展示进度和结果；
- 完成后触发文件列表、源代码和预览刷新。

前端不自行遍历或复制文件。

### 6.2 Host API

在现有 `/api/app-templates` 路由域下增加四个受控接口：

```text
GET  /api/app-templates/workspaces/import-source/status?workspaceId=...
POST /api/app-templates/workspaces/import-source/prepare
POST /api/app-templates/workspaces/import-source/apply
POST /api/app-templates/workspaces/import-source/cancel
```

`status` 返回当前模板是否存在上一次来源目录、来源目录名称及本地目录是否仍然可访问，不返回来源绝对路径。

`prepare` 输入当前模板 `workspaceId` 和可选的本地来源目录。首次上传必须提供目录；重新上传省略目录时由 Host 读取本地状态中的上一次路径。接口返回：

- 一次性 `importToken`；
- 项目识别信息；
- 新增、修改、删除文件；
- `package.json` 合并摘要；
- 忽略文件；
- 警告和阻断项。

`apply` 输入 `workspaceId` 和 `importToken`。Host 必须重新校验工作区、来源快照和 Token 有效期，不能信任 Renderer 传回的文件清单。

`cancel` 输入 `workspaceId` 和 `importToken`，只允许取消绑定到该工作区的未使用会话，并立即清理临时快照。

### 6.3 导入会话

`prepare` 在系统临时目录创建只读导入快照，并计算来源文件哈希。`importToken` 只引用 Host 内存中的导入会话，不暴露临时目录。

导入会话应满足：

- 绑定当前模板 `workspaceId`；
- 设定短期有效期；
- 只能成功应用一次；
- 应用、取消、过期后清理临时文件；
- SClaw 退出后不可恢复使用。

这样可以避免用户确认期间来源目录发生变化，也避免 Renderer 指定任意目标路径。

### 6.4 覆盖服务

覆盖服务只处理一个模板工作区，顺序如下：

1. 校验当前工作区是 `kind: app-template`。
2. 校验模板 Marker、Manifest 和 `pageType` 一致。
3. 创建覆盖前 Git checkpoint。
4. 将全部待修改和待删除文件复制到系统临时目录，作为本次操作失败时的恢复快照。
5. 根据上一次导入清单删除已消失的业务文件。
6. 复制本次来源业务文件。
7. 合并 `package.json` 和允许的工程配置。
8. 恢复模板身份和 SClaw 受保护文件。
9. 重新运行模板结构、敏感文件和构建配置校验。
10. 原子更新本地来源信息和导入文件清单。
11. 触发依赖准备和预览重启。

目标目录更新失败时必须自动恢复到覆盖前状态，不能留下半导入工作区。

## 7. 本地状态

上一次上传信息存入模板工作区的本地 `.sclaw` 状态文件，至少包含：

- 来源目录绝对路径；
- 最近上传时间；
- 最近来源快照哈希；
- 最近导入的业务文件相对路径和哈希；
- 最近一次成功导入结果。

该状态文件固定存放在被 Git 忽略的 `.sclaw/local/` 下，并加入模板归档排除规则，不进入 Git 提交和 OSS 包。

## 8. 错误处理

### 8.1 阻断项

以下情况禁止应用覆盖：

- 目标不是模板工作区；
- 模板 Marker 与 Manifest 身份不一致；
- Site/Assets 类型明确冲突；
- 来源目录无可识别前端入口；
- 来源目录包含越界软链接；
- `package.json` 无法解析或合并；
- 来源快照包含无法安全处理的凭据或路径；
- 当前模板工作区存在未解决的 Git 合并冲突。

### 8.2 警告项

以下情况允许用户确认后继续：

- 无法识别标准 Vite 启动脚本；
- 构建产物目录与 SClaw 默认值不同；
- 业务依赖与模板基建依赖版本不同；
- 来源项目没有 `pageType` 声明；
- 来源包含被忽略的 `.env` 或构建产物；
- 导入后可能需要 AI 调整入口或路由。

### 8.3 恢复

- `prepare` 失败不修改模板工作区。
- `apply` 失败自动恢复覆盖前状态。
- `apply` 成功后用户仍可通过现有 Git 恢复能力回到上传前 checkpoint。
- 依赖安装或预览启动失败不回滚已成功导入的源码；工作台展示诊断信息并允许 AI 修复或用户主动恢复。

## 9. 安全边界

- 目标路径只能通过 `workspaceId` 从 Session Catalog 解析，Renderer 不能传目标绝对路径。
- 来源目录由本地系统文件夹选择器产生，并由 Host 再次验证。
- 拒绝复制指向来源目录之外的软链接。
- 所有复制目标必须经过相对路径归一化和目录越界检查。
- 敏感文件扫描在 Host 完成，敏感内容不返回 Renderer、不写日志。
- `importToken` 必须绑定工作区、过期并单次使用。
- 发布阶段继续复用现有模板归档过滤和 memory-center 权限校验。

## 10. 测试策略

### 10.1 单元测试

- 项目类型和入口识别。
- 忽略规则与敏感文件识别。
- 受保护路径不可覆盖或删除。
- `package.json` 合并及版本冲突报告。
- Site/Assets 类型一致性校验。
- 上一次导入清单驱动的镜像删除。
- 软链接和路径越界拒绝。
- `importToken` 的绑定、过期和单次使用。
- 应用失败后的自动恢复。

### 10.2 路由契约测试

- `prepare` 只接受有效模板 `workspaceId`。
- `prepare` 不修改模板工作区。
- `apply` 不接受 Renderer 自定义文件清单。
- `apply` 拒绝过期、跨工作区或已使用 Token。
- 成功响应包含刷新预览所需结果。

### 10.3 UI 测试

- 上传按钮只在模板工作区出现。
- 首次为“上传项目”，成功后为“重新上传”。
- 确认弹窗展示新增、修改、删除和忽略文件。
- 存在阻断项时确认按钮不可用。
- 完成后刷新文件树和预览。
- 发布模板仍必须单独确认，不会因上传自动触发。

### 10.4 集成验证

分别使用一个 Site Vite 项目和一个 Assets Vite 项目验证：

- 首次上传；
- 修改后重新上传；
- 来源删除文件后的镜像同步；
- checkpoint 恢复；
- 本地预览；
- 模板发布；
- 从新模板版本创建应用并成功预览。

## 11. 验收标准

- 模板作者无需离开模板编辑页即可上传和重新上传本地项目。
- 上传前能看到完整的变更与风险摘要。
- 上传不会改变模板身份和 Site/Assets 类型。
- 来源项目删除的业务文件能在确认后同步删除。
- 任何覆盖失败都不会留下半完成状态。
- 上传后当前页面的代码和预览能刷新。
- 上传不会自动发布，也不会把本地路径、环境变量或凭据打入 OSS。
- 发布新版本后，新建应用能够使用更新后的模板。
