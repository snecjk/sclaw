# Site Minimal UI/UX 设计规范

## 目标

将 `resources/app-templates/site-minimal` 从包含虚构业务和零散样式的演示应用，改造成可直接承载真实业务的干净企业后台骨架。

新建 Site 应用应具备统一的视觉系统、可访问的基础交互和最少但完整的应用框架；它不应预设订单、报表、指标或任何虚构业务流程。

## 设计依据

- MasterGo《PC端白皮书》基础模板：顶部品牌区、侧栏导航、浅灰工作区、内容分区、面包屑、指标/表格页面模式。
- [内置模板主题设计系统](../../ui-ux/builtin-template-theme-design-system.md)：基础颜色、排版、间距、阴影、弹层和 Ant Design 映射。

## 方案

采用“设计系统 + 干净骨架 + 可组合页面模式”。模板分为四层：

```text
Theme Tokens
    ↓
App Shell（Header / Sider / Content）
    ↓
Page Primitives（PageHeader / PageContainer / EmptyState）
    ↓
初始页面（Home / Example）与未来业务页面
```

### 主题层

新增一个唯一的主题入口，提供：

- CSS 语义 Token：颜色、间距、文字、圆角、边框、阴影。
- Ant Design `ConfigProvider` 主题对象。
- 模板组件不直接使用品牌色、灰阶和尺寸字面量；仅可使用语义 Token 或 Ant Design Token。

颜色采用当前整理稿的候选值：品牌橙 `#F76F00`、正文 `#333333`、标题 `#1A1A1A`、页面背景 `#FAFAFA`、容器背景 `#FFFFFF`、边框 `#E8E8E8`。主按钮需通过独立的可访问操作色处理白字对比度，不能直接假设品牌橙配白字可用。

### 应用骨架

`AppLayout` 只承担页面编排，不负责路由解析、用户数据组装或业务菜单定义。

- Header：应用标识、应用标题、可选的全局操作插槽、用户菜单。
- Sider：最小导航配置；默认仅“首页”和“示例页面”。支持未来扩展为分组导航和收起态。
- Content：浅灰布局背景、响应式留白和按需使用的内容分区；不强制将每一个页面包进大白卡。
- 用户菜单仅包含账户相关的真实可用操作；无对应路由的菜单项不展示。

### 页面基础组件

| 组件 | 职责 |
| --- | --- |
| `PageHeader` | 面包屑、标题、描述、右侧操作区；不包含业务状态。 |
| `PageContainer` | 标准页面留白、内容最大宽度和纵向节奏。 |
| `ContentSection` | 按需提供白色容器、边框、标题和操作区。 |
| `EmptyState` | 空数据、未配置或尚未生成页面的统一引导。 |
| `RuntimeBootstrapShell` | 仅显示加载和启动失败，不泄露认证或请求实现细节。 |

### 初始路由和内容

默认仅保留两条路由：

- `/home`：干净的应用首页。显示面包屑、标题、说明和一个可删除的开始引导；不显示身份、Token、虚构 KPI 或伪业务数据。
- `/example`：开发示例页。放置表单、表格、标签等组件组合示例；不出现在面向最终用户的默认导航中，或作为明确标记的开发参考入口。

模板不预置“业务办理、订单、报表、个人中心、偏好设置”等业务名称或空路由。

### 页面模式

模板提供文档化的组合方式，而非预置伪数据：

- Dashboard：`PageHeader` + 可选通知 + 指标卡/图表分区。
- List：`PageHeader` + 筛选区 + 表格分区 + 分页。
- Form：`PageHeader` + 表单分区 + 固定或页面底部操作区。
- Detail：`PageHeader` + 信息分区 + 时间线/附件等可选区域。
- Empty：`PageHeader` + `EmptyState`。

仅当用户的实际业务需求需要时，AI 或开发者才创建指标、图表、筛选器和表格。

## 迁移清单

| 现有项 | 处理 |
| --- | --- |
| `TOP_NAV` 的工作台/业务办理/系统设置 | 替换为最小、可扩展的导航配置。 |
| `HomePage` 的待办/任务/完成数和 SSO 提示 | 删除，改为干净首页引导。 |
| `DemoPage` 的网络探测、伪业务数据 | 移除网络探测；保留为隔离开发示例或移至文档。 |
| `PlaceholderPage` | 以统一 `EmptyState` 替代。 |
| `AppLayout` | 拆分为 Header、Sider、Content 和导航工具。 |
| `index.css` 中硬编码视觉值 | 迁移至主题 Token 和局部语义样式。 |
| `App.tsx` 的内联主题 | 改从主题入口读取。 |

## 交互与可访问性

- 键盘焦点必须可见；不以移除 outline 的方式隐藏焦点。
- 图标按钮必须有可访问名称。
- 常规正文为 `14px`，行高至少 `1.5`；不以 `12px` 作为通用正文。
- 交互状态应有 default、hover、active、focus、disabled。
- 状态反馈不能只用颜色表达。
- 响应式规则以内容不横向溢出为底线；窄屏下 Header 信息降级，Sider 可收起。

## 非目标

- 本次不实现完整业务组件库。
- 本次不根据虚构数据制作 KPI、图表或表格首页。
- 本次不实现暗色主题。
- 本次不改变 SSO、外部服务、请求封装或发布流程。

## 验收标准

1. 新模板首页不包含虚构业务数据、Token/SSO 实现说明或不可用菜单。
2. Theme CSS 与 Ant Design 主题从同一入口维护。
3. Header、Sider、PageHeader、PageContainer、EmptyState 是独立可复用组件。
4. 示例页面与最终用户默认入口隔离。
5. Site 模板可通过类型检查和生产构建。
6. 模板相关的现有契约测试按新骨架更新并通过。
