# SClaw 最优浅色与深色主题系统设计

**日期：** 2026-08-30  
**状态：** 待书面审核  
**范围：** 主题颜色、组件视觉状态、主题同步、预览边界与视觉回归  

## 1. 背景

项目已经建立浅色、深色与跟随系统三种外观，并完成了暗色中性层级、集合卡片外壳、表格适配、独立窗口与内嵌预览同步等第一阶段工作。当前主要问题不是缺少主题能力，而是新旧实现仍然并存：语义 Token 与局部 `dark:` 工具类、共享 Recipe 与页面级 `.dark` CSS、主窗口色板与 iframe 色板同时存在。

本设计把当前已认可的视觉结果固化为基线，在不改变布局、尺寸、字体、圆角和业务行为的前提下，把主题实现收口为一套可证明、可维护、可回归的系统。

## 2. 目标

1. 当前已认可的浅色效果成为唯一冻结基线。
2. 深色使用纯中性层级，不出现蓝黑、青黑、紫黑阴影或普通表面色。
3. 浅色、深色与跟随系统覆盖主窗口、后创建窗口、Adaptive iframe 和文件预览。
4. 应用、技能、连接器、工作流等同类卡片共享同一视觉外壳与状态模型。
5. 页面不再自行定义普通中性颜色和明暗分支。
6. 迁移完成后，活跃生产 CSS 不净增长，生产源代码整体争取净减少。
7. 通过真实渲染、计算样式与截图回归证明视觉稳定，而不是仅检查源码字符串。

## 3. 非目标

- 不重新设计页面布局。
- 不调整间距、尺寸、字体、字重、圆角或图标大小。
- 不修改业务流程、数据结构或后端通信。
- 不修改依赖、Lockfile、构建配置或发布配置。
- 不强制重着色需要内容保真的图片、PDF、PPT、Word 纸张和用户文档。
- 不在主题提交中夹带运行时 Manifest、资源版本或其他无关修改。

## 4. 视觉冻结与允许变化

### 4.1 冻结原则

以用户当前已认可的浅色和深色效果为基线。迁移只改变颜色的所有权和复用方式，不改变最终计算样式。

冻结项包括：

- 页面与组件背景
- 文字与图标颜色
- 边框、阴影与透明度
- 默认、Hover、Selected、Focus、Disabled、Loading、Empty、Error 状态
- 关键页面截图和关键元素计算样式

### 4.2 允许修正的例外

只有以下已确认问题允许产生视觉变化：

- 带蓝、青、紫倾向的暗色阴影和 Glow 改为中性黑。
- 未统一的卡片、按钮、侧栏和浮层状态归一。
- 暗色下不可读的表格、文字、图标和 Adaptive 预览内容修正。
- 同类集合卡片的外壳与交互状态统一。

除例外清单外，任何截图差异都视为回归。

## 5. 主题架构

主题系统固定为四层：

```text
原始色板
  ↓
语义 Token
  ↓
组件 Recipe
  ↓
页面布局与业务状态
```

### 5.1 原始色板

原始色板只定义品牌色、功能色和中性色阶，不表达组件用途。页面和组件不得直接消费原始色板。

### 5.2 语义 Token

浅色与深色只在 `src/styles/theme/tokens.css` 映射一次。核心语义包括：

- `surface.canvas`
- `surface.panel`
- `surface.inset`
- `surface.elevated`
- `text.primary / secondary / tertiary / disabled`
- `icon.primary / secondary / tertiary / disabled`
- `border.subtle / default / strong / focus`
- `shadow.overlay`
- `focus.ring`
- `feedback.info / success / warning / danger`

深色基础映射固定为：

| 语义 | 深色值 |
| --- | --- |
| 内容画布 | `#0D0D0D` |
| 内容面板、卡片 Hover | `#181818` |
| 侧栏、内嵌面 | `#212121` |
| 浮层、选中态 | `#282828` |
| 主文字 | `#DFDFDF` |
| 次文字 | `rgba(255,255,255,.70)` |
| 弱文字 | `rgba(255,255,255,.50)` |
| 默认边框 | `rgba(255,255,255,.08)` |
| 强边框 | `rgba(255,255,255,.16)` |

暗色普通阴影只能使用中性黑。品牌色只用于品牌动作、焦点、明确状态或数据表达，不得作为普通表面光晕。

### 5.3 组件 Recipe

`src/styles/theme/recipes.css` 是跨组件视觉状态的唯一所有者。只保留以下 Recipe：

- Card
- Control
- Navigation
- Segment
- Overlay
- Feedback

Recipe 只负责颜色、边框、阴影和状态，不负责布局、尺寸、圆角和排版。

### 5.4 页面层

页面只负责：

- 布局
- 尺寸与间距
- 圆角与排版
- 业务内容和业务状态

页面不得定义普通中性十六进制色、普通暗色表面、带色阴影或重复的明暗模式组合。

## 6. 组件状态模型

所有可交互组件完整覆盖：

```text
default → hover → active/selected → focus → disabled → loading → error
```

### 6.1 卡片

| 状态 | 浅色 | 深色 |
| --- | --- | --- |
| Default | 当前白底、默认边框、无阴影 | 透明底、默认边框 |
| Hover | 当前白底、强边框、轻中性阴影 | `#181818`、强边框、无阴影 |
| Selected | 当前冻结选中底 | `#282828`、主文字与主图标 |
| Focus | 统一 Focus Ring | 同一语义 Focus Ring |
| Disabled | 专用禁用文字、图标与边框 | 对应暗色禁用语义 |
| Loading | 保留原卡片层级并增加遮罩 | 中性遮罩与 Spinner |
| Error | 错误色只表达状态 | 暗色错误弱底，不改变卡片层级 |

应用、技能、连接器和工作流使用同一集合卡片外壳。内容结构可以不同，普通背景、边框、阴影、过渡和焦点状态必须一致。

### 6.2 控件

控件统一为：

- Field：Input、Search、Textarea
- Primary：品牌主按钮
- Outline：描边按钮
- Ghost：图标按钮与低层级动作
- Segment：分段选择与页签

页面只能指定 Variant 和状态，不得重新拼接主题颜色。

### 6.3 侧边栏

- 默认项使用次文字与次图标。
- Hover 使用 Control Hover 语义。
- Selected 在深色使用 `#282828` 与主文字、主图标。
- 分区标题使用弱文字。
- Badge、运行中与错误只使用登记的功能色。

### 6.4 浮层

Dialog、Dropdown、Popover 与 Tooltip 统一使用 Overlay Recipe：

- 浅色保持当前冻结结果。
- 深色使用 `#282828`。
- 使用统一边框、纯中性黑阴影和 Scrim。
- 禁止页面自定义普通浮层底色和品牌 Glow。

### 6.5 禁用状态

禁止通过给整个组件统一添加 `opacity` 表达禁用。文字、图标、边框、表面与功能色分别使用禁用语义，避免不可预测的多层透明度和对比度下降。

## 7. 可访问性语义

视觉外壳统一后，交互语义必须可达：

- 只有一个主动作且没有子操作的卡片使用原生 `button` 或 `a`。
- 包含编辑、删除等子操作的卡片使用 `article` 加独立主操作按钮，禁止嵌套 Button。
- 所有可点击卡片支持 Tab、Enter、Space 与 `focus-visible`。
- DOM 语义调整不得改变冻结的尺寸、布局和默认视觉。

## 8. 主题同步与预览边界

### 8.1 主窗口与独立窗口

主进程持有已解析的 Appearance。主窗口、Sprite、Float 和后创建窗口必须在首屏加载前获得当前值，并在设置或系统主题变化时实时更新。

Renderer 只应用已解析结果，不建立第二套主题判断逻辑。

### 8.2 Adaptive iframe

允许适配的生成 HTML 使用 Adaptive 策略：

- 初始 HTML 写入已解析 Appearance，避免首屏闪烁。
- 运行时通过统一消息同步。
- 表格、表单、代码块、引用块和普通文字显式映射。
- iframe 复用同一份主题 Token CSS，不复制另一套颜色数字。

### 8.3 Fidelity 内容

图片、PDF、PPT、Word 纸张和用户文档使用 Fidelity 策略，不反色、不重写内容颜色。若 Word 高保真渲染不可用，降级预览仍保持纸张语义，不随宿主暗色重着色正文。

## 9. 迁移顺序

### 批次 0：隔离范围

- 将主题改动与运行时 Manifest、资源版本和其他无关文件分开。
- 删除备份 CSS、临时文件和无消费者配方。
- 每个批次独立提交、独立验证、可以单独回滚。

### 批次 1：冻结基线

- 采集浅色、深色和跟随系统的关键页面截图。
- 记录关键元素计算样式。
- 建立允许变化的例外清单。

### 批次 2：收口 Token

- 整理原始色板与语义映射。
- 清除竞争语义和重复别名。
- 迁移期兼容别名必须登记，并在最终批次删除。
- 让 Adaptive iframe 复用同一 Token 源。

### 批次 3：补全 Recipe

- 完成 Card、Control、Navigation、Segment、Overlay 与 Feedback 的全部状态。
- 页面不得重新定义 Recipe 已覆盖的颜色。

### 批次 4：按业务域迁移

1. 基础 UI、App Shell 与侧边栏
2. 应用、技能与连接器卡片
3. 定时任务与工作流卡片
4. 对话、思考、工具调用与 Composer
5. 表格、代码块、Toast 与浮层
6. 设置、模型、Agent 与 Setup
7. Adaptive iframe、Sprite、Float 与文件预览

每迁移一个业务域，同时删除其局部 `dark:`、页面 `.dark`、重复中性色和被替代的颜色组合。

### 批次 5：无视觉变化的语义修复

- 修复卡片键盘访问和主操作语义。
- 验证 DOM 调整没有产生视觉与布局差异。

### 批次 6：最终清场

- 删除临时别名和永久兼容层。
- 删除页面级普通中性明暗分支。
- 删除第二套 iframe 色板和无消费者样式。
- 更新 Rules，使其描述实际完成状态而非目标状态。

## 10. 测试与验收矩阵

验收覆盖：

```text
3 种主题
× 8 类界面
× 7 种状态
× 4 个运行环境
```

### 10.1 主题

- Light
- Dark
- System，包括运行时系统主题切换

### 10.2 界面

- 首页与对话
- 侧边栏
- 应用、技能与连接器
- 定时任务与工作流
- 设置、模型与 Agent
- Dialog、Dropdown、Popover 与 Tooltip
- 表格、代码块与 Feedback
- 文件预览与内嵌内容

### 10.3 状态

- Default
- Hover
- Selected
- Focus
- Disabled
- Loading / Empty
- Error

### 10.4 环境

- 主窗口
- 后创建独立窗口
- Adaptive iframe
- Fidelity 内容

### 10.5 验证层级

1. **Token 契约测试：** 唯一所有权、浅深映射和允许例外。
2. **源码审计：** 同时扫描 TS、TSX、CSS 与 SVG，覆盖 Hex、RGB、HSL、阴影和主题选择器。
3. **组件行为测试：** 验证状态、键盘操作和 Appearance 切换。
4. **计算样式测试：** 验证最终渲染值，而非仅匹配源码字符串。
5. **Electron 截图回归：** 在真实窗口环境验证页面、浮层、独立窗口和预览。

## 11. 代码预算

- 活跃生产 CSS 最终净增长必须小于等于 0。
- 活跃生产源代码整体争取净减少。
- 不得把删除旧备份 CSS 计入生产代码优化成果。
- 新增共享 Recipe 时，必须同步删除至少等量的局部实现。
- 测试、截图基线和规范文档单独统计，不计入生产代码预算。
- 每个迁移批次输出 Numstat，防止新旧体系长期并存。

## 12. 完成定义

只有同时满足以下条件，主题系统才算完成：

1. 浅色冻结区域无未经批准的视觉变化。
2. 深色普通表面和阴影全部为中性。
3. 页面级普通中性 `dark:` 分支为 0。
4. 页面级普通 `.dark` 样式为 0。
5. iframe 不复制主题色值。
6. 所有交互组件具有完整状态并支持键盘访问。
7. 活跃生产 CSS 净增长小于等于 0。
8. 无备份样式、无永久兼容别名、无无消费者配方。
9. 主题契约、行为、计算样式、Electron 截图、类型检查和构建验证通过。
10. 无关 Manifest、资源和工程配置变更不进入主题提交。

## 13. 风险与控制

| 风险 | 控制方式 |
| --- | --- |
| 浅色被语义迁移连带改变 | 先冻结截图与计算样式，每批对比 |
| 新旧主题长期并存 | 每批要求“新增一处、删除一处”并设置代码预算 |
| iframe 与主应用颜色漂移 | 复用同一 Token CSS，不复制数字 |
| 卡片 DOM 修复引发布局变化 | 语义修复单独成批，并执行像素回归 |
| 源码测试绿但视觉错误 | 增加计算样式与 Electron 截图测试 |
| 无关变更污染主题提交 | 批次 0 隔离范围，提交前检查文件清单 |

## 14. 已确认决策

- 以当前已认可的浅色效果作为冻结基线。
- 采用契约优先、逐域迁移，不推倒重写。
- 除明确问题区域外，浅色与深色视觉保持不变。
- 允许无视觉变化的可访问性语义修复。
- 最终以可证明的真实渲染结果和代码收口作为完成标准。
