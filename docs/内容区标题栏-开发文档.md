## 0. 目标

把内容区头部从"对话工具栏（引擎/模型/搜索/刷新/思考）"换成一条 **52px 全局标题栏**：
- **样式**与内容区白卡片容器一致（同底色/圆角衔接，见 §3），形态参考图一。
- **左**：聊天标题（取值口径同侧栏历史记录）。
- **右**（从右到左）：**预览 → 深度思考开关 → 刷新 → 搜索**，纯 icon。
- 移除原头部 **引擎 / 模型** 选择器——它们**已在输入框内实现**（`composerLayout="home"` + `toolbarInlineSelectors`，见 §4.3），Chat 改用同款即可。
- 52px 区域**可拖动窗口 + 双击最大化**；其下全部为内容信息区。
- **全局通用**：这是所有页面内容区共用的头部框架，Chat 是第一个接入方。

**不改**：刷新（`refresh`）、深度思考（`showThinking`/`toggleThinking`）、搜索（`ChatSearchBar`）、预览（`useChatPreviewPanel`）各自逻辑，只换"入口位置"。

## 1. 绝对铁律

1. **范围 = 本任务列出的组件**（见 §2）；侧栏、对话流消息体、预览区内部本轮不碰。
2. **不改功能/逻辑**：上述四个动作的 store 调用与行为、引擎/模型选择逻辑——不动；只搬位置 / 换布局。
3. **样式按设计稿改**；**精确值（高度 52 已定、内距/字号/icon 尺寸/间距/颜色）以 MasterGo MCP 为准**（见 §3），找不到 token 不要造，列出来问。
4. **写法遵守 02-styles**：Tailwind + `cn()`；禁止 inline 视觉值、模板字符串拼 className、无注释裸 hex；`dark:` 与 `var(--sto-...)` token 原样保留。
5. **横切统一 token + 品牌色**：品牌色 `#FF6700` / `var(--sto-brand-6)`，不引入 `#FF6F00`。
6. **Electron drag 规则**：52px 容器加 `.drag-region`，**所有可点元素（标题除外的按钮）必须 `.no-drag`**，否则点击被窗口拖拽吞掉。
7. **两阶段**：先按 §6 阶段一交「方案 + 现状分析」，**等用户确认后**再写码。遇到 🟥 停下来问。

## 4. 实现

### 4.1 新增可复用 `ContentHeader`（52px，全局框架）

一个**与白卡片同款样式**、固定 **52px**、`shrink-0` 的横条，作为内容区顶部框架；其下为内容信息区。Props：
- `title: ReactNode`（左）、`actions?: ReactNode`（右，从右到左排列）。
- 自带：`.drag-region` 拖动窗口 + `onDoubleClick` → `invokeIpc('window:maximize')`；左留白随侧栏收起态变化（§4.4）。
- 内部所有按钮容器加 `.no-drag`。

**挂载策略 ✅ 已确认**：挂在 `MainLayout` 省区白卡片**顶部**（`stoMainCardShellClass` 区域之上、`<Outlet/>` 之上），作为全局框架；各页通过**轻量 layout 槽 / context** 注入自己的 `title` 与 `actions`，**未注入的页面给默认**（页面名作标题、无右侧操作）。Chat 为首个接入方。
- 建议用一个 `ContentHeaderContext`（或 zustand 轻量 store）让当前路由页 set `title`/`actions`，`ContentHeader` 读取渲染；页面卸载时清空。

### 4.2 Chat 接入：标题 + 四个 action

去掉 `index.tsx` L459–481 的 `ChatToolbar` 块，改由 `ContentHeader` 承载：
- **标题（左）**：当前会话标题，**取值口径同侧栏历史记录**——复用 `getSessionLabel` 的解析（建议把它抽成共享 util，如 `lib/session-label.ts`，侧栏与标题栏共用；或直接调用同一函数）。数据用 Chat 现有 `currentSession` / `currentSessionKey`。
- **右侧 action（从右到左）**：
  1. **预览**：点击 = 现有 `setShowPreviewPanel(true)`（对应 index.tsx L694–706 浮动钮逻辑）；**`canShowPreviewPanel` 为 false（无产物）时此 icon 隐藏**。✅
  2. **深度思考开关**：`showThinking` / `toggleThinking`（激活态高亮，沿用 `ChatToolbar` 现写法）。
  3. **刷新**：`refresh()`，`loading` 时禁用 + 转圈（沿用现写法）。
  4. **搜索**：触发现有 `ChatSearchBar`（现挂在 toolbar 的 `trailingContent`）——搜索 icon 放进标题栏右侧；**点开后输入框向左延伸**（icon 位置不动，搜索框从该 icon 处向左展开，叠在标题栏内）。✅
- 原"预览产物"浮动钮（L694–706）与新标题栏预览 icon **二选一**：保留标题栏的，浮动钮条件隐藏 + 注释。

### 4.3 引擎/模型移入输入框（复用现成实现）

Chat 的 `<ChatInput>`（`index.tsx` L623–635）改为与 `HomeComposer` 同款：
```
composerLayout="home"
toolbarInlineSelectors={<><ChatEngineSelector variant="inline" /><ChatModelSelector variant="inline" /></>}
```
原 `ChatToolbar` 里的 `ChatEngineSelector`/`ChatModelSelector` 随 toolbar 一起移除。**引擎/模型逻辑不改**，只是渲染位置从头部 → 输入框内（代码已支持）。

### 4.4 拖拽 / 双击 / 收起态左留白（避让红绿灯）

- **拖动 + 双击 ✅**：标题栏根容器加 `.drag-region`，**行为与左侧侧栏顶部 `SidebarProvincialChromeRow` 完全一致**——后者就是个纯 `.drag-region`（无自定义 `onDoubleClick`），双击最大化由系统对拖拽区的处理负责。**因此本标题栏也不加自定义 `onDoubleClick`**，只靠 `.drag-region` 保持一致；按钮/可点区一律 `.no-drag`。
- **收起态左留白 + 展开钮归属 ✅**：
  - 侧栏**展开**时：红绿灯 + 收起钮在侧栏列顶（`SidebarProvincialChromeRow`），内容卡在其右侧 → 标题栏左留白用常规内距，左侧只有标题。
  - 侧栏**收起**时：内容卡顶到左边缘 → 标题栏左侧**从左到右依次为：红绿灯留白 → 展开/收起钮（`SidebarHeaderToggle`）→ 标题**。即把展开钮**搬进标题栏左侧**（收起态显示），红绿灯区留白（macOS 参考 `pl-20`）避免重叠。
  - 据 `useSettingsStore().sidebarCollapsed` 切换：收起 → 渲染 `SidebarHeaderToggle(isCollapsed)` + 红绿灯留白；展开 → 不渲染（钮在侧栏）。平台差异按 `window.electron?.platform`。
- **改动 `app-shell-chrome-overlay.tsx` ✅**：既然收起态展开钮移入标题栏，原 `CollapsedSidebarExpandOverlay`（`z-40` 浮层）**条件隐藏/移除**，避免重复；Win 控件浮层部分按需保留。（已确认可动该文件）

## 决策（已确认 ✅）

1. **挂载策略** → `ContentHeader` 全局挂 `MainLayout` 主卡片顶部 + 各页通过 context/槽注入 title/actions。
2. **搜索展开形态** → 搜索框从右侧 icon 处**向左延伸**展开，叠在标题栏内。
3. **收起态展开钮 + 左序** → 展开钮移入标题栏左侧；收起态左→右为 **红绿灯 → 展开/收起钮 → 标题**；原 `CollapsedSidebarExpandOverlay` 移除（**允许动 `app-shell-chrome-overlay.tsx`**）。
4. **双击行为** → 与左侧侧栏顶部一致：仅 `.drag-region`，不加自定义 onDoubleClick，双击最大化由系统处理。
5. **其他页面**（未明确答复，取默认）→ 本轮只接 Chat，其余页面默认显示页面名、无右侧操作；如需调整再说。
