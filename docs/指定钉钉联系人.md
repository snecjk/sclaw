# 指定钉钉联系人 — 创建与发送流程梳理

> 项目根目录：`sto-claw`
> 整理日期：2026-07-09
> 聚焦范围：仅两部分
>   1. **MyTask 定时任务创建** — 指定钉钉收件人（收件人输入框选人 / 描述里自然语言指定）
>   2. **Chat 页面发送** — 在聊天框通过 `@` 或自然语言提及，把信息发给钉钉联系人

---

## 共用底座（两流程都依赖）

**收件人数据结构** `DingTalkMention`（`shared/dingtalk-mention.ts:1-7`）：user 带 `userId`，group 带 `openConversationId`，均有 `corpId`、`displayName`。

**选人 UI**：`DingTalkRecipientField`（MyTask 用）/ `DingTalkMentionEditor`（Chat 用），底层都靠 `useDingTalkMention` 搜人 + `mentionSearchItemToMention`（`src/types/dingtalk-mention.ts:13-28`）把搜索项转成 `DingTalkMention`。

**结构化收件人块格式** `buildDingTalkMentionSystemContext`（`shared/dingtalk-mention-context.ts:182-235`）：
```
[STOCLAW:DINGTALK_RECIPIENTS:v1]        ← marker（shared/dingtalk-mention.ts:9）
```json
{ "version":1, "source":"stoclaw-input-mention", "recipients":[ {type,displayName,userId/openConversationId,corpId} ... ] }
```
## StoClaw DingTalk Recipients
（11 条发送规范：必须用 dws chat message send、收件人参数取自 JSON、--title 必填、正文末尾代发说明、20s/条限流…）
```
注入入口 `prepareDingTalkAgentTurnMessage`（`shared/dingtalk-recipient-message.ts:26-35`）→ `appendDingTalkMentionContext`（`dingtalk-mention-context.ts:241-258`），把上述块拼在用户原文前。

**agent 侧发送工具**：`dws chat message send --user <userId>`（单聊）/ `--group <openConversationId>`（群聊），由 agent 经 exec/bash 执行 dws CLI。`sto-dingtalk-send-guard` 插件做限流（20s/条）、批量拦截、`--text` 格式校验。

**关键规则来源**（运行时注入给 agent 的上下文 `resources/context/TOOLS.stoclaw.md` / `CLAUDE.md` §钉钉 dws）：
- ✅ **允许** `dws contact user search`、`dws chat search` 等只读通讯录查询——"无结构化块时，搜人、查群属于正常 dws 业务用法"（`TOOLS.stoclaw.md:61`）
- ⛔ 当消息**含** `[STOCLAW:DINGTALK_RECIPIENTS]` 块时：**必须**用块内 `userId`/`openConversationId` 发送，**禁止**对块内收件人再 `contact user search`（`TOOLS.stoclaw.md:63-66`）
- 即：**有块→直接用块内 ID（禁止搜人）；无块→允许 agent 自行 `dws contact user search` 按名字解析**

## 一、MyTask 定时任务创建 — 指定钉钉收件人

### 1.1 入口与弹窗

`src/pages/MyTask/index.tsx` 「新建任务」按钮 → `src/pages/MyTask/components/TaskCreateModal.tsx`。弹窗内：
- **描述框** `instructions` state（`TaskCreateModal.tsx:158`）
- **收件人框** `recipients` state，`DingTalkMention[]`（`TaskCreateModal.tsx:162`），渲染 `<DingTalkRecipientField>`（`:11` import、`:478` 渲染）

### 1.2 两种指定方式

#### 方式 A：收件人输入框选人（结构化，前端录入）

```
DingTalkRecipientField.tsx:65-71  applyDingTalkMention → mentionSearchItemToMention
DingTalkRecipientField.tsx:73-77  onSnapshotChange → setRecipients
TaskCreateModal.tsx:162           recipients state
TaskCreateModal.tsx:251-261       handleSubmit → onSave({ ..., message, dingTalkMentions: recipients.length?recipients:undefined })
                                  ↑ 收件人字段名 dingTalkMentions（:256）
```
选人产出带 `userId`/`openConversationId` 的 `DingTalkMention[]`，提交时作为 `dingTalkMentions` 字段。

#### 方式 B：描述里自然语言指定（"每天9点把周报发送给钉钉联系人姚磊"）

- 前端**不解析**人名：`TaskCreateModal.tsx:253` `message: instructions.trim()` 原样提交，描述里的"姚磊"不会变成结构化收件人，`dingTalkMentions` 为空。
- **执行期由 agent 解析**：任务触发时，执行 agent（`electron/services/claude-task-worker.ts`，dws 在 PATH、能跑 bash）读到描述里"姚磊"，因**无结构化块**，按 `CLAUDE.md` 规则调 `dws contact user search "姚磊"` 把名字解析成 `userId`，再 `dws chat message send --user <userId>` 发送。**能正确发送。**

### 1.3 持久化分叉（按引擎）

`src/pages/MyTask/index.tsx:325-424` `handleSave`：

| | claude 引擎 | openclaw 引擎 |
|---|---|---|
| 收件人处理 | `prepareDingTalkAgentTurnMessage(message, mentions)` 编码进 `promptTemplate`（创建 `:373-376` / 编辑 `:335-338`） | `message`（原文）+ `dingTalkMentions`（独立字段）分存（创建 `:390-401` / 编辑 `:354-365`） |
| 后端 | `POST /api/claude-scheduled-tasks`（`src/stores/cron.ts:188-191`） | `POST /api/cron/jobs`（`cron.ts:196-199`） |
| payload 含 dingTalkMentions? | ❌ 只活在 promptTemplate 字符串里 | ✅ 独立字段（`src/types/cron.ts:65`） |
| 编辑态同理 | `PUT /api/claude-scheduled-tasks/{id}`（`cron.ts:225-228`） | `PUT /api/cron/jobs/{id}`（`cron.ts:238-241`） |

- **claude**：收件人注入成 `[STOCLAW:DINGTALK_RECIPIENTS]` 块塞进 `promptTemplate`；执行期 `claude-task-worker.ts:101` 把 `promptTemplate` 当 user prompt，`claude-runtime-extensions.ts:111` 叠加执行 system prompt。
- **openclaw**：收件人独立存 `dingTalkMentions`，由后端在触发时注入。

### 1.4 编辑态回填

`TaskCreateModal.tsx:78/87` `resolveScheduledTaskMentions(job.promptTemplate || job.message)` → `src/lib/scheduled-task-recipients.ts:74-81` → `parseMentionsFromRecipientContext`（`:10-53`）从 `[STOCLAW:DINGTALK_RECIPIENTS]` 后的 ```json 块还原 `DingTalkMention[]`；无块则退回旧字段 `dingdingId/dingdingGroupId`。

### 1.5 执行期发送行为（方式 A vs B 的差异）

执行 system prompt `SCHEDULED_TASK_EXECUTION_SYSTEM_PROMPT`（`shared/scheduled-task-instruction.ts:18`）核心规则：

> **若 message 含 StoClaw DingTalk Recipients JSON，必须将执行结果通过 `dws chat message send` 发给 JSON 中所有收件人（P0 强制）；禁止发送前询问确认、禁止 `--dry-run`。**

| | 方式 A（收件人框选人） | 方式 B（描述自然语言） |
|---|---|---|
| promptTemplate/message 含块? | ✅ 含（claude 注入；openclaw 后端触发时注入） | ❌ 不含 |
| 发送是否强制 | ✅ P0 强制发送 | ❌ 非强制，依赖 agent 对描述语义的理解（通常仍会搜人发送） |
| 收件人 ID 来源 | 块内 `userId`（禁止再 search） | agent 调 `dws contact user search` 解析 |
| watchdog 兜底补发 | ✅ `claude-task-workflow-watchdog.ts:276` `parseDingTalkRecipientsFromText` 能从块还原收件人 | ❌ 兜底拿不到（无块，纯名字无法还原） |

> 即：**方式 A 的发送是系统强制的、对象锁定的；方式 B 的发送是 agent 自主按语义执行的**。两者最终都能经 dws 正确发出，但可靠性路径不同。

### 1.6 调用链总览

```
TaskCreateModal.tsx:478  <DingTalkRecipientField value={recipients} onChange={setRecipients}>
TaskCreateModal.tsx:251-261  handleSubmit → onSave({ name, message, schedule, dingTalkMentions: recipients, ... })
src/pages/MyTask/index.tsx:325-424  handleSave
  ├─ claude:  prepareDingTalkAgentTurnMessage(message, mentions) → promptTemplate 含 [STOCLAW:DINGTALK_RECIPIENTS] 块
  │           cron.ts:188-191  POST /api/claude-scheduled-tasks { ..., promptTemplate }
  │           执行期: claude-task-worker.ts:101 prompt=promptTemplate
  │                   claude-runtime-extensions.ts:111 注入 SCHEDULED_TASK_EXECUTION_SYSTEM_PROMPT
  │                   → agent 读块 → dws chat message send --user <块内userId>（P0 强制）
  └─ openclaw: message(原文) + dingTalkMentions(独立字段)
              cron.ts:196-199  POST /api/cron/jobs { ..., message, dingTalkMentions }
              执行期: 后端触发时注入块 → agent 同上

【方式 B（描述自然语言，无块）】
  描述原文 → promptTemplate/message（无收件人块）
  执行期 agent 读到"发送给姚磊" → 无块 → dws contact user search "姚磊" → userId
                                   → dws chat message send --user <userId>（agent 自主，非系统强制）
```

## 二、Chat 页面发送 — @ / 自然语言提及

Chat 与 Home 共用发送管线（`dispatchChatSend` / `sendMessage` / `buildDingTalkMentionRpcExtras` / `preprocessChatSendParams`）。两条触发路径的差异在「收件人有无已解析 ID」。

### 2.1 共用发送管线（@ 与自然语言都走前半段）

```
ChatInput.handleSend (ChatInput.tsx:515)        ← 读取 snapshot.mentions
 → Chat.handleSend (index.tsx:332)              [有@时 :351 skipQuestionSplit=true]
 → dispatchChatSend (dispatch-chat-send.ts:27)   透传 dingTalkMentions
 → sendMessage (runtime-send-actions.ts:101)
 → buildDingTalkMentionRpcExtras (dingtalk-mention-context.ts:271)   仅当有 resolved 收件人才产出 extras
 → POST /api/chat/send  deliver:false  ...dingTalkRpcExtras  (runtime-send-actions.ts:330)
 → preprocessChatSendParams (electron/utils/dingtalk-mention-send.ts:56)
     :79-81  删除 extras 根字段（Gateway schema 拒未知字段）
     :84-87  prepareDingTalkAgentTurnMessage → 注入 [STOCLAW:DINGTALK_RECIPIENTS] 块进 message（仅有收件人时）
     :88-91  writeDingTalkMentionPending 写 pending 缓存
 → adapter.sendMessage (gateway.ts:163)         message 已含块（或有）
 → 插件 before_prompt_build (sto-dingtalk-send-guard/index.ts:34)
     readDingTalkMentionPending → appendSystemContext（双保险，把块+规范也进 system context）
```

`deliver:false` 表示不直接投递 IM，由 Gateway 转 agent 处理。

### 2.2 两条触发路径

#### 路径 A：手动 `@` 选人 → agent 自动发送

输入框 `DingTalkMentionEditor`（`ChatInput.tsx:806-821`）+ `DingTalkMentionPopover`（`:786-805`），`applyDingTalkMention`（`:360-379`）选人 → snapshot.mentions 带 `userId` → 经 2.1 管线注入块 → agent 读块内 `userId`，按规则**禁止再 search**，直接：

```
dws chat message send --user <块内userId> --title "..." --text "..." --format json
 → 插件 before_tool_call (index.ts:67) evaluateDingTalkSendGuard（限流/批量/格式校验）+ fixDwsChatMessageSendToolParamsForOpenClawExec
 → dws CLI 真正发出
 → extractDingTalkSentPreviews (dingtalk-sent-display.ts:389) → DingTalkSentPreview.tsx 卡片回显
```

#### 路径 B：自然语言提及（"把上周销售额发给姚磊"，无 @）

- `mentions` 为空 → `buildDingTalkMentionRpcExtras` 返回 `undefined`（`dingtalk-mention-context.ts:275`）→ `preprocessChatSendParams` 跳过注入（`:83` 条件不满足）→ message 原样进 Gateway。
- 插件 `before_prompt_build`（`index.ts:39`）**无条件**追加 `DINGTALK_SHARE_TOOL_PROMPT`（`share-to-dingtalk.ts:12-18`）。
- agent 从语义解析"发给姚磊" + **无结构化块** → 按 `CLAUDE.md` 规则调 `dws contact user search "姚磊"` 解析 `userId` → `dws chat message send --user <userId>`。**能正确发送。**

> ⚠️ `share_to_dingtalk`（唤起 PC 选人窗）**仅**在用户明确要"自行选人发送"（"分享到钉钉""发给同事选一下"）且无块时才用（`TOOLS.stoclaw.md:72`）；普通自然语言人名提及**不走**它，而是 agent 自行 `dws contact user search` + `dws chat message send` 直接发送。

### 2.3 回显与展示剥除

- **发送卡片**：`AssistantTurnMessage.tsx:360-367` `extractDingTalkSentPreviews`（`dingtalk-sent-display.ts:389-435`）遍历 turn 内 `dws chat message send` 的 `tool_use`/`tool_result`，仅当 `isSuccessfulDwsToolResult`（`:329-342`）才生成 preview → `DingTalkSentPreview.tsx:22-76` 渲染收件人 tag + 标题 + 正文 + 代发说明。出现在 `AssistantTurnMessage.tsx:497-498`（主回复区）/ `:539-543`（仅 preview 时）。
- **剥重复正文**：`AssistantTurnMessage.tsx:371-383` `stripEchoedDingTalkSentBodiesFromAssistantReply`，避免 preview 与 assistant 回复双重展示。
- **剥用户消息注入块**：`message-utils.ts:78` `stripDingTalkMentionContextForDisplay`、`:266` `stripDingTalkAgentSendDisclaimerForDisplay`，展示时去掉 `[STOCLAW:DINGTALK_RECIPIENTS]` 块。
- **路径 B 的 share_to_dingtalk**：返回 `dingtalk_share_picker_opened` 信封（`share-to-dingtalk.ts:87-92`）→ `builtin-tool-dispatch.ts:183-186` → `toast.success`，不走 DingTalkSentPreview 卡片。

### 2.4 Chat 页特有 / 与 Home 的差异

- `DingTalkSentPreview` 卡片为 Chat 页特有渲染（Home 无）。
- `Chat/index.tsx:57` `useBuiltinToolListener()` **未传 `onScheduledTaskConfirmation`** → Chat 页收到定时任务确认信封不弹窗（handler 为 undefined，`builtin-tool-dispatch.ts:188-197` 不处理）。

### 2.5 调用链总览

```
【路径 A：手动 @】
ChatInput.handleSend (ChatInput.tsx:515)  mentions=snapshot.mentions（带 userId）
 → Chat.handleSend (index.tsx:332) [skipQuestionSplit=true]
 → dispatchChatSend → sendMessage → buildDingTalkMentionRpcExtras（编码 extras）
 → POST /api/chat/send deliver:false ...dingTalkRpcExtras
 → preprocessChatSendParams :84 注入收件人块进 message；:88 writePending
 → 插件 before_prompt_build readPending → appendSystemContext
 → agent 读块 userId（禁止 search）→ dws chat message send --user <userId>
 → 插件 before_tool_call 限流/批量/格式校验 → dws 发出
 → DingTalkSentPreview 卡片回显

【路径 B：自然语言提及】
ChatInput.handleSend  mentions=undefined
 → dispatchChatSend → sendMessage（dingTalkRpcExtras=undefined）
 → POST /api/chat/send deliver:false（无 extras）
 → preprocessChatSendParams :83 跳过注入，message 原样
 → 插件 before_prompt_build 无条件追加 DINGTALK_SHARE_TOOL_PROMPT
 → agent 语义解析"发给姚磊" + 无块 → dws contact user search "姚磊" → userId
 → dws chat message send --user <userId> → dws 发出 → DingTalkSentPreview 卡片回显
   （仅当用户要 picker 选人时才走 share_to_dingtalk → toast 提示）
```

## 两流程方式对照

| 维度 | MyTask 收件人框选人 | MyTask 描述自然语言 | Chat `@` 选人 | Chat 自然语言提及 |
|---|---|---|---|---|
| 前端结构化收件人 | ✅ `dingTalkMentions` | ❌ 仅描述原文 | ✅ `dingTalkMentions` | ❌ 无 |
| 注入 `[STOCLAW:DINGTALK_RECIPIENTS]` 块 | ✅（claude 编码进 promptTemplate；openclaw 触发时注入） | ❌ | ✅（preprocessChatSendParams 注入 message） | ❌ |
| 收件人 ID 来源 | 块内 `userId` | agent `dws contact user search` 解析 | 块内 `userId` | agent `dws contact user search` 解析 |
| 发送是否系统强制 | ✅ P0 强制（执行 system prompt） | ❌ agent 自主按语义 | ❌ agent 按块规则发（禁止 search） | ❌ agent 自主按语义 |
| 兜底补发 | ✅ watchdog 可还原块 | ❌ 无块无法还原 | —（实时对话） | —（实时对话） |
| 最终发送工具 | `dws chat message send` | `dws chat message send` | `dws chat message send` | `dws chat message send` |
| 能否正确发送 | ✅ | ✅ | ✅ | ✅ |
