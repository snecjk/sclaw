# 变更检查点

## 规则

1. 完成一轮会改文件的任务后，提醒用户（或通过工作台）保存检查点
2. 检查点说明用业务语言：「改了列表筛选」「修了空状态文案」，避免堆砌 git 术语
3. 若改坏了，引导使用工作台「恢复上一版」，而不是让用户手动 revert
4. 无文件变更则不要空提交

## 与 OpenSpec 的关系

若当前 change 仍在 proposal/design 阶段且尚未改业务代码，可不建代码检查点；进入 apply 并改文件后再建。
