# Conclusion Layer —— 报告类「结论先行」层怎么构建

> 铁律在 SKILL.md 文末。这里是 SKILL.md 第 0 步②「报告类 → 结论先行」的**完整规则**(主文件只留原则,细节在此)。
> 适用:日报 / 周报 / 复盘 / 分析 / 汇报。**非报告类**(监控看板 / 产品页 / 对比 / 清单 / 落地页)不强求结论先行,按内容自行判定结构。

核心:报告类**顶部先给一段能三秒读懂大局的"核心结论"**,支撑明细放结论之后。下面是把这一层做对、做客观、不重复的全部规则。

> **★铁规(owner 2026-06-18):头部核心结论永远是一张「有底色的结论卡」,不是裸排在灰底页面上的普通段落文字。** 无论它是几条要点、还是源自带的**一段叙述总结**(如「昨日整体运行平稳,累计收入…需重点关注…」),都必须包进一个**有底色的卡容器**——默认淡橙底诊断卡 `.sto-diag`(有风险/提醒语气)/ 纯中性说明用灰底 `.sto-diag--gray`/ 白卡浮灰底 + 细描边亦可。**绝不允许把这段结论当普通正文段落直接铺在灰底 `--bg` 上(无任何卡容器)。** 可检验失败定义:**头部出现"核心结论/核心发现/核心观点/AI 总结/结论"内容,但它没有任何底色卡容器(`.sto-diag`/`.diag`/`.verdict`/白卡)、是裸段落直接落在页底灰上 = 违规。**

---

## 1. 结论层的可视化不做限制(v4 放开)
结论可以是纯判断文字,也可以**配大数值、配图表、做聚焦卡**——怎么呈现最能让人三秒抓住大局,就怎么来。v3 曾要求"结论只给判断、不复述数字、不立 hero",**v4 取消这些限制**:若一个核心指标值得在结论处放大成聚焦卡/大数值,就放大;若几条发现配上迷你图更清楚,就配。

**放开的是"表现力",不是"客观性"。** 保留两条客观底线:
- **① 不只报喜。** 结论必须正负、缺失如实并列,禁只挑正向数据当头条(见下 §6)。
- **② 同一数据全文最多 2 次,必须跨层:结论 1 次 + 明细 1 次。** 结论处放大某指标(判断/配图/大数值/聚焦卡)是它的**结论那 1 次**,明细层再给 1 次完整数据 = 共 2 次,正常。**禁止超过**:同一指标在结论 + 卡 + 表都出现(≥3 次)、或在明细层内既进卡又进表、或做成两个数字相同的重复模块 = 违规。(见地板「同一数据全文最多 2 次」)

---

## 2. 优先用数据源自己的结论,别自造分析
很多报告源数据**本身就带一段"核心观点/结论"**(如"一、核心观点&结论:…")——**直接客观地呈现它**(原文要点清楚排版),不要自己再去算一套分类计数、不要二次编排成你以为的样子。**你自算的分类(如"13 达标/13 未达")有算错和带入主观的风险,且属于"过多编排"。** 只有源**没有**结论段时,才由你做一段中性综述。

---

## 3. ★结论层是"单一合并块",不并列多个总结(相关性合并)
凡是"对今天/本期下判断"的内容——源自带的 **AI 总结 / 核心观点**、你按"结论先行"要做的**核心发现**、顶部的**今日概览/KPI 行**——它们**职能相同(都在概括大局),必须合并成一个结论模块,不能三个总结块并列堆在页顶**(实测高频翻车:核心发现 + AI 总结 + 今日概览三块各放一遍同一批数)。

- **源已有 AI 总结时:它就是结论层**——把它作为结论正文客观呈现,**别再另造一个并列的"核心发现"块**(两个总结打架)。要强调的关键值/状态从这段总结里挑出来放大即可(v4 允许),不另起炉灶。**⚠ "作为结论正文呈现" ≠ "裸排成灰底上的普通段落":这段 AI 总结仍必须包进上面那张有底色的结论卡(`.sto-diag` 淡橙底 / 灰底 / 白卡),关键值标语义色。owner 实测翻车(2026-06-18):一段叙述型 AI 总结被直接当 `<p>` 铺在灰底页上、没有任何卡容器 = 违规。**
- **"今日概览/KPI 概览"不得复述结论已给的数**:结论里已说过的指标(异常数、占比、涉及金额…),概览**不再重复一遍**;概览只保留**结论没提到的其余指标**。若概览指标已被结论全覆盖,**整个概览块删掉**(并入结论),别为"凑一个 KPI 行"把同一批数再排一次。
- **合并 ≠ 剔除数据**:这是"相关性去重",不是删数。AI 总结的信息并进结论、概览的独有指标保留——**信息一个不少,只是不再三处重复**(与地板「不漏」一致;违反的是「同一数据 ≤2 次」)。
- 可检验失败定义:**①页顶同时存在"核心发现/结论"+"AI 总结"两个职能重复的总结块 = 违规(应合并为一);②"今日概览/KPI"的指标已在结论块出现、又原样排了一遍 = 违规(同一数据 >2 次、未跨层)。**

---

## 4. 推荐结论排版:尊重原数据 + 有重点强调

### ★先按"有效结论条数"选呈现形式(锁硬规格)
先把弱结论合并/下沉,数清**真正有效的核心结论有几条**,据此选形式:
- **≤ 3 条 → 优先文本式(诊断提醒卡片样式)**:一个淡橙底容器 + 带点序号列表,每条「**子标题加粗** + 结论文 + 关键值标红/语义色」(直接套 sto-components.html 的 `.sto-diag`,见诊断卡)。少量结论用卡片网格会显得空、每卡留白浪费;文本式更紧凑、读起来连贯,且自带"提醒"语气,适合 1–3 条。**无强调语义的纯说明**用 `.sto-diag--gray` 灰底。
- **> 3 条 → 用卡片式**:每条做独立卡片、`grid` 并列(状态 + 关键值,见下方"默认卡片化" + §7 金标准 3 卡同款)。结论多时卡片的"各自边界 + 一致位置"更便于并列扫读、区分状态。
- 判断的是**有效结论数**,不是硬把弱发现凑成卡或拆成多条。拿不准 → 3 条上下两可时,有明确状态/大数值差异用卡、偏叙述/提醒口吻用诊断文本式。
- 可检验失败定义:**只有 1–2 条结论却硬铺成一排大卡(空、留白浪费)= 违规;>3 条强结论挤进一个诊断文本块、读不出各自状态量级 = 违规。**

### 卡片式(>3 条)的具体装法:尊重原数据 + 有重点强调
每条发现包含:**语义状态标签(达标绿/关注橙/未达红/缺失灰)+ 同色标识** · **结论原文,关键数字/状态加粗并按语义上色** · **该条对应的一个大数值 + 小标签(语义色)**。既忠实源结论文字、又一眼看出每条的状态和量级。头部可带"日期 · N 项关键发现"。**强调 ≠ 改写**:措辞用源的,只把关键值突出、状态标出,不添油加醋。

**★默认卡片化**(只要不触发 §5 框中框 / 重复明细底线就尽量用卡):每条发现做成一张**独立卡片**(各自留白、各自边界、状态色点或胶囊标签),比纯分隔线的文本条目更有结构感。**前提是把卡做"实"**——别做成"大数字 + 小标签 + 渐变底"的空心 SaaS 卡(违反地板「指标卡每张 ≥2 层信息」)。结论卡可以承载判断文字 + 状态 + 关键值,**v4 也允许配大数值/迷你图作聚焦**;别做的是**把整张明细的全套数字逐项搬进来再加一遍**(那会让同一数据超过 2 次 / 同层重复)。

### ★"重点区分"是强制的(条目卡 / 纯文本段落都一样)
实测高频翻车:模型只把指标名加粗、正文一片黑。无论结论用哪种形式呈现:
- **状态词(达标/未达标/关注/超阈/缺失)必须语义上色**(达标绿 `--success` / 关注橙 `--warning` / 未达红 `--danger` / 缺失灰 `--text-3`),禁全黑字;
- **关键数字 + 环比方向(▲▼)** 要与正文区分(加粗,方向值按好坏上色);
- **强调对象是"值和状态",不是"指标名"** —— 只加粗指标名、关键值与状态毫无视觉区分 = 强调错了对象。
- 纯文本结论微例:`当天签收率 <b class="pos">98.4%</b>(达标),低于 95% 的网点 <b class="neg">6 家</b>;淘天揽签 <b class="neg">92.23%</b>(<span class="neg">未达</span>)`——值与状态有色有重,指标名反而不必加粗。

### ★核心结论"标题"默认与其他模块标题同级一致(锁硬规格)
"核心结论 / 核心发现"这个**分节标题**本身,**默认用与其余分节标题(趋势洞察 / 完整明细…)完全相同的样式**——同一个 `.sec` class、同字号(13–14px)、同字重、同色条/间距 token。**别给它单独加大字号、加大色块、加整条彩色横幅**把标题做得比别人重。
- 真正承载"结论先行"分量的是**结论的内容**(状态卡、关键值放大、语义上色),**不是把标题做大**。标题统一,版面才整齐、像有人调过;标题各做各的大小 = "间距/层级乱跳"的同类翻车。
- **唯一例外**:用户明确要求把核心结论区做成特殊设计(如整页 hero 开篇、汇报封面页)时,才允许结论标题区单独升格——那是"特殊设计"的主动决定,不是默认。
- 可检验失败定义:**核心结论标题在无特殊设计意图时,字号/字重/样式与其他分节标题不一致(被单独做大 / 加色块横幅)= 违规。**

### ★排布:尽量一行排多个结论条目,节省竖向空间
默认用 `grid` 一行放 **≥2 个**条目(短结论可 3-4 个/行),按内容长短自适应列数;只有单条特别长(需整行展开叙述)时才独占一行。**禁默认每条都独占一整行**——那样竖向拖得很长、上半屏全是结论、明细被推到很下面。参考:`display:grid;grid-template-columns:repeat(auto-fit,minmax(280px,1fr));gap:10px`,长条目用 `grid-column:1/-1` 跨整行。

## 5. ★结论卡边界与防框中框
多条结论既可做成**独立卡片平铺**(推荐),也可共用一个容器但条目间有明确分隔线;无论哪种,模块划分都必须清晰。**铁规:**
- **✅ 推荐:每条是独立卡(各自边界 + 统一内边距 + 统一 gap),彼此平铺,不外套一个带边框的大容器。** 卡的"边界"可以是边框,也可以是浅一档的底色块(`--surface` / `--surface-2`)+ 留白——后者往往更干净。
- **✅ 次选:共用一个无边框容器,条目间用分隔线(`border-top:1px solid var(--border-2)`)划分。**
- ⛔ **禁框中框:一个带边框/圆角/底色的大容器,内部再放一排各自带边框的小卡 = 框中框 = 违规**(这是实测最高频、也是用户最反感的结论层翻车)。要卡就让卡自己平铺,别再给它们套壳;要套容器就让容器"隐形"(无边框、仅作 grid 布局)、内部才出边界。
- ⛔ 禁"一个大框 + 内部无分隔的连续文字"(糊成一团分不清几条)。
- 状态用同色**色点 / 胶囊标签**标识该条状态即可(注意地板:`border-left` 作彩色装饰条 >1px 是违规,承载语义的状态左边框保持 ≤3px;**更推荐色点/标签,不靠色边**)。
- 可检验失败定义:**①多条结论共处一个边框内、条目间无分隔线也无独立卡边界 = 模块划分不清 = 违规;②带边框/底色的大容器内再套一排带边框的小卡 = 框中框 = 违规。**

---

## 6. ★客观、禁只报喜(偏见)
不管是呈现源结论还是自己综述,都不能只挑正向数据当头条。**禁止顶部三个大数全选正向**(104%、98.4%、第 1 这种"全是赢的")——那是变相立 hero + 预设"形势大好"。正负、缺失要如实并列。失败定义:**核心结论只呈现正向数据、未如实列出未达/异常/缺失 = 违规(偏见)**。

- ⛔ **禁止一上来就甩几十行大表 / 一堆平铺卡让读者自己找结论。**
- **结论处放大某指标 / 立焦点是允许的(v4)。** 当数据本身有一个值得让版面为它让路的主角(一个濒临红线、一个反常暴涨),结论层**可以**把它放大成聚焦卡/大数值。**唯一约束仍是客观**:别只把"正向成绩"抬成主角来制造"形势大好"的错觉(那是偏见);如实呈现的"问题主角"或"中性大局"都正常。

## 7. ★可直接抄:核心结论卡片式并列(>3 条 / 状态量级差异明显时用)
**先按 §4 选型**:**>3 条结论**(或条目间状态/量级差异明显、需并列扫读)才用这个——**N 张并列大卡(一行 3–4 张,密度够又干净),每卡 = 状态标签 + 大数字(语义色)+ 一句描述**;**≤3 条改走 §4 诊断文本卡 `.diag` / `.sto-diag`,别默认铺成一排大卡(空、留白浪费)**。问题项那张用 `.focus` 加极淡语义底 + 大数字上语义色——**分布式一致强调,不靠某个数比别人大很多**(见 SKILL.md 出门前自检 #1)。下方 CSS/HTML 片段可直接抄(默认金标准 example-sto 核心结论用 ≤3 诊断卡,>3 才用这套并列卡)。
