# Structure & Hierarchy

> 铁律在 SKILL.md 文末。这里讲版面结构、信息层级、形态(圆角/阴影/边框/卡片)。

结构是出彩的**前 80%**(见 SKILL.md 第三步)。先把层级和结构立住,颜色才有意义。

## 信息层级:版面的脊柱

层级 = "读者眼睛的移动顺序"。好版面让人**不假思索就知道先看哪、再看哪**。

建立层级的手段(**至少叠两种非颜色手段**,见 craft-moves.md 灰度测试):
- 字号(主角大、辅助小,且拉开档,见 typography.md)
- 字重(关键 700 vs 辅助 400)
- 位置(重要的在左上,信息从左上流,不从中心展开)
- 留白(留白多的地方 = 重要,见 density.md)
- 颜色(第三层强化,不是第一层支撑)

**信息流向**:数据页/报告页从**左上**流。居中 Hero 只留给单 KPI 大屏、年度回顾这种"焦点页"。

### 分节标题要紧凑(别占太高)
一份报告分几大块(重点 / 趋势洞察 / 完整明细)时,**小节标题用紧凑间距**:字号 13-14px、上间距 ~20px、下间距 ~8px,标题到内容之间**不留大空档**。低端模型常把分节标题撑到 40-48px 的上下留白,看着空旷——压回 20/8。参考:
```css
.sec{font-size:13px;font-weight:600;margin:20px 0 8px;display:flex;align-items:center;gap:8px}
.sec::before{content:"";width:3px;height:13px;background:var(--accent);border-radius:2px}
```
标题克制(一个 3px 小色条 + 文字即可),别用大色块/大图标/整行分割线把标题区撑高。

### ★所有标题→内容的间距必须全文统一(同一组 token,不逐个不同)
低端模型常给每个小节随手写不同的 `margin`(这块标题下 8px、下一块下 24px、再下一块 16px),整页看着"间距乱跳、没人调过"。**铁规:全文所有同级标题用同一组间距变量,改一处全文一致。** 用变量定义一次、所有标题引用:
```css
:root{ --sec-mt:20px; --sec-mb:8px; }     /* 标题上/下间距,全文唯一来源 */
.sec{ margin:var(--sec-mt) 0 var(--sec-mb); }
```
- 同一层级的标题,上间距彼此相等、下间距彼此相等;**禁逐个小节手写不同数值**。
- 标题与其正下方内容的间距(`--sec-mb`)全文一个值,别这块贴得近、那块离得远。
- 可检验失败定义:**同级分节标题的上间距或"标题→内容"间距在全文中出现 ≥2 种不同值 = 违规。**

## ★第一步:先选报告原型(按原始内容特征定,再谈模块)

同一套 STO 设计语言下有**三种报告原型**,区别只在**头部 + 模块编排 + 用途**,不是三套样式。**先按你拿到的原始内容选一种,再用下面「条件触发」填模块。** 三份金标准分别对应:

| 原型 | 原始内容长这样 → 选它 | 头部 | 核心结论区 | 主体模块 | 金标准 |
|---|---|---|---|---|---|
| **① 排名钻取型** | 一个维度的**榜单**(TOPN / 降幅榜 / 红黑榜),且要按区域、分类**切片看同一张榜** | `.hero` 大图 banner + 居中标题(单主题封面感) | 无(直接进榜)或可选 | **单模块**:一张大卡 = 区域 tab(`.rnav`) + 一张排名表(红圈排名 + 降幅条 + 关键列橙) | example-sto-ranking |
| **② 异常监控型** | 数据是**异常项/风险项集合**,每条要给处置、责任、优先级,按异常类型分多张明细表 | `.masthead` 签名(左标题右元信息,克制) | 指标卡(表达异常面/达成面的整体收敛) | **多模块**:分布 barlist + 行动建议(P0/P1/P2·SLA) + 多张异常明细表(风险点 + 可能原因/研判 + 涉及金额) | 客户异常监控报告 |
| **③ 全景日报型** | 把一段时间内**全部常态指标**(业务量/时效/质量/网点…)平权铺开、**无单一主角** | `.masthead` 签名 | 诊断提醒卡 `.diag`(≤3 条判断 + 风险) | **多模块**:指标卡(带 sparkline) + 网点分表 + 多级表头大表(业务分类 rowspan + 趋势列) | example-sto |

一句话:**①钻一个维度的榜，②抓异常 + 派活，③把全部常态指标铺开看。**

取舍(用失败定义)：
- **头部**:单主题榜单用 hero 大图;多模块运营报告用 masthead 签名。⛔ 给一份全景日报套营销大图 = 调性错位。
- **结论区**:≤3 条判断 → 诊断卡(③);要表达"异常面/达成面整体收敛" → 指标卡(②);纯榜单可省(①)。
- **模块数**:① 只放 1 个主模块,别硬塞指标卡和行动建议;②③ 才铺多模块。⛔ 把排名榜包装成"指标卡 + 行动建议 + 多表"= 过度设计;⛔ 把全景日报压成单榜 = 信息丢失。
- 三原型**共用**同一套 token / 组件 / 表格卡片画法(见 sto-components.html、base.md);选型只换头部与模块组合,不另起炉灶。

## 结构是条件触发的——没条件就不出现

不强制任何结构。**有这个特征才考虑对应元素:**

| 数据特征 | 可考虑 | 没有就别加 |
|---|---|---|
| 有结论性内容 | 顶部结论区(形式自定) | 没结论不造 |
| 表格 >15 行且可分类 | 分章节分组 | 行少不分 |
| 有时间序列 | sparkline / 趋势缩略 | 无时间维度不用 |
| 有占比/构成 | 环形/堆叠/进度条 | 无占比不用 |
| 有异常需突出 | 突出方式自定 | 无异常不强调 |
| 多个并列指标 | 卡片网格/列表/表格 | 单指标不用网格 |
| 有流程/路径 | 漏斗/桑基/步骤图 | 无流程不用 |
| 原始内容明确可下载**全局行数据** | 右上角下载按钮(与元信息用分割线分隔,见下) | 无全局可下载数据不加 |

> **★全局数据下载按钮(条件触发):仅当 HTML 原始内容明确表明存在「可下载的全局行数据」(完整明细表 / 全量行级数据 / 原文说"可下载/导出")时才加;普通汇总/无行级数据不要凭空造下载入口。**
> - **位置:报告右上角**,即 masthead 右侧元信息区(报告日 / 生成 / 口径 / 共 N 项指标 那块)。
> - **与右上元信息整合,用分割线(1px hairline `--border`)分隔,别挤成一团:** 元信息竖排时,分割线横置于按钮与 meta 之间(上下分区);按钮与 meta 横向并列时用竖向分割线。下载按钮归一组、纯文字元信息归另一组,中间一条线。
> - 按钮复用 `.sto-btn`(次级/三级 + 下载图标),小尺寸、不抢主标题;只放一个全局入口,别每张表都挂下载(单表级下载属表内操作列,不在此列)。**下载/链接文字一律用申通橙 `#FF6700`(品牌交互色),不用辅助蓝**(owner 2026-06-18 定;表内操作列「下载明细 / 查看」等文字链接同理用橙)。
> - **多个下载按钮且无明确主次时,全部用三级按钮(`.sto-btn--tertiary`),不要随意把某个抬成主/次按钮。** 仅当原始内容明确某个下载是主操作时,才允许它单独升一级。

常见信息架构(参考,可自由调):
```
元信息(日期/维度/周期)
  → 核心结论 / Verdict   ← 仅当有结论
  → 重点关注指标          ← 仅当有重点
  → 完整数据表 / 图表
  → 附注 / 口径说明        ← 仅当需要说明
```

## 卡片:能不用就不用(impeccable 启发)

卡片是**"懒答案"**。模型反射性地把所有东西包进卡片,结果是一堆等权的盒子 = 平庸。

- 真正需要分隔时才用卡片
- **嵌套卡片永远错**(最多两层:页面 → 卡)
- 不要把所有东西都包进容器
- 替代方案往往更高级:**分隔线、背景色块、留白、标题 + 短分割线**

数据指标卡确实有用,但每张必须 ≥2 层信息(见 SKILL.md 地板),且"该用才用"。

### ★卡片白名单:全页只允许 2 个卡位,别处一律禁卡(治"满页都是卡")
卡片是懒答案,**最高频的翻车不是单张卡不好,是整页从上到下全是一排排卡**——结论卡 + KPI 卡 + 行动卡 + 子项卡…堆四五排,既单调,又把本该用图/表/列表的数据硬塞进卡。

> **为什么旧版"≤2 种卡片族"压不住:"族"是要模型先分类再计数的模糊单位,模型能把任何布局合理化成"我只用了 2 族"。改成白名单——不数、不分类,只比对"这是不是那 2 个允许的卡位"。**

**规则:全页卡片只允许出现在下面两个固定卡位,其余任何数据都禁止做成卡。**

| 卡位 | 唯一合法用途 |
|---|---|
| **卡位 1 = 结论卡** | 顶部「结论先行」的核心发现(见 conclusion-layer.md,默认就该做成卡) |
| **卡位 2 = KPI / 指标卡** | 一组横向对比的关键指标(1主+N副,见 data-presentation.md) |

**两个卡位用满即止。** 其余一切想平铺成卡的数据,一律换成对应形式:

| 想做成一排卡的数据 | 强制改用(禁卡) |
|---|---|
| 构成 / 占比(几项加总≈整体) | 环 / 100% 堆叠条(不是一排"数字卡") |
| 类别比大小(各子项的量) | **排序横条**(最该换的:N 个子项各一张"数字+delta"卡 = 典型滥用) |
| 排名 / 名次 | 排序条 / 带序号列表 |
| 并列的建议 / 步骤 / 清单 | 带序号/优先级的**列表**(不必每条套卡) |
| 明细 | 表格 |
| 单时点孤值 | 并入卡位 2 的 KPI 组,别再开一处卡 |

- 这条和「可视化要有变化」(SKILL.md 簇 A)同源:不同数据关系本就该用不同形式交替,卡片只是其中一种,不该独占整页。
- **收尾机械自检(数字面量,不数抽象族)**:数产物里独立的 `.card` 网格(每个 card grid 算一处)有几处,**>2 就违规**,把超出卡位 1/2 的那些按上表改成非卡形式再交。
- 可检验失败定义:**①产物出现第 3 处 `.card` 网格 = 违规(超出白名单);②一组"构成/分布/类别对比/排名"数据被做成一排"数字卡"而非条形/环图 = 违规(见 charts.md 簇 A「选对图」)。**

> **★白名单豁免:红黑榜 / 排行榜不算"第 3 处卡"(STO 官方《卡片容器》《排行榜样式》)。** 红榜+黑榜、TOP3 红旗/黑旗榜这类**本就是一个独立成立的展示模式**,它用卡是模式自带的、不是"把数据偷懒包卡",故**不计入 2 卡位限额**。但仍守:① 红/黑两榜并排在**一个 grid** 里、不互相外套大边框(防框中框);② 榜内单条仍 ≥2 层信息。

### ★排名 vs 序号 + 红黑榜样式(STO 官方《排行榜样式》)
"排名"和"序号"是两件事,呈现强度不同,别混:
- **排名(要突出名次高低)**:前 3 名用奖牌/底色强调;想突出"优秀↔差劲"两端时,用正负向色(**前段绿、末段红**,即 `dir` 色);其余名次降噪。**整体 ≤ TOP10,别拉长榜。**
- **序号(只是行号、不表达优劣)**:用**普通正文样式**,不加奖牌、不染色——别把序号做成排名抢视觉。
- **红黑榜**:红旗榜(正向 TOP)走暖/绿正向语义,黑旗榜(负向 TOP)走红负向语义;两榜并排,标题带红/黑区分,榜内每条"名称 + 分值"。
- 可检验失败定义:**①纯序号(行号)被做成奖牌/染色的排名样式 = 违规(过度强调);②排行榜拉到 >10 条还逐条强调 = 违规(降噪或截断);③红黑榜两榜各自外套带边框大容器 = 框中框违规。**

### ★同一行卡片:等高 + 内部按最高内容对齐(通用规则,不限图表卡)
**等高只是第一步,不够。** 只设 `align-items:stretch` 卡片外框等高了,但**卡内的描述文字行数不同**(一行 vs 两行)会把它下面的大数值/分割线/环比行**整体下推**,导致同一行各卡的"大数值不在同一水平线、分割线和环比错位堆叠"——这是实测翻车(用户明确反馈)。**必须让内部各行也跨卡对齐:把"会变高的那块"(描述/标题文字)按本行最高内容统一高度,让它下面的锚点行(大数值/分割线/脚注)落在同一基线。**
```css
.cards{ display:grid; gap:10px; align-items:stretch; }   /* ① 外框等高 */
.card { display:flex; flex-direction:column; }            /* ② 卡内纵向流 */
.card .desc{ min-height:calc(1.55em * 2); }               /* ③ 关键:变高的文字块按本行最长(如 2 行)预留统一高度 → 下方大数值跨卡对齐 */
.card .value{ margin-top:8px; }                           /*    大数值/分割线在 desc 之后,desc 等高后它们自然对齐 */
.card .foot { margin-top:auto; }                          /* ④ 脚注/口径钉到卡底 → 底边也对齐 */
```
- **③ 是这条规则的命门**:`margin-top:auto` 只能把**最底部**的脚注钉齐,**钉不齐中间的大数值/分割线**——中间锚点要靠"上方文字块 min-height 统一"来对齐。按本行**最长描述**的行数设 `min-height`(中文常 1-2 行),或对描述用 `-webkit-line-clamp` 限定行数。
- **`align-items:stretch`**(grid 默认,别覆盖成 start)+ 统一 padding / gap / (若有)图固定尺寸。
- 可检验失败定义:**①同一行卡片高度参差 = 违规;②同一行各卡的大数值/分割线/环比行不在同一水平线(因描述行数不同而错位堆叠)= 违规;③底部脚注未对齐成一条线 = 违规。**

### ★并排列表 / 表格行数不等(短的那张矮一截)怎么办
两张并排的榜单 / 分表 / 列表行数不同(如左 6 行、右 3 行),右边矮一截、底部参差——这是**版面问题,不是数据问题**(行数差本身是真实信息,标题已标「6 家 & 3 中心」)。**别为凑等高去藏数据或造假数据。** 按场景:
- **★报告类(可滚动页 / 可打印)= 自然高度、顶对齐、底部参差可接受。** 各表取真实长度,短的就短。⛔ **禁固定等高 + 内部滚动**——报告是静态可扫读 / 可打印的,内部滚动把数据藏进滚动条(违反地板「不删表 / 不藏数」),3 行硬滚去凑 6 行更无意义;⛔ **禁拉高行 / 塞空行凑高**(虚高、假数据)。
- **想把参差收口** → 用**轻量补位**填短表尾部:一行**合计 / 阈值口径 / 小结**或中性注脚,让卡底自然收齐,而不是硬撑空白或塞假行。
- **行数差悬殊**(>2 倍且短表 ≤3 行)→ 别硬塞等分两栏:给长表更宽的**非等分 grid**(如 `1.4fr 1fr`),或把两表**上下堆叠**,别让一张明显空半截。
- **不是换可视化** → 3 行的榜单仍该是表 / 榜,别为"凑高"把它改成饼图 / 大数卡等别的形式,那会破坏"两张同类榜单并排"的一致性,是为形式而形式。
- **唯一可用「固定高 + 滚动」的场景 = 固定视口看板**(监控大屏 / dashboard 面板,版面高度被钉死),那里等高面板内部滚动才成立;**报告不在此列**。
- 可检验失败定义:**报告类里为凑等高给表格加内部滚动 / 空行 / 拉高行 = 违规;并排两表行数差悬殊仍硬用等分两栏、短表空半截无补位 = 版面失衡。**

### ★对齐标准:巨数 / 极端字号差并排时,别用 baseline 混排
**当一个 `.t-display` 巨号(48-96px)和小字标题块并排**(典型:masthead 的"05·27"巨号 + 旁边"日报标题 / 副标"两行小字 + 右侧 meta chips),**用 `align-items:baseline` 会错位**——巨号的基线和小字块的基线差太远,看着"没对齐"(用户明确反馈)。统一标准:
- **同一横排,选定一个对齐基准并全行一致**,别一处 `baseline`、一处 `flex-end` 混用。
- **巨号 + 小字块推荐 `align-items:flex-end`(底对齐)**:让小字块的底边贴齐巨号的底边(视觉地面线一致),比 baseline 稳。或显式给小字块 `padding-bottom` 微调到巨号视觉基线。
- **左侧标题区 与 右侧 meta chips**:同样底对齐到同一条地面线(或都顶对齐),别一边 baseline 一边 center。
- 小字块内部(标题 + 副标两行)自己 `flex-direction:column; justify-content:flex-end`,作为一个整体再去和巨号底对齐。
- 可检验失败定义:**同一横排内极端字号差(巨号 + 小字)用 baseline 对齐导致小字块明显偏高/偏低、未对齐到统一地面线 = 违规;同一横排元素用了 ≥2 种对齐基准 = 违规。**

> **★结论层是"该用卡"的典型场景(而非滥用):** 核心结论的多条发现本就需要彼此分隔、各自承载状态,默认优先做成**独立平铺的卡**(见 conclusion-layer.md §4「默认卡片化」)。这与本节"能不用就不用"不矛盾——反对的是**反射性地把所有东西包卡 + 嵌套卡**,不是反对在真正需要分隔处用卡。**但第 72 行的底线照旧:结论卡彼此平铺即可,绝不能再外套一个带边框/底色的大容器(= 嵌套/框中框,永远错)。**

## 形态:全局选一档,贯穿到底

**圆角**(选一档,禁混用):
| 档 | 适合 |
|---|---|
| 方角 0px | 工业、精准、监控大屏、严肃 |
| 小圆 4px | 编辑、专业克制 |
| 中圆 8-12px | 现代、温和、友好 |
例外:头像/圆形徽章 `50%`、胶囊 tag `999px`(与档位独立)。

**阴影**(选一种策略):
- 无阴影:用分隔线/背景色/边框做层级(编辑型、工业型)
- 极轻:`0 1px 3px rgba(0,0,0,.04)`(现代专业)
- 柔光:`0 4px 12px rgba(0,0,0,.06)`(温和友好)
禁重投影、多层叠加、嵌套阴影。

**边框**:
- 半透明黑 `1px solid rgba(0,0,0,.08)` / 品牌色淡边 `1px solid <accent>/12%` / 分隔线代边框(只一条边)
- 禁纯灰硬边框 `#e5e5e5`(用半透明黑或带色微调替代)

**分层方式**(单报告只用 1-2 种,禁混乱叠加):阴影 / 背景色(不同 L 灰阶)/ 边框 / 留白 / 分隔线。

## 响应式 / 移动端自适应
报告**桌面优先**(截图/全宽展示),基础版面锁桌面,别为手机牺牲信息密度。

**默认(必做)** —— 给一个平板断点 `@media(max-width:760px)`,把**所有多列**都塌成单列:findings 三卡、左右两栏、KPI/kf-grid、grid2 进度条列、verdict 结论板。失败定义:760px 下任一多列网格仍横向并排 = 违规。

**★同断点必做:masthead 头部 meta 翻横排** —— `.masthead` 桌面是「左标题 + 右 meta 竖列」,右侧 meta(报告日 / 生成 / 对比口径 / 规则版本 / 共 N 项…)是 `flex-direction:column` 每条占一行。窄屏 masthead 一旦掉成整行,这个竖列就**每条拖一片右侧留白、白白拉高头部**。在 `@media(max-width:760px)` 里**把 masthead 改竖排、meta 翻成横向 wrap 排**,贴左占满整行、能并几条并几条:`.masthead{flex-direction:column;align-items:stretch;gap:10px}` + `.mh-meta{flex-direction:row;flex-wrap:wrap;align-items:baseline;justify-content:flex-start;text-align:left;column-gap:16px;row-gap:4px}`。失败定义:窄屏 meta 仍每条一行竖排、右侧大片留白 = 违规(owner 反馈 2026-06-18)。

**手机断点(仅当用户明确要"移动端/手机")** —— 另加 `@media(max-width:480px)`:
- 被强制单行的文案(`white-space:nowrap`)恢复换行(`white-space:normal;overflow-x:visible`)
- 概览头部竖排(主数在上、指标在下),横向指标条改 `grid 1fr 1fr`(2×2);奇数项重置左分隔(`padding-left:0;border-left:0`)
- 残留的 2 列进度条(grid2)塌 1 列
- 字阶降一档(巨数 ~24px、H1 ~23px),body padding 收到 ~10px 12px

**★取舍要说出来,别偷偷处理** —— 强制单行文案(`nowrap`)和全字段 `nowrap` 表格对桌面友好,但手机上必然横滑。手机上"既一行又不横滑"做不到:**桌面保持一行、手机换行**,两套规则互不影响。生成时若用到了 nowrap 文案/宽表,主动告诉用户这个权衡,而不是替他选。

## ★组合 / 联动布局(列表 → 详情;来源:STO 联动表格,组件见 sto-components.html「组合/联动布局」)
排名/明细表常和"详情"配成**左列表 + 右详情**的联动(钻取)版面,右侧详情按需是三种之一:
- **表格 + 图表**:左排名表,右趋势/面积图(选中某行→图表展示该对象趋势)。
- **表格 + 指标卡**:左排名表,右一组指标卡(选中行→卡片展示该对象关键指标,套 sto-card)。
- **表格嵌套(表格 + 表格)**:左大区表→右网点表→(3 级)再右商家表,逐级钻取。
要点:① **选中行淡橙高亮**(`.is-sel` = `--brand-bg` 底),并把该行关键值染橙;② 每个面板带**橙竖条标题**(`.sto-panel__h`);③ 布局 `list-detail`(列表窄·详情宽)或 `t2`(等分),760px 塌单列;④ 图表用 sto-charts、指标卡用 sto-card 直接拼。**别做成两张互不相干的表硬并排**——联动的意义是"右侧跟着左侧选中变",版面上用高亮 + 标题点明从属关系。
