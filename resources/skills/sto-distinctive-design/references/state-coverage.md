# 状态覆盖:数据不全时怎么呈现(报告/仪表盘口径)

> 铁律在 SKILL.md 文末。本文管"哪些状态必须存在",data-presentation.md 管"数据长什么样",两者互补。
> 思路改编自 open-design `craft/state-coverage.md`(MIT,源自 refero_skill),按数据报告场景裁剪。

**AI 生成数据页最可靠的一种翻车,是只画了"数据齐全"那一种状态。** 真实业务里数据经常缺、晚、异常、超量。一个被设计过的报告,会在数据不理想时**仍然不崩、不骗、不空白**。

## 五种状态:每个表格 / 卡片 / 图表都要想过

| 状态 | 触发 | 必须做到 |
|---|---|---|
| **齐全(Populated)** | 数据正常 | 设计本来就为它画的样子 |
| **缺失(Empty)** | 某指标当日无数据 / 口径未回流 | 显式标"—"或"暂无数据 · 口径 T-1 未回流",**绝不编造、绝不补 0 充数** |
| **异常(Anomaly)** | 值超红线 / 环比剧变 | **原样呈现 + 标红 + 标"待核实"**,不替用户下"严重"结论,也不悄悄抹平 |
| **极端(Edge)** | 超长名称、超大行数、超长小数、空可选字段 | 布局不崩:名称截断带 title、表格可滚动、数字对齐不撑破列 |
| **加载/失败(仅活数据看板)** | 实时拉数在途 / 拉数失败 | 骨架占位;失败说清"什么失败+能做什么",别只转圈 |

> 静态报告(截图交付)重点是前三行;**活数据看板(live dashboard)才需要管加载/失败**。别给静态报告硬塞 loading 态。

**自检方式:render-and-screenshot —— 把每个表格 / 卡片 / 图表都过一遍这几态,缺一个就是 silent failure。**

## 缺失态:空不是"没有状态",是一种要被设计的状态

- **禁止三种偷懒**:① 缺数据就补 0(制造假趋势);② 缺数据就留纯白单元格(读者不知是 0 还是没数);③ 缺数据就把整张表/图删掉。
- **正解**:缺口处显式占位——单元格 `—`、sparkline 缺口用 `null`(自动显示 —)、整块缺失给一行"暂无数据 · 原因(口径未回流 / 当日无单)"。
- 一句话:**"没有数据"本身是有效信息,要让读者看见它,而不是被填平。** 这正是去 AI 味的关键——AI 反射是"把每个格子填满",专业反射是"该空就诚实地空"。

## 异常态:标记清楚,但不替用户定性

错误/异常呈现要回答三件事,顺序固定:

1. **发生了什么** —— "中心最晚未转出 2.26%"(给值,不给"出大事了")
2. **对照是什么** —— "红线 0.7% · 超 1.56pt · 环比 +132.99%"(给参照系)
3. **状态是什么** —— `待核实` / `已确认` 标签,把"要不要紧"的判断留给用户

- 异常用**颜色 + 形态双编码**(红 + ▼ + 底色),色盲可辨;不靠单一颜色。
- **不把负向项做成压倒性主视觉**(同 SKILL 文末铁律):标清楚即可,巨型字默认留给中性结论,除非用户明确要"排查/预警"。

## 极端态:测一下别崩

落到数据报告,至少survive 这几个场景:

| 场景 | 要扛住 |
|---|---|
| 表格超量 | 1000+ 行、全数字列、排序+筛选后仍对齐;表头粘性 |
| 超长文本 | 200 字网点名 / 备注:截断带 `title`,不撑破列宽 |
| 超长小数 | 用 `tabular-nums` + 小数点对齐,不让列宽跳动 |
| 空可选字段 | 缺备注/缺趋势:占位 `—`,不留布局空洞 |

## 常见错误(自检时 lint 这些)

- 只画了数据齐全态,缺失 / 异常 / 极端全没考虑。
- 缺数据被补成 0,制造了不存在的趋势。
- 空单元格纯白,读者分不清是 0 还是没数。
- 异常只标了红色,没有形态/文字,色盲不可辨。
- 异常被悄悄抹平(取了"正常"的那天数据),数据失真。
- 超长名称撑破表格列宽,整行错位。
