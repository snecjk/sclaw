# Data Presentation

> 铁律在 SKILL.md 文末。这里讲数字、趋势、状态、异常的呈现细节。

## 先读数据语意,再决定"强调什么"(带数据时的第一步)
**带数据的内容,不要拿到数字就套版面——先花十秒读懂它的语意,强调才有依据。** 这一步决定下面所有呈现细节(强调谁、上什么色、配不配图)。问四件事:
- **极性**:这个指标「越高越好」还是「越低越好」?(决定 ▲▼ 上绿还是上红,见下「方向/环比/状态」)
- **关系**:它是单值/对目标的达成/几项构成一个整体/同类比大小/时间序列/排名?(决定图型,见 charts.md「先判断数据关系」)
- **状态**:达标 / 关注 / 未达 / 缺失?(决定语义色和徽章)
- **量级与落差**:哪个数字大到值得放大、哪个落差大到值得并排对比?(决定视觉权重)

**读完语意,"强调"才落到对的对象上,且有明确优先级:**

> **★强调优先级:率值/核心指标值 = 主强调(最大、最重) > 状态(达标/未达) = 辅助强调(小、点到为止) > 指标名 = 不强调。**
> 实测翻车(用户明确反馈):模型把"达标/未达标"做成顶部加粗大写彩色 pill,最抢眼,反而盖过了率值——**优先级反了**。一张指标卡的视觉主角应是那个**率值**(达成率 104.0% / 时效 92.23% / 签收率 98.4%),状态只是给它配一个**小色点或小标签**说明达没达,不该比率值还响。

- ✅ 对:**率值做大做重(卡内最大字号),作主角**;状态用一个**小色点 / 小胶囊标签**(语义色)辅助标注,不抢戏;方向 ▲▼ 跟随率值按好坏上色。
- ❌ 错:① 把"达标/未达"做成顶部加粗大写彩色块,响过率值(强调优先级反了);② 只把指标名加粗、值和状态一片黑(强调错对象);③ 不分极性纯按 +/− 上色(把"投诉率下降"标成红)。
- 失败定义:**①带数据却未做任何语义强调(值/方向/状态全黑)= 违规;②强调对象错放在指标名 = 违规;③状态标识(达标/未达)的视觉权重 ≥ 率值、盖过主角 = 违规(状态是辅助,不是主角)。**(与 conclusion-layer.md §4「重点区分」同源)

## 原始描述/口径要保留(可视化最常丢的东西)
源数据每项常带**口径/备注/caveat/上下文**——这些直接决定数字怎么读,**做成卡/图时不能无脑丢**:
- 例:"含全量·未剔除 S 类·待新接口""有偿派件量·无总部市场部数据""此接口实际为签收问订率排名,非字面『淘天服务』"。
- **保留方式**:卡片数字下方一行 `.t-xs`/`.note` 小字注;或表格加一列"口径/备注";或全表底 footnote 统一列。空间紧就缩短但别删意。
- **可省的只有**:把数字又用文字复述一遍的纯冗余、零信息的客套。**口径和 caveat 永远算有信息,不可省。**
- 失败定义:源带的口径/caveat 在产物里完全消失 = 违规(丢的是"怎么读这个数")。

## 数字
- **主指标视觉权重明显高于辅助**(字号/字重/颜色/位置任选或组合)——见 craft-moves.md 手法 1
- 数字 + 单位可上下分级(`98.4` 大字 + `%` 小字)
- 格式:`18.88%`(两位小数无空格)、`¥500.00`(符号紧贴)、`共 1,234 票`(中文量词留空格)、千分位逗号、大数缩写 `1.2 万 / 1.8K`
- **等宽数字字体**(见 typography.md)或 `font-feature-settings:'tnum' 1`,让一列数字小数点对齐、扫下去是齐的
- 主指标可加粗 500-600

## 指标卡的信息结构:1 主 + N 副(每张卡的"装法")

> 这是对地板「指标卡每张 ≥2 层信息」的**具体规格**——把"≥2 层"落成一套固定的信息单元,既保证不空心、也封住上限不堆乱。源自一批高密度物流看板的共性提炼。

每张指标卡是同一个信息单元,三段固定:

```
名称行    标签 / 名称(可带补充说明 / 对标对象)
主指标    大数字 + 单位          ← 唯一主角,永远 1 个,卡内最大字号
副指标群  [对比维度 : 值] × N    ← 0–4 个,全部用来修饰主指标
```

- **主指标永远只有 1 个**(卡内视觉主角,见上「数字」+ craft-moves 手法 1);**副指标 0–4 个,单卡数据点 ≤5**(超过就拆卡或下沉明细表,见 density.md「按决策深度分配」)。
- **★铁律:没有裸数字——每个副指标必须挂一个"对比维度"。** 一个孤零零的数,读者无法判断好坏;挂上对比维度,它才有"结论含义"。副指标只有 4 种语义,反复组合:

| 副指标类型 | 回答 | 例 |
|---|---|---|
| 环比 / 同比 | 比过去 | 环比 ▲1.21% |
| 环比差 / 变化量 | 变了多少 | 环比差 +1.2 |
| 目标值 / 达成 | 比目标(常配进度条 / 环) | 目标 90% · 达成 98% |
| 对标 / 构成 | 比同类 or 拆分占比 | 抖音 82% · 渗透率 0.15% |

- 这套结构同时满足两个地板:**≥2 层信息**(主 + 至少 1 个副)、**禁空心 SaaS 卡**(副指标是真信息,不是"大数字 + 小标签 + 渐变底")。也是"信息相关"维度的落点(density.md 三维度框架):它保证卡里**每个数字都有用**。
- **★STO 官方指标卡有两种装法(都在 example-sto.html,默认抄 A/B)**:
  - **A · 主指标卡(PC-5,用于核心结论/概览,`.cc`)**:顶部 = 标题(可带 ? 帮助图标);下方左块 = **大号粗体主数 ~38px/700** + 小灰单位 + 环比行(灰"环比"标签 + 语义 ▲▼ + 值);右块 = **副指标群**(每行 `标签 值 单位` 行内,标签/单位灰、值深粗,堆 2–3 行,无竖分隔)。恶化主角整卡淡红底 + 主数红。
  - **B · 主指标卡 + 趋势(用于重点关注 KPI 区,`.mc`)**:与 A 同信息结构,但主数小一档(~21px),且**底部加「近 7 日趋势」小标签 + 申通橙面积 sparkline 全宽出血**(描线入场,进视口播一次)。这是把"主指标 + 趋势"合进一张卡的标准 STO 画法。两者区别只在"主数大小 + 有无趋势图":结论区用 A(大数概览),指标区用 B(带趋势)。
  - **C · 进度条卡变体(可选,强调"目标达成进度"时)**:名称行右挂**状态药丸**(达标绿 `.pill.ok`/未达红 `.pill.no`,药丸=标签可语义上色)+ 主指标下方**进度条**(`--brand` 申通橙填充 + 灰轨;★**条=分类色不按好坏、不"未达走红"**,达标与否看状态药丸/数值——见 [color.md](color.md) 进度条规则)+ 右下**折角**。本金标准 example-sto 没用 C(用 A/B),但 C 也是官方画法,有目标进度语义时可取。
  - **★用进度条时:控制其版面占比,禁"一行/一列全是进度条",且进度条相关区域最多占页面面积 ½**。一整排卡片每张都铺一条进度条、或表格一整列全是进度条、或进度条模块横向满幅独占整页 = 进度条在版面占比过重、单调重复、廉价感。处理:**用其他内容补位对齐、把进度条降为局部点缀**——① KPI 卡里进度条只占主数下方一条短轨,卡内其余是数值/副指标/趋势;② 表格的进度条列旁必配真实数值列(进度条不单独成列);③ 多卡并排时,只给"有目标达成语义"的卡加进度条,无目标的卡用趋势/数值,不强行统一铺条;④ **★有进度条的模块最多占页面横向一半,另一半(右侧)用"内容较少的模块"补位对齐**——小 KPI / 状态药丸 / 排名小结 / 占比环等,让进度条区与右侧轻模块各占半幅,别让进度条区铺满整页宽。可检验失败定义:**① 一行卡片或一列单元格 100% 都是进度条、无其他内容补位 = 违规;② 进度条相关模块占页面面积 > ½(满幅横铺、右侧无较轻模块补位)= 违规**。
- **可检验失败定义**:**①卡里只有一个裸数字 + 一个名称、无任何对比维度 = 违规(空心卡 / 没"下结论");②单卡数据点 > 5(主 + 副 ≥6)堆成一团 = 违规(该拆卡或下沉明细);③副指标是孤值(只给数、没说明它在比什么)= 违规。**

## ★指标列表 / KPI 区:标签与数值必须「贴合」(锁硬规格 —— 治"对应不上谁是谁")
当一组指标做成**列表 / 定义区 / 紧凑 KPI 区**(不是大表、也不是结论卡)时,**每个指标的标签和它的数值必须成一个不可拆的单元,贴在一起**。实测高频翻车(owner 明确反馈):把**标签贴最左、数值甩到最右两端对齐**,中间一大段空白——哪怕加点线 / 引导线连接,**读者也对应不上"这个数是哪个标题的"**,整片显得松散。

- **✅ 默认做法:「标签在上、数值紧贴正下方」**,上下成一个 stat 单元。标签小字(`--text-2`)、数值大一档做主角(语义色),口径 / 备注放数值下方小字。多个单元用 grid 排成 N 列(常 3–4 列)、按组(业务量 / 成本 / 时效…)分块。**上下贴合 = 对应关系一眼成立,不需要横向找。**

**可直接抄(owner 认可版式;主指标卡完整画法见金标准 [example-sto.html](example-sto.html) 的「重点关注」卡):**
```css

@media(max-width:760px){.kf-grid{grid-template-columns:repeat(2,1fr)}}

.kf .v{font-family:var(--num);font-size:21px;font-weight:600;line-height:1;letter-spacing:-.01em;color:var(--text)}
```

- **次选(仅当确实需要一列对齐扫读、且每行很短时)**:标签左、数值右,但**整行收窄到标签与数值挨得近**(不是甩到页两端),且最好有交替底色 / 紧凑行高把一行锁成一组。
- ⛔ **失败定义**:**①指标列表里标签贴最左、数值贴最右,中间大段空白,读者对应不上谁是谁 = 违规(即便加点线引导也算);②同一行各 stat 的数值因标签长短不一而高低参差、不在同一基线 = 违规(用标签 `min-height` 预留行数对齐)。**

### ★概览主数(ov-hero / 大数 + 其标签)也走上下结构,禁 baseline 左右并排
概览模块顶部那个**大数主角**(如「4.49% 异常占比 · 较昨日 ▼0.42pt」)同理:**数值在上、标签+环比紧贴正下方**成一个单元,别用 `align-items:baseline` 把大数和标签左右并排(大数旁甩一行小字,对应关系要横向找、且大数右侧拖留白)。owner 实测取向。
```css
.ov-hero{display:flex;flex-direction:column;align-items:flex-start;gap:3px}  /* 上下:数值在上、标签在下;禁 baseline 并排 */
.ov-hero .hn{font-size:28px;font-weight:600;line-height:.9}                  /* 主数 */
.ov-hero .hl{font-size:11px;color:var(--text-2)}                            /* 标签+环比 delta,紧贴主数正下方 */
```
- 可检验失败定义:**概览大数用 `align-items:baseline` 与标签左右并排、大数右侧拖一行小字+留白 = 违规(改成 `flex-direction:column` 上下贴合)。**
- 区分:这是说**指标列表 / KPI 区**;**明细大表**仍按上「表格内呈现」(列对齐 + 表头同列),**结论卡**按 conclusion-layer(卡内标签 + 大数值本就上下贴合)。

## ★表格里的正负向色 + 可点击数值(STO 官方《使用在表格上》《颜色语义》)
> 颜色按 `dir` 配(见 color.md「dir 标记接口 / 正负向 5 载体」);物流指标方向查 [logistics.md](logistics.md),**不在表格里自行猜方向**。

- **可视化列(数值列加背景条)**:某数值列想横向比大小 → 给每行加按值长短的背景条;**条色按 `dir`**:越大越好(达成/签收)→ 绿条,越大越坏(投诉/破损/成本)→ 红条。禁不分方向一律同色。
- **双色阶梯度(考核/排名多行)**:网点考核这类一列多等级 → 正向走绿阶、负向走红阶分级;**权重高的指标列优先上色阶**(投诉>滞留>遗失…,见 logistics.md 考核权重)。
- **强调单元格(整格填色)**:仅表达梯度顶/底或单格特别强调时填满色,**非特殊慎用**(强化版只此一处,见 color.md「禁高饱和」例外)。
- **区分不同表格列**:可改**表头底色**区分多组列(一级/二级表头分组),不是给数据格乱铺色。
- **★可点击数值用下划线**:数值变色已被"正负向"占用,所以"可点击/可下钻"的数值**用下划线**表示,**不能用高亮/染色冒充可点击**。
- 可检验失败定义:**①可视化列/色阶把"越大越坏"指标配成绿(方向反)= 违规;②用数值高亮/染色冒充可点击(无下划线)= 违规;③整格填满饱和色出现多处(非单点强调)= 违规。**

## 方向 / 环比 / 状态:颜色必须按"语义"分,不按算术正负
> **范围:本节讲的是"方向箭头 ▲▼/↑↓、状态徽章、卡片顶条"的颜色——这些按语义上色。趋势的图形本身(sparkline / 面积线)是例外,全文统一品牌色,见本节末尾"⚠ 例外"与 charts.md。** 别把本节标题误读成"连趋势线也要语义上色"。
**关键:箭头/徽章/顶条的颜色由"这个变化/状态是好是坏"决定,不由 +/− 符号决定。**
- **环比/趋势色**:先判断指标极性——「越高越好」(揽收/达成率/效能/签收率)还是「越低越好」(滞留率/成本/投诉/破损/中断/未转出)。再决定:**好的方向 = 绿、坏的方向 = 红、持平 = 灰**。**★物流指标的极性别在这里凭记忆判,直接查 [logistics.md](logistics.md) 方向表(已按 `dir` 标好);单量类默认 flat、缺方向走中性禁猜。**
  - 例:揽收 ↑ = 绿;最晚未转出占比 ↑ = **红**(越低越好的指标在涨);投诉率 ↓ = **绿**;达成率 ↓ = 红。
  - **失败定义:环比上升和下降用同一个颜色、或纯按 +/− 符号上色(把"投诉率下降"标成红)= 违规。** 同一份里 ▲ 可以是绿也可以是红,▼ 同理——由语义定。
| 方向×语义 | 颜色 | 形态 |
|---|---|---|
| 好的变化(该升的升 / 该降的降) | 绿 success | ↑/↓ + ▲/▼ |
| 坏的变化(该升的降 / 该降的升) | 红 danger | ↑/↓ + ▲/▼ |
| 持平 / 无判定 | 灰 | — / = |
- **卡片/区块的"状态色"也必须语义化**:卡片顶条、状态徽章、方向箭头(▲▼/↑↓)的颜色要表达**该项状态/方向**——达标=绿、需关注=橙(warning)、未达/超阈=红、数据缺失/无判定=灰。**禁止用一个无语义的统一色(如默认蓝)给所有卡片当状态色**——那样"蓝色"什么都不表示,读者无法判断。可检验失败定义:**卡片用统一的非语义色(蓝等)当状态标识、达标和未达的卡片同色 = 违规**。(注:这不违反"平权"——平权是不放大某一指标当 hero;如实用语义色反映数据自己的达标/未达,是"尊重原数据"。)
- **⚠ 例外:趋势图形(sparkline / 面积图)反过来——单一非语义色,不按好坏变色**(见 charts.md)。"该项是好是坏"由旁边的**方向箭头 ▲▼(语义色)**说,趋势线/面积本身**统一一个色**,禁时红时绿时蓝。**STO 默认两档分工**:关键结论卡的 3–6 条重点 sparkline 用申通橙 `--trend`(点睛),30+ 行明细表的趋势列用中性灰 `--text-3`(别让申通橙铺满整表)——两处各自统一、都不按语义变色。分工:**状态徽章 / 卡片顶条 / 方向箭头 = 语义色;趋势线 / 面积图 = 统一非语义色(关键处橙、明细处灰)。**
- 位置选项:跟随数值 / 右上角徽章 / 表格独立列 / 数值下方副标。

## 表格内呈现

### ★全表竖向分割线(默认必做 · 无条件 —— owner 硬性要求,弱模型最爱漏)
**每一张表、每一列之间都必须有一条竖向分割线(全表竖向网格),不是"只在分组边界画线",也不是"列多才画"。** 单层表头、多级表头、5 列还是 15 列,一律都要。
**别再用 `nth-child(3),nth-child(5)…` 去手算列号画线**——那是最高频漏执行的根因(算错/漏算/列数变了就没了)。改用一条无条件全局规则,套了就有:**CSS 已在 [base.md](base.md) 锁定基线里**(`table{border-collapse:collapse}` + `th,td{border-right:1px solid var(--border)}` + 最右缘 `:last-child{border-right:0}`),套基线就生效,不在此重复。
- 线宽 `1px`、颜色统一 `--border #e6e6e6`(灰表头 `--th`/白表体都看得见,别用比表头底色还浅的 `--border-2` 否则在表头里"隐身")。
- 模块带 `.mod`(colspan 标签行)同样要让竖线穿过:用 `th,td` 通配后,band 里每个 `<td>`(标签 `colspan` + 其余空 `<td>`)都自带 `border-right`,竖线自然接通,不再断。
- **可检验失败定义**:任一张表存在"相邻两列之间没有竖向分割线" = 违规;整表只在分组边界有线、组内列之间无线 = 违规(本要求已升级为全列网格)。

### ★斑马纹隔行(锁硬规格 —— 起始行必须纯白,治"第一行被染灰糊在表头下")
**斑马纹从「与表头紧挨的第一行」开始,而第一行必须是纯白 `#FFFFFF`,然后依次往下交错**(白 → 灰 → 白 → 灰…)。第一行染灰会和上方灰列头(`--th #f5f6f7`)糊成一片、表头与表体分界消失,所以**首行(`nth-child(1)`,即所有奇数行)锁死纯白,只染偶数行**。
```css
tbody tr:nth-child(odd){ background:#FFFFFF; }      /* ★奇数行(含与表头紧挨的第一行)= 纯白,锁死 */
tbody tr:nth-child(even){ background:var(--zebra); } /* 偶数行 = 隔行底色 #FAFBFC(比表头更浅、可见) */
tbody tr:hover{ background:var(--surface-2); }       /* hover 覆盖斑马纹 */
```
- **方向定死**:染色挂在 `:nth-child(even)`(第 2、4、6… 行),**绝不允许写成 `:nth-child(odd)` 去染第一行**——那会让首行带灰、贴着灰表头分不开。
- `--zebra` 用 `#FAFBFC`(比表头 `--th` 更浅、但在纯白行边上仍可见);别用比 `--th` 还深的灰,否则斑马纹比表头还重、喧宾夺主。
- 模块带 `.mod` 行有自己的底色(`.mod td` 覆盖),不参与斑马纹奇偶。
- **可检验失败定义**:**①与表头紧挨的第一行不是纯白 `#FFFFFF`(被染了 `--zebra` 灰)= 违规;②斑马纹方向写反(`nth-child(odd)` 染色)= 违规。**

| 列类型 | 对齐 | 字重 |
|---|---|---|
| 数值(金额/数量/涨跌/率值) | **右对齐** | **加粗 600** |
| 文字 | 左对齐 | 常规 400 |
| 状态 | 居中 | 常规 400 |
| 单位 | 与数值同列右对齐 | 跟随数值 |
- 表头粘性(数据多时);列宽按数据宽度不强制等宽;关键列加粗或淡底色作锚点
- **★STO 官方表格画法:把"一个关键指标列"(如当日值/核心率值)的数值染申通橙 `--brand` 做视觉锚点,其余数字列保持中性近黑**(照 example-sto.html 的 `.c-key`)。一张表只橙一列,趋势 sparkline 列仍走中性灰——这是 STO 系统用色,不是"铺满"。
- 尾列可嵌 sparkline / 进度条 / 迷你柱 / 状态徽章
- **★表内趋势图列(STO 画法,组件 sto-components.html `.trend` / 用 sto-charts 渲染)**:窄列放申通橙面积 sparkline(≈84×22),展示该行近期走势;30+ 行别逐行画到糊,只给关键指标行画。
- **★色值进度条单元格(数值列加背景数据条;STO 官方"可视化列")**:单元格 = 数值 + 一条按比例的背景条(`.databar`),**条=分类色不按好坏**:默认申通橙淡底、第二条/同页橙过多时蓝淡底(`.blue`),**不按越大越好/越坏染绿红**(达标/未达靠条上率值数字 `.up` 绿/`.down` 红表达——见 [color.md](color.md) 进度条规则);条只做底衬、真实数值压在条上,**不是纯进度条**(仍遵守"进度条占比克制":数值是主、条是辅)。

### ★表头与列"同列对齐"(锁硬规格 —— 治"表头和列不对齐"这一最高频翻车)
实测最反复的塌方:**数据单元格右对齐了,表头却还左对齐**,整列看着错位、读不齐。根因是模型给 `td` 写了对齐、却忘了给同列 `th` 写。**铁规:对齐是"按列"的,同一列的 `th` 与所有 `td` 必须用同一个对齐值,绝不允许表头一种、数据另一种。**
- **做法(锁定):按列给一个对齐 class,`th` 和 `td` 同时挂同一个 class**,从源头杜绝错位:
```css
.col-num{ text-align:right; font-variant-numeric:tabular-nums; }   /* 数字列:右对齐 + tnum 小数点对齐 */
.col-num.th, thead .col-num{ font-weight:600; }                    /* 数字列表头:加粗 */
td.col-num{ font-weight:600; }                                     /* 数字列数据值:加粗(金额/数量/涨跌/率值) */
.col-text{ text-align:left; } .col-status{ text-align:center; }
```
```html
<th class="col-num">金额</th> … <td class="col-num">¥1,280.00</td>   <!-- 表头与单元格同 class，对齐天然一致 -->
```
- **★金额/数量/涨跌/率值列:数据值与表头一律右对齐 + 加粗**(上表已锁)。涨跌的 ▲▼ 方向值按好坏语义上色(见上「方向/环比/状态」),但右对齐 + 加粗不变。
- **可检验失败定义**:**①任一列的表头对齐方式与其单元格不一致(典型:数字列表头左对齐、数据右对齐)= 违规;②金额/数量/涨跌类列未右对齐、或值/表头未加粗 = 违规。**

### 多级表头(分组 / 两级表头 —— 列多到该按语义分组时用)
列 ≥8 且能按语义聚成几组(如「口径 / 当期表现 / 月累计」「基础信息 / 时效 / 质量」)时,用**两级 `thead`**:顶行 `colspan` 跨列给组名,标识列用 `rowspan="2"` 跨两行。结构:

> **★有多级表头时,一级表头(顶层分组行 `hgrp`)整行居中**——`thead tr.hgrp th{text-align:center}`(含 `rowspan` 的标识列头也居中),让组名压在它所跨列组的正中、整条分组带视觉成立。二级子表头(`hsub`)与数据列各自对齐照旧(数值右对齐、文本左对齐)。**只有出现分组/两级表头时才需要**;单层表头按列对齐(表头左、数值右)不动。可检验失败定义:**存在多级表头却把一级分组行做成左对齐 = 违规。**
```html
<thead>
  <tr class="hgrp">                        <!-- 顶层:分组行 -->
    <th class="col-num" rowspan="2">#</th>  <!-- 标识列跨两行;对齐随它本列的 col-* class -->
    <th class="col-text" rowspan="2">指标</th>
    <th colspan="2">口径</th>              <!-- 组名跨 2 列 -->
    <th colspan="5">当期表现</th>
    <th colspan="2">月累计</th>
  </tr>
  <tr class="hsub">                        <!-- 子表头:真正的列名,挂 col-* 对齐 class -->
    <th class="col-text">周期</th><th class="col-text">维度</th>
    <th class="col-num">目标值</th><th class="col-num">当日值</th>…<th class="col-num">月累计达成</th>
  </tr>
</thead>
```
```css
/* ★表头全部同字号同色(owner 口味:组标题别比子表头更小更淡) */
thead tr.hgrp th,thead tr.hsub th{font-size:10px;color:var(--text-2)}
thead tr.hgrp th{text-align:center;text-transform:uppercase;letter-spacing:.06em;
  border-bottom:1px solid var(--border);top:0}                /* 组行底线用 --border(不弱化) */
thead tr.hgrp th[rowspan]{vertical-align:middle;text-transform:none;letter-spacing:.02em}
thead tr.hsub th{top:23px}                                    /* 双行吸顶:子表头错开分组行高度 */
/* ★竖向分割线已由全局 th,td{border-right:1px solid var(--border)} 统一负责(见上「全表竖向分割线」),
   每列之间都有线、无需再写 nth-child。分组只需顶行 colspan 表达语义,不再靠"选择性画线"区分组。 */
```
- **列数守恒**:顶行 `Σ(rowspan 列 1 + colspan)` 必须 = 子表头列数 + rowspan 列数 = `tbody` 每行 `td` 数。算错一格整表错位。
- **组名行不参与「同列对齐」铁规**(它是跨列标签,一律居中);**子表头行才是真正的列**,数字列照旧右对齐 + 加粗(挂 `col-num`)。
- **表头文字同字号同色**(owner 口味):组标题(顶行)别做得比子表头更小更淡——统一一个 size + 一个 color,只靠居中/大写区分层级。
- **竖向分隔要"一条直线"且全列都有**(本版已升级为全表竖向网格,见上「全表竖向分割线」):① 全列竖线由全局 `th,td{border-right:1px solid var(--border)}` 统一负责,表头与表体**同色同宽**(都 `--border`,别上深下浅);② **模块带行 `.mod` 不要用整行 `colspan` 总列数**——否则那一行只有一个单元格、竖线在模块带处断开。正确写法:标签 `colspan="2"` + 其余每列各一个空 `<td>`,这样每列 `td` 自带的 `border-right` 都穿过模块带,竖线全程接通;③ **竖线颜色统一 `--border #e6e6e6`**,别用比表头底色(`--th`)还浅的 `--border-2`,否则在表头里"隐身"看着没连上表体;④ 分组语义只靠顶行 `colspan` 表达,**不再靠"选择性画线/线长"区分组**(每列都有线了)。
- 别过度分组:**只在列真多 + 组语义清楚时用**;5–7 列的表单层表头更干净,硬分组反而添乱。多级表头完整画法见金标准 [example-sto.html](example-sto.html) 的 33 项明细表。

### 行高焊死:别让表行被撑成竖排(低端模型最丑的塌方)
症状:某一行突然有别人 3–5 倍高,"订单量""示例省公司"被逐字竖排成一列。两个根因要同时堵:
1. **时间序列只用一列 sparkline,绝不拆成 N 列日期。** 7 天趋势 = 一个 100×28 的 sparkline 列,不要排成「5/20 5/21 … 5/26」七列。拆列 = 列爆炸 → 每列挤窄 → 中文逐字换行 → 行高失控。**同一张表里出现「趋势」sparkline 列 + 逐日期列 = 冗余且致塌,删日期列。**
2. **单元格默认 `white-space:nowrap`,中文永远横排单行。** 列多到放不下,就把 `<table>` 包进 `<div style="overflow-x:auto">` 横向滚动,**绝不靠竖排塞列**。个别确需换行的长文本列才单独放开。
可检验失败定义:任一数据行渲染高度 > 该表正常单行 ~2 倍 = 违规;出现中文逐字竖排单元格 = 违规。

## 异常呈现(默认平权陈述,不擅自抬成"主角")
**默认:平权陈述事实,不替数据下"这是问题"的定义。** 异常只**如实标注**(数值 + 目标/阈值并排,如「92.2% · 目标 93%」),与其他指标同级,不擅自放大成红色警报头条。
**仅当用户明确说**"排查异常 / 重点看问题"时,才前置、放大异常。没明说 = 异常和正常指标同一视觉权重。
可用的中性标注:目标/阈值并排呈现、`—` 占位缺口、必要时一条淡色块(`oklch(98% .03 25 / 50%)`)定位行——但**不默认用最大字号 + 最饱和红铺满去"压全场"**。
