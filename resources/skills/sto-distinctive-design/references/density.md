# Density

> 铁律在 SKILL.md 文末。这里讲密度、留白、节奏参数。

密度不是"塞多满",是**节奏**(见 craft-moves.md 手法 4)。被人调过的版面密度是**混合的**;AI 反射是全页一个 padding。

---

## 先分清:"信息密度"其实是三件事(别用一个词概括)

"密度高/低"常被当成一个问题,其实是三个**互相独立**的维度,解决手段各不同。混着说,就会"想加密度、结果加成了噪音"。

| 维度 | 回答 | 谁在解决 | 去哪 |
|---|---|---|---|
| **信息密度** | 塞多少(数据点数量) | 决策深度分配 · 单元上限 · 图形替数字 | **本文** |
| 信息层级 | 塞进去怎么分主次 | 字号落差 / 字重 / 留白 / 对齐 | structure-and-hierarchy.md · typography.md |
| 信息相关 | 每个数字有没有用 | 禁裸数字 · 每卡 ≥2 层 | data-presentation.md「指标卡 1主+N副」+ 文末地板 |

- **本文(density.md)只管第一件:塞多少。** 下面的「固定间距规格 / 混合密度」是用**留白**调密度;新增的「按决策深度分配」是从**整页**控总量。
- 另两件是**密度的副作用**、不是密度本身:塞多了会乱(→ 层级)、塞多了易塞废话(→ 相关)。**高密度能用的前提是三件都到位**,但别把它们混成一个词——"想让页面更密"时先问清是缺哪一件。

## 固定间距规格(锁定基线 —— 所有 HTML 产物适用,不限报告)
> 这是**硬规格,不是建议**。报告/dashboard/demo,以及 **Word/PDF/Excel/PPT 转 HTML**,一律按此值。别因为"这是文档转换、不是报告设计"就跳过间距/出血基线。低端模型最常见的"**标题与内容间距过大**",由这张表 + 下面那条核心规则根治。

> **默认值已按「信息曝光率优先」收紧(本文后段)**——数据报告/看板默认用下表的紧值;**只有纯叙事长文**(月度复盘、PDF/Word 长文转 HTML)才放宽到括号里的松值。

| 用途 | 数据报告锁定值(**唯一合法值,直接抄,别挑别的**) |
|---|---|
| body 上 / 下 padding | `16px` / `24px` |
| 侧边出血 | `clamp(12px,1.6vw,24px)`(**全页唯一允许的 clamp**;不居中、无 `max-width`) |
| 分节标题**上**间距(= 区块间) | `16px` |
| 分节标题 → **其内容**(标题下间距) | `8px`(= 上间距一半,比例固定) |
| `h1` → 下方内容 | `14px` |
| 结论区 / `.lead` 下 margin | `14px` |
| 卡片 / 容器间 `gap`(并排 & 堆叠,行列同值) | `12px` |
| 卡片 `padding` | `10px 12px 9px` |
| 表头 `padding` | `6px 10px` |
| 表格行 `padding` | `3px 10px`(行高焊死单行,见下「行高/列高极致收窄」) |
| **模块白底面板 `padding`(白底↔内容)** | `16px`(四周统一;面板内标题→内容仍 `8px`) |
| **模块白底面板之间 `margin`** | `12px`(同容器间距) |
| 区块与区块之间 | `14–20px` |

> **★模块白底面板(.mod / .sto-modpanel)**:间距规格见上表两行(面板 padding `16`、面板间 margin-top `12`、面板内标题↔内容仍 `8`)。**完整 CSS、白套白处理(内层转 transparent / 指标卡用灰底 .sto-greycard 分层)与用法见 [base.md](base.md)「模块白底面板」;组件见 sto-components.html #19/#20。** 可检验失败定义:**模块面板 padding ≠ 16px、或白面里再嵌白底卡(白套白)= 违规。**

> **★容器 / 卡片间距 = `12px`(STO 官方,容器 5669 横向 frame↔frame / 5670 纵向 frame↔frame)。** 并排卡、堆叠卡、并排面板、卡片网格的 grid `gap` **横列纵行统一 12px**,不再用旧的 6 / 8 / 10。注:这是"**容器之间**"的 gap,**不是容器内元素间距**(图标↔标题、圆点↔正文、标签↔数值、bar 行等内部间距仍按各自规格,别一刀切成 12)。

> **★禁双值裁量(根治"飘向松值"):上表每个用途只有一个合法值,数据报告/看板一律照抄。** 旧版给"(叙事可 X)"括号 = 给了模型逃生口,它每次都飘向更大的松值还自认合规——现已删除。**唯一放宽场景是纯叙事长文**(月度复盘、PDF/Word 长文转 HTML),且必须**整页统一**切到叙事档(不许逐块挑松值):body 上/下 `26`/`44`、分节上/下 `22`/`11`、卡 gap `10`、卡 padding `16px`、侧边出血 `clamp(16px,2.6vw,48px)`。**判不准是不是纯叙事 → 一律用上表紧值。**

> **★间距禁用 clamp(根治"撑满→自动放大"):`margin` / `padding` / `gap` / 分节间距一律写固定 px,禁用 `clamp()` / `vw` / `vh`。** 全页**唯一**允许 clamp 的是上表 body 侧边出血那一条。模型对"撑满屏幕"的反射是把间距写成 `clamp(28px,4vw,56px)` 把 16px 放大成 28–56px——**这就是违规**。"撑满屏幕"靠 `width:100%` + 满宽不居中实现,**不靠把间距 clamp 放大**。可检验失败定义:除 body 侧边出血外,任何 `margin`/`padding`/`gap` 出现 `clamp(`/`vw`/`vh` = 违规。

可直接抄的基线(★这段直接复制,间距值一个都别改):
```css
body{ padding:16px clamp(12px,1.6vw,24px) 24px; }  /* 满宽不居中、无 max-width;侧边出血是全页唯一允许的 clamp,上下用固定 px */
h1{ margin:4px 0 14px; }
.sec{ margin:16px 0 8px; }                           /* 上 16 下 8 = 2:1,标题贴紧内容;固定 px,禁 clamp */
.lead{ margin-bottom:14px; }
.cards{ gap:12px; } .card{ padding:10px 12px 9px; }   /* 容器间 gap 12px(STO 官方 容器5669/5670);卡内 padding 仍紧 */
thead th{ padding:6px 10px; } tbody td{ padding:3px 10px; line-height:1.35; }
/* 竖向分割线(table/th,td border-right + 最右缘 0)已在 base.md 锁定基线里,套基线即有,此处不重复;规则与失败定义见 data-presentation.md「全表竖向分割线」 */
```

### ★行高/列高极致收窄(锁硬规格 —— owner 取向:信息密度做到极致)
默认把行高/卡高压到"可读底线再收一档":
- **表格行**:`padding:3px 10px` + `line-height:1.35` + `white-space:nowrap`,单行高约 22–24px;>30 行的密表可再降到 `padding:2px 10px`。**禁止默认给表行留 8px+ 的上下 padding 撑高。**
- **卡片**:`padding:10px 12px 9px`,高度只够"主指标 + 1 行副指标",别让卡又高又空;**卡间 `gap:12px`(容器间距固定值,见上 STO 官方 容器5669/5670)**。
- **分节标题行**:`line-height:1.2`,上 16 下 8,别让标题行自带大行高顶出空当。
- **两条不可破护栏(收窄 ≠ 挤坏)**:① 字号不低于 base 最小档、行内不字贴字(收到看不清就回退一档);② 信息稀疏(<8 项)不强行收窄铺满(此项优先,见文末「信息稀疏禁紧凑」)。
- 可检验失败定义:**密表行高 > 26px(非稀疏数据却给表行留 8px+ 上下 padding)、或卡片高度明显虚高留大片纵向空 = 违规。**

**★核心规则(根治"标题浮空"):标题与它所标注的内容是一组,标题下间距必须 ≤ 标题上间距的一半。**
- 标题上方是"区块间"(数据报告固定 16px,纯叙事整页切档可 22px),标题下方贴的是它自己的内容(≤8px),比例固定 2:1;均用固定 px,禁 clamp。
- 可检验失败定义:**标题下间距 ≥ 标题上间距 = 违规**(标题浮在内容上方,看不出它在标注谁——这就是"间距过大"的根源)。
- 可检验失败定义:**body 侧边 padding > 48px、或设 `max-width`+`margin:0 auto` 致宽屏两侧留白 = 违规**。
- **出血唯一例外:纯叙事 / 阅读型长文正文段落**(月度复盘、**PDF/Word 长文转 HTML**)仍限行宽 35–50 字——**壳满宽,正文单独限宽**;表格/卡片/结论行照样满宽。(详见下「页面外壳」文末例外)

## 页面外壳:满宽出血(数据大盘 **和报告类** 默认,追求信息密度)
数据报表/大盘/日报/周报/复盘**都不要**像网页那样 `max-width:1100px; margin:0 auto` 居中——那会在宽屏两侧留大片空白,是"信息密度低、像营销页"的头号原因。**"报告类"不等于"阅读型长文"**:报告里的表格、卡片、结论行一律满宽,只有纯叙事正文段落才限行宽(见文末例外)。低端模型最常见的翻车就是**把报告整页套进一个窄容器,两侧留出大片留白**。
**默认满宽出血(报告类同样适用):**
```css
body{ padding:16px clamp(12px,1.6vw,24px) 24px; }   /* 曝光优先:不设 max-width、不居中,内容铺满视口宽;四周收紧到最小,别留宽屏侧白(叙事长文放宽,见「信息曝光率优先」) */
```
- 侧边出血曝光优先 12-24px(窄屏降到 12px),上下 16/24px,**不留宽屏侧白**;留白靠内部节奏(混合密度 + 唯一签名时刻)做,不靠把整页推窄或四周留宽边
- 可检验失败定义:**页面设了 `max-width` + `margin:0 auto` 导致宽屏两侧出现大片留白 = 违规;侧边 padding > 48px = 违规**
- 表格 `width:100%` 自然铺满;KPI 卡用固定列数 grid(`repeat(4,1fr)`/`repeat(5,1fr)`)铺满整行,而非 auto-fit 在宽屏只占左侧
- **每个分组(业务量/成本/时效…)的卡片行都要满宽适应**:用 `grid-template-columns:repeat(N,1fr)`,卡片 `1fr` 等宽拉伸**铺满整行**。**只有 2 张卡时也用 `repeat(2,1fr)` 各占 50% 撑满**,别让两张卡挤在左边、右侧留空。失败定义:某卡片行未铺满页宽、右侧留大片空 = 违规(尤其分组里只有 2-3 张卡时最常翻车)。

### ★每行放几张:先算留白,再定列数(卡片占多行时尤其要做)
满宽只解决"横向不留侧白",但**每行塞几张**还得按留白平衡——目标是**信息密度均衡、不留尴尬空当**。规则:
- **★每排卡片数下限 = 4 张(owner 硬规则)**:总卡数 ≥4 时,**每排列数 ≥4**,禁 2 列(2×2)/3 列这种稀疏排法——卡太少每张会被拉得过宽、显空旷廉价。**总卡数 <4(2–3 张)才全放一排**(此时按上「满宽适应」用 `repeat(N,1fr)` 撑满)。下面所有「减列吃留白 / 选能整除 N 的列数」都在 **列数 ≥4** 的前提下做。**例外:核心结论层的诊断/结论卡按 `conclusion-layer.md` 自己的规则(≤3 条可 3 张并列),不受本下限约束**;本下限针对的是指标卡 / KPI 卡 / 概览卡这类网格。
- **卡片占多行时,先看留白**:若按当前列数排下来,**每张卡内留白很大**(内容少、卡很空)或**末行落单**,可适当减少列数让卡更宽——但**减到 4 列为止,不再往下**;若 4 列仍留孤儿(如 7=4+3、9=5+4),接受末行不满或改单行铺满,别为了凑整除而破 4 列下限。
- **判断依据是"卡内容的体量"**(在 ≥4 列前提下):内容多(数字+图+口径)→ 可多列;内容少(就一个数字+标签)→ 收到 4 列、让卡变宽别空旷,但不低于 4。
- **★卡片数已知时,用固定列数排成"均衡满行",别用 `auto-fit` 让它自己排(实测翻车:6 张被排成 5+1 孤儿行 + 大片留白)。** `repeat(auto-fit,minmax(280px,1fr))` 会在宽屏尽量塞满列,导致末行落单。**已知 N 张,在「列数 ≥4」前提下选让行均衡、末行最满的列数:**
  | 卡片数 N | 选列数 → 排布 |
  |---|---|
  | 4 | 4 列(1 行) |
  | 5 | 5 列(1 行) |
  | **6** | **6 列(1 行)**(不用 3+3,每排 ≥4) |
  | 7-8 | 4 列 → 4+4 / 4+3 |
  | 9 | 5 列 → 5+4(不用 3×3,每排 ≥4) |
  | 10-12 | 4 列 |
  原则:**在「每排 ≥4 列」前提下,优先让每行填满、末行不留孤儿(4+4、5+4、6 整行)**;整除不了就选末行最满的。
- **可检验失败定义**:**①任何一排卡片列数 <4(总卡数 ≥4 时)= 违规(2×2 / 3+3 / 3×3 都算);②已知 N 张卡却用 auto-fit 排成末行只剩 1-2 个的孤儿行 + 大片留白 = 违规;③某行卡片明显比内容所需宽很多、内卡大片留白 = 违规**(在 ≥4 列前提下减列让卡变宽,或选末行最满的列数)。
- 例外:纯叙事/阅读型长文(月度复盘)正文行宽仍受 35-50 字限制,可在满宽壳内给正文单独限宽,但表格/卡片照样满宽

## ★信息曝光率优先(默认追求:首屏尽可能多真实信息)
> 本 skill 的默认数据报告/看板**追求极致的首屏信息曝光率**——首屏(不滚动)尽量多承载真实信息。**这是 owner 的明确取向,默认就按它来**,不必等用户再提。它**压紧基线密度**,但不取消下面「混合密度/签名时刻」的相对节奏。

**做法:把"非内容空间"压到最小,让内容铺满。**
- **★出血/边距压到最小(首屏的头号变量)**:body 顶 `16px`、侧边 `clamp(12px,1.6vw,24px)`、底 `24px`(满宽不居中不变,只是把四周空白收紧)。区块间距 / 分节标题上间距压到 `~16px`(**标题下间距仍 ≤ 上的一半,比例不变**)。**目标:首屏看到 结论 + 概览 + 第一块明细的表头与前几行。**
- **整体走极紧凑 / 紧凑档**(见下「密度档位」):卡 padding `12px`、**卡 gap `12px`(容器间距固定值,不随档位变)**、表行 `4–7px`。
- **★图表 / 卡片高度极致压缩(首屏塞更多的关键)**:
  - **KPI / 指标卡**:砍掉多余纵向 padding,一张卡的高度**只够"主指标 + 1 行副指标"**,别让卡又高又空。
  - **趋势 / 面积图卡**:压到 ~一行标题 + 一条 `80–100×28` 的 sparkline 级,别做大图;确需大图的留到滚动区。
  - **环 / 饼**:直径压到刚好放下中心数 + ≤5 块,别占一大块方形区。
  - **表格**:行高焊死单行(`white-space:nowrap`)、行 padding 取 `4–6px` 档。

**两条不可破护栏(压缩 ≠ 做坏):**
1. **可读性地板**:压缩有底——正文/表格字号不低于 base 最小档、sparkline ≥ `80×24px`、图表仍看得清、表行不挤到字贴字。**压到看不清就是过头,回退一档。**
2. **不伪造填充**:曝光率是"首屏多塞**真实**信息",不是把稀疏数据拉伸铺满。**信息稀疏(<8 项)时仍禁强行紧凑铺满**(地板项)——那时让信息有呼吸,别假装很满。

**与「混合密度 / 签名时刻」的关系(别误读成"全页一个紧 padding"):** 曝光优先把**基线压紧**,但**仍保留唯一那处签名时刻 / 结论块的相对呼吸**——它只占一点纵向空间,却是"不像通用 AI 密集看板"的关键。即 **到处都紧、唯独主角处相对透**:疏密对比变克制,不取消。可检验失败定义:**①图表/卡片高度明显虚高、留大片纵向空,首屏塞不下本可塞下的信息 = 违规;②body 四周/区块间留通用基线那么大的空(顶 26+、区块间 22–32)而非曝光优先紧值 = 违规(除非是纯叙事长文);③通篇等紧、连签名处都不留任何相对呼吸、糊成一坨无重点 = 违规(另一个方向的翻车)。**

## 信息密度按"决策深度"分配(整页控总量:越下结论越聚合,越查证据越密集)

密度不是均匀铺的,跟着**内容的用途**走:越靠近"下结论"越聚合(一个数字顶一屏),越靠近"查证据"越密集(一行一条原子记录)。**先按这张表给各层分配密度配额,再往层里填内容**——这是控制全页信息总量的总闸,和「结论先行」的信息架构(structure-and-hierarchy.md)是同一根脊柱的两面。

| 层 | 角色 | 信息密度 | 上限 |
|---|---|---|---|
| 结论 / 指标卡 | 下结论 | 高(但每单元封顶) | 单卡 ≤5 数据点(见 data-presentation.md「1主+N副」) |
| 一排卡 | 横向对比 | 中 | 4–8 张/排(排布见上「每行放几张」) |
| 图表 | 解释结论 | 中 | 双轴 ≤2;环/饼中心 1 个汇总数、≤5 块 |
| 明细表 | 查证据 | 极高 | 列数不限,纵向密度靠分页卸载(见 data-presentation.md 行高/列爆炸) |

- **方向规律**:从上到下,单个单元承载的信息量递增、聚合度递减。指标卡是"已经替读者算好的结论",明细表是"原始证据"。两端密度都可以很高,但**高的方式不同**:指标卡靠"少而精的聚合值",明细表靠"多而齐的原子行"。
- **可检验失败定义**:**①把明细级密度(一格塞 8–12 个并列值)搬进结论/指标卡层 = 违规(结论层该聚合,不该堆原子数据);②整页只有一种密度(全是密表 or 全是疏卡)= 违规(没有按决策深度分配,退回"全页一个 padding"的 AI 反射)。**

## 密度档位
| 档 | 卡片 padding | 表格行 padding | 字号 |
|---|---|---|---|
| 极紧凑(默认基线) | 10px | 2-3px | 12-13px |
| 紧凑 | 14-16px | 6-7px | 13px |
| 正常 | 20-24px | 10-12px | 14px |
| 通透 | 32-40px | 14-16px | 15-16px |

选择:
- **默认追求信息曝光率 → 极紧凑/紧凑为默认基线**(见上「信息曝光率优先」)
- 数据密集(日报/周报/KPI/大盘)→ 紧凑/极紧凑
- 分析型/编辑型/月度 → 正常/通透
- **信息稀疏(< 8 项)→ 禁紧凑**,在正常/通透间选,让信息有呼吸感,别硬铺满(地板项;此项**优先于**曝光率优先——没那么多真实信息就别假装塞满)
- Demo/原型 → 自由

## 混合密度(推荐——这就是节奏)
数据页常用:
- 表格**密**(行 8px,行高 1.4)——美在信息密度和对齐
- 卡片/结论区**透**(24-40px,大量留白)——留白把视线推向重点
- 密透交替本身制造节奏,也暗示重要性

**自查**:如果全页一个 padding 值 → 还没"设计",只是在"填充"。

## ★内容少的模块并排一行(锁硬规格 —— 治"一个小模块独占整行、右侧大片留白")
**当一个模块内容很少**(如只有 2–3 个指标、一张 ≤4 行的小表、一段短结论、一个小环图),**别让它独占一整行横铺**——它撑不满页宽,右侧会拖出一大片尴尬留白(浪费曝光,违反信息曝光率优先)。**把多个这类"半幅以下"的模块用 grid 并排到同一行**,各占一栏,把横向空间吃满。
- **判断依据**:模块的自然宽度 < 页宽 60% 且内容无法再扩 → 它是"半幅模块" → 找另一个半幅模块拼到同一行。
- **做法**:外层 `display:grid;grid-template-columns:…;gap:14px`,按内容体量分配栏宽(等量 `1fr 1fr`,不等量如 `1.4fr 1fr` 或 `2fr 1fr`)。**两个并排模块各自仍是独立模块(各有自己的分节标题),不是把它们塞进一个框**(否则触发框中框,见 structure-and-hierarchy.md)。
- **典型可并排组合**:小结论 + 小 KPI 组;占比环图 + 它的图例/明细小表;一个小趋势卡 + 一段口径说明;两个各 3–4 项的分组卡。
- **例外**:明细大表、需要横向滚动的宽表、信息稀疏需呼吸的内容 → 不并排,独占整行。
- 可检验失败定义:**①一个内容明显撑不满页宽的小模块独占整行、右侧留大片空,而页面里还有别的小模块可与它并排 = 违规(浪费空间);②为并排而把两个模块塞进一个带边框/底色的大容器 = 框中框违规。**

## ★模块动作收进标题行 + 短摘要横向铺(治"动作独占一行、摘要逐行堆叠的留白")
同一根脊柱(信息曝光率优先、不浪费空间),管两类高频留白翻车。**来源:STO 总部对账·异常波动监控模块实测(owner 2026-06-10)。**

**A · 模块级动作放分节标题行最右,别独占一行 toolbar**
一个模块的操作入口(下载全部明细 / 导出 / 查看更多 / 筛选)若单独占一行右对齐的 toolbar,白白吃掉一整行竖向空间、且该行左侧全空。**改放到该模块分节标题 `.sec` 那一行的最右端**——一行同时承载「标题 + 计数 + 动作」,标题左、动作右。
- 做法:`.sec{display:flex;align-items:center}` + 动作 `margin-left:auto` 推到最右(`.sec .dl-link{margin-left:auto}`)。
- 失败定义:**模块的动作按钮/链接独占一整行(该行只有一个右对齐按钮、上下都是该模块内容)= 浪费竖向空间 = 违规**;能并到标题行的动作却另起 toolbar 行 = 违规。

**B · 一组并列短摘要别逐行满宽堆叠,用「自适应多列」横向铺(别写死列数)**
一组并列的短状态摘要(如「重点关注 N 项 / 轻微波动 N 项 / 正常 N 项」这类汇总条),若每条 `<br>` 各占满宽一行,**每行右侧拖一大片留白、整块还很高**。**改用自适应 grid 横向铺**,让它跟着容器宽度走:**全宽屏能塞几条塞几条**(放得下 3 条就 3 条一排),**窄屏自动降到 1 条/行**——**别写死 2 列**(写死会出现"全宽屏明明放得下却还在换行"的浪费)。
- 做法:`display:grid;grid-template-columns:repeat(auto-fit,minmax(240px,1fr));gap:6px 24px`。`minmax` 的 min(每条最小可读宽,~220–260px)决定一排放几条:容器够宽就多放,不够就自动换行/降列,直到 1 条。
- **落单项免手动 span**:`auto-fit + 1fr` 下末行落单的那条会自动拉伸填满整行、不留半行空——所以**别再加 `grid-column:1/-1`**(加了反而会在全宽时让它霸占整排)。
- **★这里能用 auto-fit、和「指标卡禁 auto-fit」不冲突**:卡片禁 auto-fit 是因重视觉卡要均衡行、孤儿行难看(见上「★每排卡片数下限」);**短文字摘要是轻量行,要的就是随宽度自适应、落单自动撑满,auto-fit 正合适**。摘要也**不受「每排 ≥4 卡」下限约束**(那条只管 KPI/指标卡)。
- **条间加竖分割线(「指标组合」画法,源 ~/Desktop/指标组合.pdf)**:同排相邻两条之间画一条浅色竖线分隔(`1px var(--border)`),**首条不画、末条右侧不画**(只画相邻之间,不是每条都包边)。做法:列间 `gap` 归 0 改用线 → `gap:6px 0`;每条 `.ms-item{padding:1px 24px;border-left:1px solid var(--border)}`,**首条 `:first-child{border-left:none;padding-left:0}`**;**窄屏堆叠时去掉竖线**(媒体查询里 `border-left:none;padding:1px 0`,堆叠的条画左竖线很怪)。⚠ auto-fit 下若中间宽度恰好换成 2 列,第 2 行行首那条会带一条多余左竖线(纯 CSS 无法识别"换行后的行首")——要竖线绝对干净就改"按断点定死列数"(`@media` 切 1/2/3 列)再用 `:nth-child(列数·n+1){border-left:none}` 精确去掉每行行首线。一般报告全宽=单排、窄屏=堆叠,中间 2 列只是窄窗口,可接受。
- 失败定义:**①一组 ≥2 条的短摘要逐行满宽 `<br>` 堆叠、右侧大片留白 = 违规;②写死固定列数(如永远 2 列)导致全宽屏本可一排放下却仍换行 = 违规;③给 auto-fit 的末条又加 `grid-column:1/-1`、害它全宽时霸整排 = 违规;④加竖分割线时给首条/末尾也画线(每条包边)、或堆叠态仍留左竖线 = 违规(只画相邻之间)。**

**C · 模块标题右侧的内联统计组(标题左 / 统计右),换行后要贴左紧排、别浪费空间**
模块标题(`.sec`,如「服务异常明细 · 41 客户」)右侧常挂一组分布统计(如「揽件<95% 31 75.6% · 滞留>2% 8 19.5% · 错分 7 17.1% · 工单 3 7.3%」)。宽屏时标题左、统计右一行放下;窄屏一行放不下要换行时,**统计组整组掉到标题下一行、并贴左用竖分割线紧排**——能一行放下就一行放下,别让每条各占一行、右侧拖留白。
- **结构**:标题与统计组是 flex 兄弟,外层 `display:flex;flex-wrap:wrap;justify-content:space-between;align-items:baseline;gap:8px 16px`。`space-between` 让宽屏标题左/统计右;窄屏换行后每行只剩一项(标题独占一行、统计组独占一行),`space-between` 对单项即 `flex-start`——**统计组自动贴左,不会被推到右边**(这正是关键:别给统计组写 `margin-left:auto`,那样换行后它会黏在右边继续浪费左侧)。
- **统计组内部**:自身也 `display:inline-flex;flex-wrap:wrap;align-items:baseline`,每条 `.st{padding:0 12px;border-left:1px solid var(--border);white-space:nowrap}`,**首条 `:first-child{border-left:0;padding-left:0}`**——竖分割线只画相邻之间。条内 `标签(text-3) + 数值(num/600) + 占比(text-3)` 用 `gap:4px` 贴合。这样换行后整组在自己那行能塞几条塞几条、塞不下才再折行,绝不每条独占一行。
- 具体可抄实现见 sto-components.html「模块标题 + 右侧内联统计组」(`.sechead` / `.sec-stats` / `.st`)。
- 失败定义:**①标题右侧统计组换行后仍黏右边(用了 `margin-left:auto`)、左侧留白 = 违规;②换行后每条统计各占一行(没横向 wrap 紧排) = 违规;③统计条之间用大 `gap` 撑开而非竖分割线紧排、本可一行却折多行 = 违规。**

## Spacing 节奏(不等距才有节奏)
序列:`4 / 8 / 12 / 20 / 32 / 48`(相邻 ~1.5-2x)
分配:元素内 < 组件内 < 组件间 < 区块间
- 例:数字↔单位 4px,卡内行间 12px,卡间 20px,大区块间 22–32px(通透型可到 48px)
- ⚠ "区块间"指**区块与区块之间**,**不含"标题↔它的内容"**——后者是"组件内",必须贴紧(≤11px),见上「固定间距规格」核心规则。序列里的大值(32/48)别套到标题下方。
- **★但"贴紧 ≤11px"只管 section 小标题(~14px)↔ 它的内容;整体/masthead 大标题(H1 ≥24px)↔ 它的副标题/deck 要松一档**:大字(28px 粗)配 ≤12px 小间距会显挤、压得慌,**给到 ~16–20px**(约标题字号的 0.6–0.7×,随标题放大而放大)。这俩别混:小标题配内容要紧、hero 大标题配副标题要透气。**失败定义:H1 ≥24px 的大标题↔副标题间距 ≤12px、显拥挤 = 违规**(来源:STO 监控金标准 masthead 实测,owner 2026-06-10,`.mh-title .sub` 12→20)。
  - **⚠️ inline 陷阱(必查):副标题若是 `<span class="sub">`,span 是行内元素、`margin-top` 被浏览器忽略——你把 margin-top 从 10→20 调多大都没用,渲染出来永远贴着 H1 的行高。必须给 `.sub` 加 `display:block`(或 inline-block) margin-top 才生效。金标准实测就栽在这:span 上调 margin-top 看似无效。修法 `.mh-title .sub{display:block;margin-top:18px}`(28px H1 → 18px ≈ 0.65×)。失败定义:副标题用 inline 元素 + 只调 margin-top 没加 display = 间距永远不生效(来源:owner 2026-06-10)。
- **禁全页 16px / 全 gap 8px**(AI 默认值)

## 留白原则
大块留白用在视觉锚点周围;紧凑区可零留白堆叠。**节奏才有可读性**——别"四处都留白"也别"四处都不留白"。
