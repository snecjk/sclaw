# Color

> 铁律(禁 #000/#fff、状态色饱和度等)在 SKILL.md 文末。这里只讲色彩**策略**和参数。

色彩是**最后 20%**。在动颜色之前,确认结构、层级、节奏、细节已经立住(见 craft-moves.md 的灰度测试)。颜色用来**强化已经成立的层级**,不是用来**掩盖薄弱的结构**。

---

## 先破一个误解:出彩 ≠ 用色多

模型最容易犯的错:把"大胆/出彩"等同于"大色块 + 撞色 + 满屏饱和"。
**真正的大胆是"敢把一处做到饱和,同时敢把其余全部留白"**——后半句更难。
所以下面四档里,**多数数据报表的最佳解是"克制地大胆"**:中性为主 + 一处精准的高饱和强调,而不是整页铺色。

---

## 四个色彩档位

每档绑定背景 + 强调策略 + 适用场景。**默认偏向有表现力的方向(C),但 C 有两条路:铺色的、和克制的。**

### A · 数据严肃
```
背景    oklch(98% .005 85) 暖白 / oklch(97% .003 240) 冷白
强调    chroma .15-.25,单色,占面积 ≤10%,只点睛
中性    向品牌色相微调 chroma .005-.01
```
适用:数据 >30 行、表格主导、监控类、多维度对比。气质:克制、数据为王。

### B · 编辑克制
```
背景    oklch(94-96% .03-.06)  米色/淡杏/淡灰蓝/淡橄榄
主色    单色相 chroma .08-.15,占面积 20-30%
字体    serif display + sans body(编辑感)
```
适用:月报、深度分析、阅读型、季度复盘。气质:杂志感、严肃而温暖。

### C · 有表现力(默认)★ — 但有两条路

**这是默认档,因为它把出发点抬到"被设计过",而不是回退到训练集均值的浅灰。**
但 C 不等于无脑铺色。先判断你这次属于哪条路:

> ✅ **本 skill 默认强调色就是申通橙 `#FF6700`**(owner 定为默认风格,base.md 已锁)——焦点用申通橙、结构用冷灰近黑 `#1d2129`、**链接/次操作/下载也用申通橙(品牌交互色,owner 2026-06-18 定)**;辅助蓝 `#005be5` 退出链接角色,**只作图表对比/进度条第二色**。申通橙做**数据强调**时仍是全页唯一克制焦点,只点睛(结论卡/关键标记/关键 sparkline),别铺满 30 行明细表;做**可交互元素**(链接/下载)时是品牌惯例、与数据强调橙统一,不算"铺满"。STO 是本 skill 唯一风格,不切换、不套别的品牌。

**C-1 · 克制的出彩(数据密集场景的 C)** ← 多数报表走这条
```
背景    中性(暖白/冷白/极浅色),克制
强调    一处高饱和(chroma .15-.22)精准爆发 + 其余全部安静
出彩来源   字阶张力、严整对齐、节奏、细节完成度(见 craft-moves.md)
```
适用:KPI 看板、运营周报、20-40 行数据 + 多个指标——**既够不到 A 的"纯严肃",又不该被大色块挤掉信息空间。**
> 这条路解决了原版 skill 的盲点:别给数据密集的报表套饱和大色块,那会牺牲可用性,变成"用力过猛"的新 AI 味。
> **★强调色相默认 = 申通橙 `#FF6700`(暖区 hue~30,克制点睛、非铺色)。** base.md 默认 `--brand:#ff6700` 就是这个取向,结构色另走冷灰近黑 `--accent:#1d2129`。**避开冷蓝/靛蓝(hue 215-275)做焦点/趋势色:那是最常见的"AI 编辑系反射"色,用户反复否决——唯一例外是 STO 辅助蓝 `#005be5`,且只作**图表对比/进度条第二色**,不当焦点/趋势亮点、也不作链接色(链接走橙)。** 状态色(绿/黄/红)只在表达达标/未达时出现,不当强调色用。
>
> **★进度条 / 双色对比 = 分类色,不是语义色(owner 2026-06-10)。** 进度条(达成/占比/率值条)填充**只区分"是哪条数据",不表达好坏**,不要按达标/未达染绿红。取色:**①单条数据(单色)→ 首选申通橙 `#FF6700`;若同页申通橙已过多 → 改辅助蓝 `#005be5`。②两条数据对比 / 折线+柱组合 → 橙 + 蓝两色(惯例:折线橙 `#FF6700`、柱蓝 `#005be5`,stoCombo 默认已是此配)。** 达标与否靠**条旁的数值/标签**表达,不靠条色。⛔ 图表/卡片等**非表格**进度条按达标/未达把填充染绿/红 = 违规。
>
> **★例外:表格内进度条(`.sto-table .databar`)走语义色,且仅限表格(owner 2026-06-11)。** 条旁率值为**绿色语义(达标/正向,`.databar.up`)时,条填充也用绿 `#B3F2C5`**;否则用橙 `#FFE4E0`。`#B3F2C5` / `#FFE4E0` 这两个进度条色值**只在表格中采用**——图表、卡片、`.sto-barlist`、`.sto-prog` 等非表格进度条仍按上面的分类色(橙 `#FF6700` / 蓝 `#005be5`),不受影响。横条「分布」列表 `.sto-barlist` 按风险状态分级,属另一类,不受此约束。

**C-2 · 铺色的出彩(表现力优先场景的 C)**
```
背景    大色块 oklch(60-75% .15-.20) 占 40-70% / 或分屏对撞(两色相 ≥60°)
主色    占面积 30-60%,是画布不是装饰
反差    1-2 个高对比强调点
字体    display 加重 48-72px + 编辑感开篇
```
适用:Demo、原型、品牌型报告、汇报演示、单焦点页——**信息密度低、表现力优先**时才走这条。
C-2 专属允许(其他档禁止):大色块作画布、分屏对撞、渐变背景(仅背景)、巨型 display 字、不对称出血排版。

### D · 暗色严肃
```
背景    oklch(15-22% .02-.05) 深底
文字    oklch(92-96% .005 同色相) 高对比
强调    chroma .10-.18,占面积 ≤15%
```
适用:运营大盘、监控屏、暗色仪表盘。气质:工业、专注、久盯不刺眼。

## 怎么选档(判断顺序)

1. 用户指定档位/风格关键词("杂志感"→B,"严肃/数据多"→A,"大胆/出彩"→C,"暗色/大屏"→D)→ 直接用
2. 数据 >50 行 / 表格主导 / 用户明说"严肃" → A
3. 数据密集但有指标卡、想要质感(典型周报/看板)→ **C-1(克制的出彩)**
4. 信息密度低、表现力/汇报优先 → C-2(铺色的出彩)
5. 暗色/大屏诉求 → D
6. 拿不准 → C-1。它在"够不到 A 的严肃"和"用不上 C-2 的张扬"之间,是数据报表最稳的高质量解。

## OKLCH 基本规则

- 接近 L=0 或 L=100 时降 chroma(两端高 chroma 发腻)
- 所有中性色向品牌色相微调 chroma 0.005–0.01(避免冰冷死灰)
- 同色相内:L 调亮度,C 调饱和度
- CSS 变量定义一次,全文 `var(--color-xxx)`,不散写 hex

## 中性色阶梯参考(向品牌色相微调后用)
| 用途 | 大致 L |
|---|---|
| 主文本 | 15-22% |
| 次文本 | 40-45% |
| 辅助文本 | 60-65% |
| 边框 | 90-94% 或 `rgba(0,0,0,.08)` |
| 卡片背景 | 98-99% |

## ★禁高饱和度卡片(锁硬规格 —— 卡片背景必须中性浅色)
**卡片的背景/顶条禁铺高饱和色块。** 卡片背景一律走中性浅色(`L ≥ 96%`、`chroma ≤ 0.03`,即上「卡片背景 98–99%」那档),禁止用饱和强调色/状态色给整张卡灌底。
- **强调放在"卡内一个点",不是"整张卡的底色"**:要表达状态/重点,用一个小色点、一个小胶囊标签、或把一个关键数值上色——不靠把卡背景做成高饱和色块去抢眼(那是 C-2 铺色页才允许的画法,数据卡不用)。
- **顶条**:若用 2px 状态顶条,颜色可语义化但只占 2px,不蔓延成整卡底色。
- **★禁彩虹卡边框(最典型 AI 仪表盘签名)**:**绝不能"每张卡一条不同颜色的顶边/左边"**——`.kpi-card.brand{border-top:橙}` / `.green{border-top:绿}` / `.red{红}` / `.blue{蓝}` 这种橙绿红蓝四色边,是 AI 生成物的视觉签名,一眼假。STO 的 KPI/指标卡**统一中性**(微灰底 `#FAFBFC` + 1px 中性描边,照抄金标准 `.mc`),好坏靠**卡内语义色 + 状态标签**承载,不靠卡边颜色编码;全页**唯一允许染色的卡 = 那个异常主角**(淡红底 `.mc.focus`,只此一张)。可检验失败定义:**同一组卡的 `border-top`/`border-left` 出现 ≥2 种不同强调色 = 违规(linter 检查 7c·P0 已抓)。** 单一语义顶条(全组同色、≤2px)不算违规;每卡换色才是。
- 例外:仅 C-2「铺色的出彩」(Demo / 原型 / 汇报封面 / 单焦点页)允许大色块作画布——数据密集报表(C-1 / A)一律禁。
- 可检验失败定义:**数据报表里卡片背景是高饱和填充色块(chroma > 0.03 或 L < 96%)= 违规。**

## 状态语义
- 状态色饱和度 ≥60%,且必配形态编码(图标/方向/位置),不只靠颜色
- 只用 3 个(success/warning/danger),多了乱

## ★dir 标记接口(物流数据用 —— 本 skill 只配色,不判方向)
> 物流指标的「方向」由判断层 [logistics.md](logistics.md) 给出(标在内容里),**本 skill 不自己判断哪个指标 ↑好↓坏**,只消费 `dir` 标记配色。根治"签收率下降配绿、成本上升配绿"。

| 内容里的 `dir` | 配色(含强化负向/降噪正向)| 现有金标准 class |
|---|---|---|
| `dir=bad`(向坏/异常)| 实强调红 + 状态标签,**显眼**(强化负向)| `.bad` / `.r` |
| `dir=good`(向好)| 文字绿即可、**不抢戏**(降噪正向,非必要不用绿色色块)| `.good` / `.g` |
| `dir=flat`(无方向/单量类)| 中性色,不上红绿 | 默认 |
| `dir=unknown`(缺方向)| 中性灰,**禁猜** | 默认 |

- **强化负向、降噪正向**(STO 官方取向):一页里红比绿显眼是对的;正向项别用饱和绿块抢视觉。
- **平权不变**:`dir` 只决定颜色,**不放大字号/不立 hero**(见 logistics.md 铁律 2)。
- 可检验失败定义:**①内容无 `dir` 标记却给指标自行猜配红绿 = 违规(走中性);②把 `dir=good` 做成饱和绿色块抢过 `dir=bad` 的红 = 违规(降噪正向)。**

### 蓝色的唯一合法用途:功能语义色(豁免禁冷蓝)
全局禁冷蓝/靛蓝(hue 215–275)指的是**禁拿蓝当主题强调色 / 趋势亮点色**(owner 反复否决)。**但消息提示 / 流程标签的"普通信息=蓝"是功能语义色,豁免**(STO 官方:普通蓝·成功绿·警告黄·错误红;流程标签 灰→蓝→绿→橙→红)。
- 可检验失败定义:**把蓝当 `--accent`/趋势线/卡片强调色 = 违规;消息提示/流程标签里 info 用蓝 = 合法。**

## ★正负向语义色:施加在哪、强度多大(STO 官方《颜色语义》《使用在表格上》)
`dir=bad` 红 / `dir=good` 绿 不只是给文字上色——按数据形态有 **5 种载体**,**强度靠"色块面积"控制**(面积越大越强化)。默认走降噪,强化只留给单个异常主角。

| 载体 | 用法 | 强度档 |
|---|---|---|
| ① 文字色 | 数值/环比文字染红绿(最常用)| 降噪 |
| ② 整卡背景(淡)| 指标卡淡红/淡绿底(混≥55%白调淡)| 降噪 |
| ③ 单元格底(淡)| 表格某格淡红/淡绿,标语义 | 降噪 |
| ④ 可视化列条底 | 表格数值列加背景条:越大越好→绿、越大越坏→红 | 中 |
| ⑤ 双色阶梯度 | 网点考核类多行,正向绿阶/负向红阶分等级 | 中 |
| (强化)整格/整卡填满饱和色 | **仅单个异常主角**,非特殊慎用 | 强化 |

- **默认降噪、强化限主角**:`dir=good` 一律走降噪(文字绿或淡底),`dir=bad` 默认也降噪、**只有"全页唯一那个异常主角"才允许强化版**(整格/整卡填满饱和)。这与「禁高饱和卡」一致——降噪版的淡底不算违规,强化版整格填色只此一处。
- 可检验失败定义:**①正向 `good` 用了强化版饱和绿块 = 违规(正向永远降噪);②强化版填色出现 ≥2 处 = 违规(只留单异常主角);③可视化列/色阶把"越大越坏"的指标配成绿 = 违规(方向反了,查 logistics.md)。**

## ★状态/流程标签色序(STO 官方《使用在卡片容器上》)
功能标签按流程推进取色:**灰(未开始/失效)→ 蓝(进行中/普通)→ 绿(已完成/成功)→ 橙(即将过期/警示)→ 红(失败/错误)**。蓝在此为合法功能色(见上「蓝色豁免」)。
- 标签用"浅底+同相深字"的胶囊,不用高饱和实心块铺大面积。
- 可检验失败定义:**流程标签配色跳脱该色序(如"已完成"配红、"失败"配绿)= 违规。**

## 反射自查(A/B/D 档生效;C 档反过来问)

A/B/D 档自问:**"这配色能从输出物类型直接猜到吗?"**(风险→整页红、科技→深蓝紫渐变 → 能猜到就重选)。**注:申通橙白灰是本 skill 已锁的默认风格(owner 主动选定),不在"能猜到就重选"之列——默认就该是它。** 这条只防"未指定风格却滑进类型联想"的其他档。

C 档自问相反:**"这配色是不是又缩回了 SaaS 安全区(浅灰/暖白/蓝白)?"**(是 → 至少把那一处强调做得更果断;C-1 也要有一处真正饱和的爆发,而不是通篇淡灰)
