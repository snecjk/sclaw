## Why

当前“上传技能”弹窗的拖拽区域可以接收技能文件和技能文件夹，但在 Windows 上点击该区域后，系统选择窗口一次只能处于“选择文件”或“选择文件夹”模式。界面没有给出明确入口，用户既不容易理解文件与文件夹的区别，也无法通过点击完成两种来源的选择。

## What Changes

- 按交互稿仅扩展上传弹窗下半部分，保留现有标题、上传说明、关闭按钮和拖拽区域的布局与行为。
- 拖拽区域继续同时接收 `.zip`、`SKILL.md` 和包含 `SKILL.md` 的技能文件夹，并在拖入后自动识别来源；不得重写或削弱现有拖拽事件、路径获取、校验和错误反馈行为。
- 在拖拽区域下方增加“或选择”分隔线及两个独立操作项：
  - “选择技能文件”：打开系统文件选择窗口，支持选择 `.zip` 或 `SKILL.md`，显示“推荐”标识。
  - “选择技能文件夹”：打开系统目录选择窗口，支持一次选择一个或多个包含 `SKILL.md` 的技能文件夹。
- 两个操作项均提供图标、标题、辅助说明和右侧箭头，并支持鼠标与键盘操作。
- 文件选择、文件夹选择和拖拽完成后，继续进入现有的校验、预览、上传及错误反馈流程；多选目录先全部校验，确认后按选择顺序逐个上传并展示进度，新增点击入口不得改变任何原有单项上传状态及结果。
- 新增区域同时适配深色和浅色模式，并遵循 `docs/sto-design.md`：推荐标识使用 Brand 语义，标题、辅助文字、图标、边框、背景、悬停和聚焦状态使用对应的 Text、Border、Fill 与交互状态 Token。
- 不尝试修改 Windows 原生选择窗口实现，不引入 native addon，不改变单个技能上传接口和数据格式；批量目录上传通过复用既有单项上传能力完成。

## Capabilities

### New Capabilities

- `skills-upload-source-selection`: 定义上传技能弹窗中“统一拖拽 + 文件选择 + 文件夹选择”的可见交互和跨平台行为。

### Modified Capabilities

- 无。

## Impact

- 影响上传技能弹窗组件、相关国际化文案及交互测试。
- 复用现有 Electron 对话框能力：文件入口使用 `openFile`，文件夹入口使用 `openDirectory`；Renderer 继续通过项目既有 host API/预加载边界调用，不新增页面或组件中的直接 IPC 调用。
- 复用现有技能校验、预览和上传服务，不修改 Main/Preload 协议、后端接口、依赖、构建配置或打包脚本。
- 与进行中的 `skill-zip-upload` 变更保持兼容；本提案只补充用户选择来源的交互，不扩大上传格式范围，并将原有拖拽能力作为必须通过的回归基线。
