## ADDED Requirements

### Requirement: 上传弹窗展示三种来源入口
系统 SHALL 在上传技能弹窗中保留统一拖拽区域，并在其下方展示“或选择”分隔区、“选择技能文件”和“选择技能文件夹”两个独立操作项。系统 MUST 保持现有标题、说明、关闭按钮和拖拽区域的业务含义不变。

#### Scenario: 用户打开上传技能弹窗
- **WHEN** 用户打开“上传技能”弹窗
- **THEN** 系统展示可接收文件或文件夹的拖拽区域，以及始终可见的文件选择和文件夹选择操作项

### Requirement: 用户选择技能文件
系统 SHALL 通过“选择技能文件”操作项打开单文件选择模式，并 MUST 将可选类型限制为 `.zip` 和 Markdown 文件；界面辅助文案 MUST 明确有效的 Markdown 文件为 `SKILL.md`。

#### Scenario: 用户选择 zip 技能包
- **WHEN** 用户点击“选择技能文件”并在系统窗口中选择一个 `.zip` 文件
- **THEN** 系统将所选路径交给现有技能预览与校验流程

#### Scenario: 用户选择 SKILL.md
- **WHEN** 用户点击“选择技能文件”并在系统窗口中选择一个 `SKILL.md` 文件
- **THEN** 系统将所选路径交给现有技能预览与校验流程

#### Scenario: 用户取消文件选择
- **WHEN** 用户打开文件选择窗口后取消操作
- **THEN** 系统保持上传弹窗可操作且不启动预览或上传

### Requirement: 用户选择技能文件夹
系统 SHALL 通过“选择技能文件夹”操作项打开允许多选的目录选择模式，并 MUST 将全部所选目录交给现有技能预览与校验流程，以确认每个目录都包含有效的 `SKILL.md`。

#### Scenario: 用户选择技能目录
- **WHEN** 用户点击“选择技能文件夹”并在系统窗口中选择一个目录
- **THEN** 系统将所选目录路径交给现有技能预览与校验流程

#### Scenario: 用户选择多个技能目录
- **WHEN** 用户点击“选择技能文件夹”并在系统窗口中选择多个目录
- **THEN** 系统保留系统返回的全部目录路径和顺序，逐项完成校验后展示所选目录数量

#### Scenario: 用户取消目录选择
- **WHEN** 用户打开目录选择窗口后取消操作
- **THEN** 系统保持上传弹窗可操作且不启动预览或上传

### Requirement: 拖拽自动识别保持可用
系统 SHALL 允许用户向统一拖拽区域拖入一个 `.zip`、一个 `SKILL.md` 或一个技能目录，并 MUST 将取得的路径交给与点击选择相同的预览与校验流程。新增点击入口 MUST NOT 替换、禁用或削弱现有拖拽事件处理、浏览器默认行为拦截、拖拽视觉反馈、文件路径兼容获取、类型校验及错误反馈。

#### Scenario: 用户拖入技能文件
- **WHEN** 用户将一个 `.zip` 或 `SKILL.md` 拖入拖拽区域
- **THEN** 系统阻止浏览器默认打开行为并进入现有技能预览与校验流程

#### Scenario: 用户拖入技能文件夹
- **WHEN** 用户将一个技能文件夹拖入拖拽区域
- **THEN** 系统阻止浏览器默认打开行为并进入现有技能预览与校验流程

#### Scenario: 用户拖拽经过并离开区域
- **WHEN** 用户将可拖拽来源移入、悬停或移出拖拽区域
- **THEN** 系统保持变更前一致的事件拦截、复制态提示和高亮清理行为，不触发系统选择窗口

#### Scenario: Electron 提供不同文件路径接口
- **WHEN** 拖入来源的路径通过当前 Electron 文件路径 API 或既有兼容回退方式提供
- **THEN** 系统继续按变更前规则取得路径并进入同一预览流程

### Requirement: 来源选择操作具备清晰语义与可访问性
系统 SHALL 为两个来源操作项提供不同的文件/文件夹图标、标题、辅助说明和右侧方向提示，并 SHALL 为文件操作项显示“推荐”标识。两个操作项 MUST 支持鼠标点击和键盘聚焦、激活。

#### Scenario: 键盘用户选择来源
- **WHEN** 键盘用户将焦点移动到任一来源操作项并执行激活操作
- **THEN** 系统打开与该操作项对应的文件或目录选择窗口

### Requirement: 新增区域遵循 STO 主题语义
新增选择区域 MUST 同时适配应用的深色和浅色模式，并 MUST 使用 `docs/sto-design.md` 定义的语义 Token：文本和图标使用 Text 层级，分隔线和描边使用 Border，背景及悬停使用 Fill 与 Interaction modifier，“推荐”标识使用 Brand 语义。系统 MUST 在两种主题下为两个操作项提供可辨识的默认、hover、active 和 focus-visible 状态，且主题切换后不得残留固定于上一主题的颜色。

#### Scenario: 用户查看或操作来源选项
- **WHEN** 来源操作项处于默认、悬停、按下或键盘聚焦状态
- **THEN** 系统使用对应语义 Token 呈现状态，且标题、辅助文字和焦点指示保持可辨识

#### Scenario: 用户在深色模式下使用来源选项
- **WHEN** 应用处于深色模式且用户查看或操作两个来源选项
- **THEN** 两个选项的背景、边框、图标、标题、辅助文字、“推荐”标识及交互状态均使用深色主题对应 Token 并保持清晰对比

#### Scenario: 用户在浅色模式下使用来源选项
- **WHEN** 应用处于浅色模式且用户查看或操作两个来源选项
- **THEN** 两个选项的背景、边框、图标、标题、辅助文字、“推荐”标识及交互状态均使用浅色主题对应 Token 并保持清晰对比

#### Scenario: 用户在弹窗打开时切换主题
- **WHEN** 上传弹窗保持打开且应用在深色与浅色模式之间切换
- **THEN** 两个来源选项立即跟随当前主题更新，不需要关闭或重新打开弹窗

### Requirement: 所有来源复用既有上传流程
系统 MUST 使文件选择、目录选择和拖拽取得的路径进入同一个现有预览、校验、上传和错误反馈流程。文件选择与拖拽 SHALL 保持单项处理；目录选择 SHALL 支持一个或多个目录，并 MUST 在用户确认后按选择顺序逐个复用现有单项上传能力。

#### Scenario: 所选来源校验失败
- **WHEN** 任一来源不符合现有技能包、`SKILL.md` 或技能目录校验规则
- **THEN** 系统展示现有错误反馈并允许用户返回来源选择状态重新操作

#### Scenario: 所选来源校验成功
- **WHEN** 任一来源通过现有技能校验
- **THEN** 系统进入现有预览和上传流程，且不因来源入口不同改变上传结果

#### Scenario: 多个目录全部上传成功
- **WHEN** 用户确认上传多个已通过校验的技能目录
- **THEN** 系统按选择顺序逐个上传全部目录、展示当前进度，并在全部成功后执行现有成功回调

#### Scenario: 多个目录上传中途失败
- **WHEN** 多目录上传中的某一项发生运行期错误
- **THEN** 系统停止尚未开始的上传，保留此前成功安装的技能，并显示已完成数量、总数和失败原因
