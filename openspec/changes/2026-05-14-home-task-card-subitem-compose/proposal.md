## Why

首页任务卡片与侧栏「任务列表」主项应对齐为同一业务入口：用户点击某张卡片时，应落在**对应主任务**下、以**当日**为语义的材料子项，并立即进入「以会话为主」的工作面，减少手动复制默认问法与多次点击。静态预置子项列表难以表达「按日生成材料」与「每张卡片各有默认问法」的产品意图；本变更在 OpenSpec 中固化**动态子项**、**卡片级默认 prompt**、**同日复用**与**网关就绪后再发送**等行为边界，便于后续接真实数据与多卡片扩展。子项内容页为聊天形态时，用户若尚未进入该子项查看助手已输出内容，应在侧栏对应子项行尾提供**未读提示**（见下），避免错过新回复。任务子项上的收发与历史须**仅**在该子项对应的聊天内容区内呈现与延续，**不得**因同一次发送在应用主路径的**普通会话列表**（如聊天页左侧或等价全局会话列表）中**再新增一条并列会话记录**，避免同一轮对话双重入口造成混淆。

## What Changes

- **动态子项**：用户点击首页某任务卡片时，系统在侧栏对应主任务下**确保存在**一条「当日」子项；若当日尚无则**创建**，若已有则**复用**该子项（不重复建两条同日条目）。
- **子项标题**：展示标题须符合「**xxxx年XX月XX日**的材料」语义；其中日期默认取**用户点击瞬间的本地日历日**（本地时区下的年、月、日）。机器可读路由片段与展示文案的对应关系在 design 中定义，展示层须可 i18n。
- **卡片级默认 prompt**：**每一张**首页任务卡片绑定**一句**默认用户 prompt（文案源须为 i18n 或等价集中配置，不得散落成组件内唯一中文长句）。点击该卡片时，在该卡片对应主任务下上述子项的**会话输入区**填入**该卡片**绑定的句子。
- **发送与网关**：自动发送行为与既有首页助手**前提一致**——网关未就绪时**不得**发送；须在**网关进入就绪**后自动发起**一轮**会话发送，并**等待**该轮助手回答输出完成（具体订阅与队列策略在 design 中定义，须仍走既有 chat / host-api 约束，渲染进程不得新增直连 Gateway HTTP）。
- **会话归属与单列展示**：该子项内产生的用户消息与助手回复**仅**绑定并展示在该子项页的聊天内容区（及为该子项持久化的会话上下文中）；产品行为上**不得**再向应用主路径的**普通会话列表**写入一条**重复**的会话项或「镜像」会话，即用户只从任务子项入口管理该对话，不从全局列表看到第二条同名并列记录（实现上如何在网关/OpenClaw 侧映射 session id 由 design 定义，须满足本条产品语义）。
- **子项页面形态**：子项详情以**类聊天界面**为主（相对原「表格 + 底部 composer」更重会话区）；与 `docs/sto-design.md` 的页面与壳层语义色、中性层级对齐，不在本 proposal 中规定像素级样式。
- **子项未读徽标**：当某子项的聊天界面中**已存在本轮（或最新一轮）助手输出**，而用户**尚未进入该子项内容页完成已读消费**（「已读」的精确定义由 design 给出，例如进入子项页并见到最新助手消息后清除），侧栏该子项行的**最右侧**须展示小型**红色圆点徽标**作为未读提示；已读后徽标消失。徽标色相与强调方式须与 `docs/sto-design.md` 中 **Danger / 提醒类语义**一致，避免引入与 STO 主色体系冲突的随意色值。

## Capabilities

### New Capabilities

- `home-task-card-subitem-bootstrap`：首页任务卡片点击 → 解析目标 `taskId` → 按本地日创建或复用当日子项 → 导航至该子项会话面；维护「卡片 → 主任务 → 默认 prompt」映射。

- `task-subitem-chat-compose-surface`：任务子项以会话为主的详情面；支持注入该卡片默认 prompt、网关就绪后自动发送、并消费该轮流式/块式回答直至本轮完成（与现有 `sendMessage` / 错误态兼容）；与侧栏子项**未读/已读**状态联动（进入子项并完成已读条件后清除未读）；**会话范围**仅限子项聊天区，**不得**在普通全局会话列表中再创建一条并列会话记录。

### Modified Capabilities

- `home-task-list-surface`：由「静态子项表 / 仅最新一条占位」改为「运行时子项集合 + 同日主键复用 + 卡片驱动创建/导航」；首页卡片与侧栏主项、子项 URL 语义一致且可扩展至多卡片；子项行支持**未读红色圆点徽标**（行尾），与聊天子页产出状态同步。

- `dashboard-sto-home-surface`（若仍单独存在）：补充每张概览卡的默认 prompt 配置与点击后的上述引导行为（含未开放卡片的交互占位策略，若有）。

- **会话列表展示（命名对齐现有 specs）**：凡规范「聊天页 / 全局会话列表」条目来源的 capability，本变更要求其与子项独占会话一致——任务子项内产生的对话**不得**在该列表中再**新增一条**与用户可感知的并列会话记录（底层 session 映射若不可避免，须在 design 中说明且 UI 不双列）。

## Impact

- 预计涉及：`src/pages/Home/HomeSummaryCards.tsx`（或等价首页卡片入口）、`src/components/layout/Sidebar.tsx` 任务子项列表（含行尾未读徽标）、`src/pages/TaskDetail/*` 或新增子项会话面路由、`src/lib/sto-tasks.ts` 及相关类型、子项未读/已读状态（Zustand / 本地持久化等，由 design 定）、`src/i18n/locales/*/home.json`、`tasks.json`（及已支持语种的等价文件）。
- 须审阅并可能调整：**聊天页 / 全局会话列表**的数据源与展示逻辑，使任务子项独占会话**不**以第二条并列记录出现（与 `src/stores/chat` 或等价模块、路由 `/chat` 的联动在 design 中定案）。
- 若对外说明应用路由或首页行为，需按仓库规则同步审阅 `README.md`、`README.zh-CN.md`、`README.ja-JP.md` 是否需一句增量说明。

## Out of Scope（本 proposal 不承诺）

- 真实报表接口、子项归档服务端同步、跨设备同步。
- 除「网关未就绪 → 就绪后补发」以外的离线编辑、草稿箱产品规格（可在后续 change 中单独立项）。
