## Context

应用广场的正常 Banner、加载骨架和错误占位当前分别在同一份 CSS 中声明为 16:5。管理端素材已经统一为 16:3，但裁剪框宽度和圆角仍与 StoClaw 的最终展示容器不同，因此客户端比例与管理端裁剪预览需要同步。

## Goals / Non-Goals

**Goals:**

- 将三种 Banner 状态统一为 16:3。
- 将管理端 Banner 裁剪框对齐 StoClaw 的 862px 最大展示宽度和 20px 圆角。
- 移除 StoClaw Banner 默认和悬停状态的蓝色投影。
- 保持状态切换期间容器高度稳定。
- 保持亮色和暗色模式的现有表现。

**Non-Goals:**

- 不修改 Banner 圆角、边框、图片填充方式或分页点。
- 不修改接口、数据模型和轮播逻辑。

## Decisions

1. 直接修改现有三个 CSS 选择器的 `aspect-ratio`。这样能够以最小范围同步正常、加载和错误状态，不引入新的运行时逻辑。备选方案是使用固定高度，但它无法随容器宽度等比缩放，因此不采用。
2. 将 Banner 默认与悬停规则的 `box-shadow` 显式设为 `none`，避免蓝色投影在图片边缘外形成色带，同时继续遵循 `docs/sto-design.md` 的亮暗色主题规则。备选方案是降低阴影透明度，但仍会导致管理端预览与客户端展示存在差异，因此不采用。
3. 使用读取 CSS 的单元契约测试锁定三个选择器的比例。备选方案是只做截图测试，但对于单一 CSS 属性而言成本更高且更易受渲染环境影响。
4. 管理端为 Banner 单独配置 862px 裁剪舞台宽度和 20px 圆角，图标仍沿用原有 520px 方形裁剪舞台。这样 Banner 裁剪框能映射 StoClaw 最大宽度下的最终轮廓，同时不会改变图标上传。备选方案是继续共用全局裁剪宽度，但无法同时准确表达两类素材的展示形态。

## Risks / Trade-offs

- [Risk] 更宽的比例会降低 Banner 高度，现有素材中的边缘内容可能更靠近裁切区 → 使用与管理端一致的 16:3 素材规范，并保持当前图片填充策略不变。
- [Risk] 只修改正常状态会造成加载完成时跳动 → 同步修改加载和错误状态并通过契约测试覆盖。
- [Risk] 管理端窗口小于 862px 时裁剪舞台无法完整横向展示 → 保留裁剪区域横向滚动，确保裁剪计算仍基于固定尺寸而不发生缩放偏差。
