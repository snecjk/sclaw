## Context

侧栏项目当前直接使用 store 返回顺序，用户观察到其表现为按名称排序；项目行已支持双击进入行内重命名，而项目内会话和“最近”会话只通过菜单触发同一编辑状态。

## Goals / Non-Goals

**Goals:**
- 项目展示顺序稳定为创建时间升序。
- 会话行双击时复用现有行内重命名流程。
- 项目草稿“新对话”继续禁止重命名。
- 侧栏行内重命名输入框在暗黑模式下保持正确背景与文本对比。

**Non-Goals:**
- 不调整数据库结构或项目持久化顺序。
- 不新增排序配置、拖拽排序或其他重命名 UI。
- 不新增 STO 主题颜色或自定义调色板。

## Decisions

1. 在侧栏展示层按 `createdAt` 升序复制排序项目数组。这样不改变 Zustand store 的共享数据顺序，影响范围最小；备选方案是在 store 加载时排序，但会影响其他潜在消费者。
2. 会话行组件在其主按钮上处理双击，并调用现有 `onStartRename` 回调。这样菜单、双击共享同一状态和提交逻辑；备选方案是在父组件包装双击事件，但会重复项目内与“最近”两套事件绑定。
3. 项目草稿行通过显式 `canRename`/现有草稿判断屏蔽双击。这样与菜单不可重命名规则一致；备选方案是触发后在父回调中静默返回，但会产生可交互却无反馈的行为。
4. 行内输入的强调边框继续使用 STO Brand token，背景改用语义 `card` token，使暗黑模式自动获得深色填充并符合 `docs/sto-design.md`。备选方案是保留 `bg-white` 并添加 `dark:` 变体，但语义 token 更统一且不易遗漏。

## Risks / Trade-offs

- [旧数据缺失或相同创建时间导致顺序不稳定] → 使用原数组索引作为稳定次级顺序。
- [双击同时触发单击打开会话] → 浏览器会先触发单击；编辑状态在双击时进入，保留现有导航语义，不阻止正常切换。
- [草稿误入重命名] → 在会话行组件和父级回调两层保持草稿保护。
- [其他侧栏行内编辑仍残留白底] → 同步检查项目、会话与最近分组的编辑输入框，统一使用语义背景 token。
