## 新增需求

### Requirement: 应用侧栏宽度与折叠目标对齐 STO Claw 归档原型
系统必须在默认展开态将主导航侧栏渲染为水平宽度 `248px`，在折叠态为 `72px`（含与归档 `styles.css` 意图一致的 padding 过渡），除非受平台最小窗口宽度限制且已在文档中说明降级策略。

#### Scenario: 侧栏展开
- **WHEN** 用户在首次启动后进入主应用壳
- **THEN** 侧栏作为主要导航必须占据 `248px` 水平宽度
- **AND** 侧栏背景色在浅色主题下必须与原型侧栏表面一致（`#f3f4f6`）

#### Scenario: 侧栏折叠
- **WHEN** 用户触发侧栏折叠控件
- **THEN** 侧栏必须过渡到 `72px` 宽度
- **AND** 折叠后隐藏的文案标签必须通过工具提示或等效的无障碍名称仍可被感知

### Requirement: 侧栏分区结构对齐原型
系统必须按自上而下顺序呈现：含产品名与版本行的品牌区、主导航入口、带可见分组标题的可选分组列表（例如任务列表）、以及底部用户卡与设置类弹出入口。

#### Scenario: 主导航可见性
- **WHEN** 用户在使用应用壳的任意主路由页面
- **THEN** 侧栏必须展示与原型顺序一致的主导航入口：首页、定时任务、技能广场、我的数据（文案必须使用 i18n 键；中英文具体措辞可不同，但结构必须一致）
- **AND** 当前激活路由必须通过等同于原型的强调方式展示（强调色和/或内凹指示条）

#### Scenario: 分组列表与底部用户卡
- **WHEN** 用户在视口高度不足以展示完整导航内容时滚动侧栏
- **THEN** 中部导航区域必须可滚动，且品牌区与底部用户卡在布局上保持相对固定（与设计一致）
- **AND** 底部用户卡必须通过弹出层或菜单提供与原型信息层级一致的通知/设置等入口

### Requirement: 渲染壳层不得绕过 host-api 处理侧栏触发的后端行为
系统必须将侧栏相关操作（登出、跳转设置、若展示的网关状态等）所涉及的 Main 进程与 Gateway 交互全部保留在既有 host-api / IPC 通道上；新增侧栏 UI 不得在页面组件中引入未经批准的 `window.electron.ipcRenderer.invoke` 直连用法。

#### Scenario: 从侧栏壳层发起账户或设置类操作
- **WHEN** 用户从用户卡菜单选择需要 Main 进程配合的项
- **THEN** 渲染进程必须调用与别处相同能力已使用的 host-api 或 store 动作
- **AND** 渲染进程不得使用 `fetch('http://127.0.0.1:18789/...')` 或其它硬编码 Gateway 地址发起 HTTP 调用
