## 新增需求

### Requirement: 首页主列宽度与画布对齐原型
系统必须将首页主内容列限制为最大宽度 `1100px`，水平内边距与原型一致（`20px` 量级，允许响应式收紧），在主滚动区域内水平居中；在默认浅色壳主题下，页面背景必须为 `#f7f8fa`。

#### Scenario: 用户在较宽显示器上打开首页路由
- **WHEN** 应用窗口宽度大于首页内层最大宽度与内边距之和
- **THEN** 首页内层容器的主要内容宽度不得超过 `1100px`
- **AND** 外围主内容区背景必须使用原型页面画布色

#### Scenario: 用户在较窄窗口上打开首页路由
- **WHEN** 窗口宽度小于内层最大宽度
- **THEN** 首页内层容器必须随响应式水平内边距收缩，且不得仅因 max-width 约束单独导致不合理的横向溢出

### Requirement: 首页按原型顺序呈现 Hero、概览栅格与助手输入区
系统必须在首页内层列中自上而下渲染：Hero 区块（图示 + 一级标题 + 导语段落）、与原型一致的横向可滚动或可换行概览卡栅格、以及底部助手 composer（多行输入、工具操作行、空内容时禁用的发送按钮）。

#### Scenario: Hero 区块
- **WHEN** 用户导航至首页表面
- **THEN** Hero 必须展示产品标识、主标题与副标题，且字号层级与原型一致（必要时使用 clamp）

#### Scenario: 概览卡片
- **WHEN** 首页表面加载概览条目（占位或真实数据）
- **THEN** 每张概览卡必须包含头部（标题 + 可选标签 pill + 状态徽标）、含一至三项指标的统计行、以及含头像/团队名与尾部引导文案的页脚行
- **AND** 卡片圆角默认值必须对齐原型大卡圆角意图（`24px`）

#### Scenario: 助手 composer
- **WHEN** 用户聚焦助手输入框
- **THEN** composer 必须在工具条行中提供与原型分组一致的工具按钮（上传文件、技能调用、数据分析、工作流调用）
- **AND** 发送控件在仅有空白内容时必须保持禁用（与原型一致），且不得仅为满足该 UI 规则而单独产生网络请求

### Requirement: 接入发送时首页须复用既有对话发送链路
系统在将首页助手 composer 连接到某会话时，必须复用已建立的对话消息发送链路（store + host-api），不得在首页重复实现 Gateway 访问逻辑。

#### Scenario: 接入后用户从首页 composer 发送消息
- **WHEN** 用户从首页助手 composer 提交文本，且已为某目标会话启用接入
- **THEN** 应用必须调用与 Chat 页面 store 动作相同的发送路径
- **AND** 渲染进程不得在首页组件内新建直连 Gateway 的 HTTP 连接
