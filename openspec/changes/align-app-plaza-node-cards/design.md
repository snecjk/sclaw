## Context

应用广场已经通过服务端目录取得 Banner、分类和应用数据。当前市场 Tab 在分类下方以双列纵向条目展示应用，并额外展示 Banner；应用条目把 `badge` 拆成多个胶囊标签，图标则由 `AppIcon` 统一渲染。最新设计要求市场内容收敛为紧凑节点卡片：上传图片、名称和一行标签是卡片的主要信息。

本变更只调整 Renderer 展示层，不改变服务端查询、Store、收藏或打开应用流程。页面配色继续以 `docs/sto-design.md` 的 Text、Fill、Border 和 Brand 语义 Token 为准。

## Goals / Non-Goals

**Goals:**

- 以三列紧凑卡片展示市场应用，并在窄窗口逐级降为两列和一列。
- 优先原样展示 `iconUrl` 对应的后台上传图片，加载失败时使用现有图标占位。
- 将 `badge` 中以常见中英文分隔符保存的标签标准化，并以“、”连接成一行。
- 保留节点整卡打开、收藏以及加载、错误、空态和分页能力。
- 浅色与深色模式均保持文本、边框、悬停和焦点状态清晰可读。

**Non-Goals:**

- 不修改 Banner、分类或 APP 后端接口。
- 不修改收藏、安装和外部应用持久化。
- 不修改“我的应用”卡片。
- 不新增依赖或修改构建配置。

## Decisions

### 1. 市场列表使用语义化紧凑卡片而非复用“我的应用”卡片

市场节点继续保留自己的 DOM 与类名，但调整为图片、名称、标签三段式，并把整卡作为主要打开入口。这样可以保留市场专属的收藏和分页逻辑，同时准确匹配设计稿。

替代方案是复用 `AppCard`，但该组件包含描述、操作区、安装状态等市场节点不需要的信息，复用会引入大量条件分支。

### 2. 上传图片由 `AppIcon` 的远程图片分支直接呈现

存在 `iconUrl` 时使用图片填满固定的圆角方形图片容器，并使用 `object-fit: cover` 保持设计稿中的缩略图效果；图片缺失或加载失败时回落到 `iconKey` 占位。这样不需要改变接口类型。

替代方案是在页面内单独渲染 `<img>`，但会复制 URL 校验、错误回退与可访问名称逻辑。

### 3. 标签标准化为单个文本节点

页面将 `badge` 按逗号、中文逗号、顿号和分号拆分，去空、去重后使用“、”连接。卡片始终渲染一个固定高度的次要文本节点：有标签时单行省略，无标签时保持为空并对辅助技术隐藏，从而让所有节点的名称和图片垂直对齐。

替代方案是只替换英文逗号，但服务端历史数据可能包含中文逗号或分号，表现会不一致。

### 4. 样式使用页面语义变量并补齐深色模式

卡片背景、边框、主次文本、悬停和键盘焦点使用 `--ma-*` 页面语义变量，这些变量分别映射 STO Design 的 Fill、Border、Text 和 Brand 层级；深色主题下覆盖这些语义变量，而不是在节点上写死浅色填充。

替代方案是直接复制设计图中的颜色值，但这会破坏主题一致性，也无法满足深色模式。

## Risks / Trade-offs

- [Risk] 上传图片比例不一致时会被裁切 → 使用方形容器与 `object-fit: cover`，并保留图片的可访问替代文本。
- [Risk] 标签过多导致卡片横向拥挤 → 单行省略，完整信息仍保留在原始数据中。
- [Risk] 移除市场 Banner 会降低运营曝光 → 本次按设计稿将市场主视图收敛为分类和节点卡片，但不删除 Banner 数据查询代码，便于后续产品决策回滚。
- [Risk] 整卡点击与收藏按钮事件冲突 → 收藏按钮阻止冒泡，键盘焦点分别可达。
