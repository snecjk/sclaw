## ADDED Requirements

### Requirement: 市场节点使用设计稿卡片布局

系统 MUST 在应用广场市场 Tab 中以紧凑卡片展示应用节点，并在可用宽度充足时每行展示三个节点；节点 MUST 包含图片、应用名称和标签文本，且在窄窗口中响应式降列。

#### Scenario: 宽窗口浏览应用

- **WHEN** 用户在宽窗口打开应用广场市场 Tab 且目录返回多个应用
- **THEN** 系统 MUST 以三列等宽卡片展示节点，每张卡片 MUST 为 74px 高、18px 圆角和 16px 内边距，且图片、名称和标签保持一致的对齐与间距

#### Scenario: 窄窗口浏览应用

- **WHEN** 应用广场可用宽度不足以容纳三列节点
- **THEN** 系统 MUST 降为两列或一列且不得截断卡片主体或造成横向滚动

### Requirement: 节点展示后台上传图片

系统 MUST 优先使用应用记录的上传图片作为节点图片，并 MUST 在图片缺失或加载失败时显示稳定的回退图标。

#### Scenario: 上传图片可用

- **WHEN** 应用记录包含有效的远程图片地址且图片成功加载
- **THEN** 节点 MUST 在 42px 方形、11px 圆角的固定区域中展示该图片

#### Scenario: 上传图片不可用

- **WHEN** 应用图片地址为空或图片加载失败
- **THEN** 节点 MUST 在 42px 方形、11px 圆角的固定区域中显示现有图标或默认占位，浅色背景 MUST 为 `rgba(189, 243, 207, 0.5)`，且卡片布局不得跳动

### Requirement: 标签字段使用顿号连接

系统 MUST 将应用标签字段按常见逗号、顿号和分号分隔符解析，去除空值与重复值，并使用中文顿号“、”连接为单行次要文本；每个节点 MUST 保留相同高度的标签行，以维持名称和图片对齐。

#### Scenario: 标签包含混合分隔符

- **WHEN** 标签字段为“标签1, 标签2；标签3、标签2”
- **THEN** 节点 MUST 显示“标签1、标签2、标签3”

#### Scenario: 标签字段为空

- **WHEN** 应用记录没有有效标签
- **THEN** 节点 MUST 保留不可见的固定高度标签行，且名称、图片和卡片高度 MUST 与有标签节点保持一致

### Requirement: 节点交互与主题保持一致

系统 MUST 保留整卡打开应用和收藏操作，并 MUST 使用与 `docs/sto-design.md` 一致的 Fill、Border、Text 与 Brand 语义样式；浅色和深色模式下的默认、悬停、焦点及收藏状态 MUST 清晰可读。

#### Scenario: 使用鼠标或键盘打开应用

- **WHEN** 用户点击节点主体或通过键盘激活节点
- **THEN** 系统 MUST 沿用现有安装与打开应用流程

#### Scenario: 切换收藏

- **WHEN** 用户点击节点内的收藏按钮
- **THEN** 系统 MUST 只切换收藏状态而不得同时打开应用

#### Scenario: 深色模式浏览节点

- **WHEN** 用户在深色模式中浏览或聚焦应用节点
- **THEN** 节点背景、边框、主次文本、焦点环和收藏状态 MUST 具有可辨识对比度且不得使用仅适合浅色模式的固定填充

### Requirement: 分类导航显示应用总数

系统 MUST 在“精选”和每个服务端分类名称后展示对应应用总数；数量 MUST 使用无关键词条件下应用列表接口返回的 `total`，不得使用当前分页已加载的卡片数量；分类按钮 MUST 使用 8px 圆角。

#### Scenario: 首次加载分类数量

- **WHEN** 分类接口返回测试专用和经营管理分类，且对应应用列表 `total` 分别为 4 和 2
- **THEN** 分类导航 MUST 分别显示“测试专用 4”和“经营管理 2”

#### Scenario: 分类没有应用

- **WHEN** 某分类的应用列表 `total` 为 0
- **THEN** 分类导航 MUST 显示该分类数量为 0

#### Scenario: 分类按钮视觉

- **WHEN** 用户查看默认、悬停或选中的分类按钮
- **THEN** 分类按钮 MUST 保持 8px 圆角

### Requirement: 外部应用入口符合设计样式

系统 MUST 将“安装外部应用”入口展示为 8px 圆角的填充按钮；浅色默认填充 MUST 为 `#E5E6EB`，按钮 MUST 使用加号图标且加号 MUST 与文字使用相同前景色，暗色模式 MUST 使用可辨识的语义填充与焦点状态。

#### Scenario: 浅色模式查看入口

- **WHEN** 用户在浅色模式查看“安装外部应用”入口
- **THEN** 系统 MUST 展示 `#E5E6EB` 填充、加号图标和入口文字，且不得显示原有橙色描边与外链图标

#### Scenario: 暗色模式查看入口

- **WHEN** 用户在暗色模式悬停或聚焦“安装外部应用”入口
- **THEN** 按钮、加号、文字和焦点环 MUST 保持足够对比度

### Requirement: 页面头部控件稳定对齐

系统 MUST 将标题与“安装外部应用”放在第一行两端，将应用页签与搜索框放在第二行两端；两行 MUST 与下方内容共享左右边界，并 MUST 在窄窗口自然换行而不重叠。

#### Scenario: 宽窗口查看页面头部

- **WHEN** 应用广场具有足够横向空间
- **THEN** 安装按钮 MUST 位于标题区右侧，页签 MUST 位于工具行左侧，搜索框 MUST 位于工具行右侧

#### Scenario: 窄窗口查看页面头部

- **WHEN** 页面宽度不足以在单行容纳对应控件
- **THEN** 控件 MUST 自然换行且不得溢出、遮挡或脱离内容边界

#### Scenario: 主页签视觉与设计稿一致

- **WHEN** 用户查看“应用广场”和“我的应用”主页签
- **THEN** 页签 MUST 使用无外层填充、无选中胶囊背景的纯文字样式，并 MUST 通过深色加粗文字区分当前页签，且 MUST 只显示名称而不显示应用数量

#### Scenario: 分类数量不受主页签调整影响

- **WHEN** 顶部主页签隐藏应用数量
- **THEN** 下方“精选”和服务端分类 MUST 继续显示各自的应用总数

### Requirement: 我的应用卡片底部操作区对齐

系统 MUST 为“我的应用”网格中普通应用和外部应用的底部操作区保留相同高度，使同一行卡片的顶部分隔线和操作内容保持水平对齐。

#### Scenario: 普通应用与外部应用并排展示

- **WHEN** 普通应用卡片带有收藏按钮且相邻外部应用卡片只有文字操作
- **THEN** 两类卡片的底部分隔线、元信息和操作文字 MUST 保持相同纵向位置
